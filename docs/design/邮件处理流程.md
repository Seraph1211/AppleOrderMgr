## 当前处理链路

[邮件 Worker](../../src/workers/emailWorker.js)调用[emailService](../../src/services/emailService.js)。连接成功打开配置邮箱，处理已有 UNSEEN 邮件；IMAP mail 事件触发后续批次。isProcessing 防止批次重复进入，但不应理解为数据库级幂等锁或整批逐封串行保证。

```text
连接 / 新邮件事件 → 搜索 UNSEEN → 获取 MIME 元数据
→ 主题关键词 + 发件人白名单检查
→ 解析内容 → 保存订单和邮件日志
→ 按配置及结果标记已读 → 批次结束后再检查 UNSEEN
```

主题关键词为 NULL、预订助手、预订成功之一；白名单使用标准化后的 From 邮箱地址匹配。生产未配置 `IMAP_ALLOWED_SENDERS` 时配置校验拒绝启动。非生产未配置白名单时仅按主题筛选，不能据此验证来源可信。

## 已读与重试语义

| 结果                       | IMAP_MARK_SEEN=true | IMAP_MARK_SEEN=false |
| -------------------------- | ------------------- | -------------------- |
| 成功保存或已有订单处理成功 | 标记已读            | 保持原状态           |
| 非订单邮件                 | 标记已读            | 保持原状态           |
| 永久错误                   | 标记已读            | 保持原状态           |
| 临时错误且累计不足 3 次    | 保持未读            | 保持原状态           |
| 临时错误达到 3 次          | 标记已读            | 保持原状态           |

永久错误包括当前代码识别的 Sequelize 验证、唯一约束、外键错误以及“邮件数据不完整”。重试计数存在进程内 Map 中，重启会丢失；关闭已读写入时，反复搜索可能重复处理同一封邮件，不能宣称最多三次的持久化重试保证。

处理完成回调在 finally 统一执行一次。批次完成后约 500ms 再次搜索 UNSEEN；错误、结束、关闭事件共用一个约 30 秒重连定时器，主动停止不重连。

## 订单保存与幂等边界

[orderService](../../src/services/orderService.js)在事务中检查订单号、匹配基础数据、写订单及邮件日志。已有订单返回已有记录。日志字段 email_uid 及订单唯一约束提供部分保护，但 UIDVALIDITY、邮箱身份、多进程抢占、失败任务重放尚未形成完整持久化机制。

## 尚未实现

启动回溯 24 小时、每 10 分钟回溯 30 分钟属于历史目标，当前没有对应回溯能力。邮件已被外部客户端标记已读时，UNSEEN 扫描不会补回。持久化幂等/重试、死信与回放任务见[优化计划](../planning/项目优化计划.md)。

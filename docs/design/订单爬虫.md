# 官网订单爬虫退役说明

> 状态：旧链路已退役；2026-10-03 新增独立手动状态更新
>
> 生效日期：2026-09-22

官网订单链接爬虫、代理 Provider、刷新队列、浏览器采集扩展和系统爬虫日志均已退出运行链路。订单生命周期展示、筛选、付款资格和企业微信推送改用官方订单邮件证据，实施范围见[官网订单链接爬虫下线与邮件状态接替方案](../planning/官网订单链接爬虫下线与邮件状态接替方案.md)。

## 手动官网状态更新（2026-10-03，已生产发布）

订单管理通过服务器队列手动更新官网状态，支持单行、勾选多行、全选本页及全选当前筛选结果。打开页面、轮询任务、重新加载列表均不触发 Apple 请求。新队列独立于已归档旧爬虫，不恢复定时爬虫。

仅把完整官网详情的商品原始状态写入 `orders.official_raw_status`，同时记录 `official_status_observed_at`。同单商品状态一致时保存该值，不一致时去重并以 `|` 连接原始枚举；不猜测整单阶段。其他订单字段（含 `status`、邮件、商品、付款、金额、取货及 `updated_at`）保持不变。失败保留旧观测，不回填历史归档。

新任务只允许拥有 `orders.read` 和 `orders.edit` 的用户提交，查询、执行及回写均检查订单 TAG 范围与当前权限。筛选全选在提交时固化 ID，最多 10000 单；超过上限明确拒绝，不静默截断。每单仅允许一个待处理或运行中任务。请求键幂等，后台串行执行，任务持久化，超时或失联标为失败，不自动重放登录。支持取消尚未开始的任务。

服务器运行已有隔离 Chromium 取数路径及 PostgreSQL 限流、账号冷却、每单 24 小时最多三次等约束。部署迁至共享持久目录，沿用原请求计数；人工批量窗口使用有限累计请求上限，达到上限明确失败。代理、密码、原文均不返回 API，API 不挂载 Docker socket。宿主机专用服务只执行固定命令领取及完成任务。

### 订单凭据读取与失败分类（2026-10-03 修复授权）

输入始终以订单保存的 Apple ID、订单号和原始链接确定身份。账号主表无匹配且 `apple_id_ref` 为空时，允许使用订单加密密码快照，不要求先补录账号。账号匹配按去除首尾空格及忽略大小写进行；已有唯一主表记录时沿用主表密码，并在存在订单密码快照时校验两者一致。

非空账号引用必须指向同一账号；多个候选、异常账号、引用冲突、密码缺失、解密失败及快照密码不一致均明确失败，不能静默换账号或使用联系人邮箱。输入阶段只读事务，不修改账号库、订单关联或业务字段。成功输入的凭据来源仅保存在服务器私密文件，不返回管理台。

输入错误通过受控 JSON 错误码传递到宿主队列及前端；仅允许固定错误码，不把原始异常、凭据或链接作为错误文本。输入失败清理本次临时文件、不启动浏览器。旧失败任务保持原审计记录，用户重新提交时执行新逻辑；不自动批量重放。

## 2026-10-03 独立服务器单笔取数

当前另有独立手动工具，输入系统 ID 后只读获取关联账号和原始链接，使用服务器国内代理、Xvfb/Chromium 从账户中心登录；列表缺少目标时再使用既有访客链接。服务器会话加密、账号绑定、有限时效，新进程重新请求官网；不使用用户电脑 Cookie 或网络中继。

`officialOrderParser` 只接受订单号精确匹配、完整商品集合、数量和原始状态；列表短名不冒充详情规格，加载页、空列表、缓存或缺字段不成功。支持 HTML JSON 模型与 `/shop/orderx/guestx/…` 的 `fetchOrder` JSON；未知合法原始状态保留，不推断业务付款或取货阶段。

`officialOrderGate` 在专用 PostgreSQL 持久化 5 RPS 许可、累计预算、单日订单次数及账号／代理冷却；浏览器全部子请求和重定向同样计数。源响应与会话加密，普通路径清除令牌、订单号和联系人。原始取数器只读，结果按次写入私密文件；手动队列验证结果后仅回写官网状态及观测时间，不发通知。

三个样本及新进程复用已真实验证，完整产品可靠性仍待验收。操作和限制见[服务器官网订单取数](../deployment/服务器官网订单取数.md)，后续范围见[重建方案](../planning/服务器端订单链接采集重建方案.md)。本节不恢复下述已退役能力。

## 当前规则

- 新订单仍由现有邮件或 AOS 入库链路接收，入库事务继续创建付款任务并登记企业微信推送；不再创建官网刷新计划或任务。
- 订单管理恢复原官网状态列并放在订单号后，邮件状态仍保持原口径；渠道、仪表板和付款页面继续使用邮件状态。
- 历史官网已付款、退款或终态证据转换为独立的 `payment_assignment_hold_reason`，即使付款任务完成后重开也继续阻止自动和手工重新分配。
- 历史限制不阻止已有负责人继续执行重开、本人处理、读取付款链接或付款码；界面显示限制提示。
- 单纯超过来源下单时间 30 分钟只阻止自动分配，保留手工交接能力。
- 已退休刷新、代理和系统日志接口返回 HTTP 410 及稳定错误码 `FEATURE_RETIRED`。

## 历史数据

退役 Migration 将刷新任务、批次、计划、系统状态和爬虫日志移动到 PostgreSQL `archive` schema，并撤销应用角色的写权限。`archive.order_official_retirement_snapshots` 保存订单退役时的官网字段快照。首版只允许运维受控查询、导出和恢复，不提供管理台入口。

归档数据不参与当前业务查询、统计、分配或通知。恢复必须先备份并使用 Migration 回滚或受控 SQL，不能直接修改归档记录。

## 发布与回滚

当前手动更新发布使用新增字段和新队列表，不回滚旧退役迁移。应用回滚先停止 `apple-official-order-queue.service` 并恢复 API/前端，保留观测和审计；不得清空归档、研究计数或队列表。下述扩展／归档顺序仅描述此前爬虫退役。

生产发布采用扩展迁移、应用无中断切换、最终归档迁移的顺序。邮件接收、AOS 入库、订单邮件 Worker 和企业微信 Worker 在维护窗口内保持运行。维护窗口上限 15 分钟，详细步骤以[生产环境部署指南](../deployment/生产环境部署指南.md)和本次发布记录为准。

如需回滚，先切回旧应用版本，再回滚最终归档 Migration 和扩展 Migration；禁止通过重新启用已删除的单个 Worker 拼接新旧版本。

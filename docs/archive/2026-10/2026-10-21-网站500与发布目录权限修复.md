## 现象与根因

用户反馈 `https://apple.godp.me/orders` 显示 `500 Internal Server Error / nginx/1.20.1`，02:21 公网复现一致。API 容器 healthy，readiness 返回数据库正常，根分区使用率 54%，可用约 89 GiB。

`current` 指向 `/var/www/apple-order-mgr/releases/20261021-log-query-bounded`。`namei -l` 显示该发布目录为 `0700 root:root`，其下 `frontend` 为 `0755`、`index.html` 为 `0644`；以 `nginx` 用户测试入口可读性失败。父目录缺少 Nginx 所需的穿越权限，阻断前端读取；SPA 回退配置与 500 表现一致。本站错误日志被配置为 `/dev/null crit`，没有以错误日志证明内部重定向具体次数，也未为排障放开可能含敏感参数的日志。

02:21 应急恢复时尚未追溯创建目录的命令；后续已从实际发布脚本和执行记录确认来源，见下方“发布流程根因追溯与修复”。

## 修复

先断言 `current` 仍指向上述版本，记录目录原权限，再仅对该发布根目录执行 `chmod 755`。02:21:39 前完成；随后 `nginx` 用户可读取入口。

未递归修改其他目录；`shared/app.env` 回读仍为 `0600 root:root`。未切换版本、重启 Nginx／容器／数据库、变更业务数据或删除日志。此次为单个目录权限修复，没有执行制品发布或数据库迁移。原权限已记录，恢复 `0700` 会重现故障，不作为正常回退方案。

## 发布流程根因追溯与修复

本节为用户继续要求追溯和修复发布流程后的增补，不把 02:21 应急阶段的未知结论当作最终状态。

### 原因证据

实际入口 `/tmp/aos-log-fix-20261021/release.py` 与发布目录内保存的 `release.py` 字节相同，原始 SHA-256 均为 `39d9006c5e9012b2e84a2b8629dbd1f9026b9996eb05095d9a51ef34e617a41f`。原脚本先调用 `os.umask(0o077)`，在 `stage()` 中调用没有显式权限处理的 `RELEASE.mkdir()`，然后使用 `shutil.copytree` 复制前端。这次执行记录显示运行了该脚本的 `stage` 和 `deploy`；最终 `current` 指向脚本定义的 `20261021-log-query-bounded`。

默认目录模式 `0777 & ~0077 = 0700`；复制子树保留了 `frontend` 的 `0755` 和入口的 `0644`，并不会修复发布根目录。回归用例也证明即使写 `mkdir(mode=0o755)`，仍受 umask 影响，必须明确 `chmod` 或使用相应公开树处理。`umask 077` 本身应继续用于私密文件，不能全局改成宽权限来解决。

漏检原因同样明确：旧 `deploy()` 只检查 API 的回环和公网业务端点、源码／前端文件内容摘要，以及共享环境和容器保全；其 `link()` 直接原子替换 `current`，没有 Nginx 用户权限测试或前端 HTTP 验收。`/api/` 经反向代理，不依赖前端目录，故 API 200 与网页 500 可同时发生。前端逐文件摘要一致不能证明 Nginx 可以读取。

### 已实施的流程修复

- 新增统一 [`productionFrontendGate.py`](../../../scripts/productionFrontendGate.py)：`prepare` 仅处理公开发布根目录和 `frontend` 子树，目录 `0755`、文件 `0644`；保留发布根目录其他私密文件的权限与内容，符号链接／特殊文件拒绝。
- `check` 检查明确模式，再用 `runuser` 降权为实际 Nginx Worker 用户读取全部前端文件，验证父目录穿越；在正式 API 切换前运行，`700` 会返回非零。
- `switch` 核对预期旧指针并加锁；检查新旧公开树后原子切换，验证三个页面及入口 JS/CSS 的状态、类型、长度和 SHA-256，以及 API 的数据库就绪字段。HTTP 200 的错误页、旧页面或错误类型也拒绝；失败恢复旧指针并复验。第三方字体样式不属于本站制品，不发外部验收请求。API／Worker 回退仍由原发布编排执行。
- [`buildProductionRelease.sh`](../../../scripts/buildProductionRelease.sh) 显式保留私密默认 `umask 077`，构建后规范公开树并校验，将门禁随制品打包且纳入 `SHA256SUMS`。上传解包后仍需在生产以 Nginx 用户再检查。
- 已更新 AGENTS、部署指南、测试指南及既有 CI；通过 `npm run test:release:frontend` 运行专用回归，新增 `npm run release:frontend -- ...` 本地入口。

服务器安装位置为 `/var/www/apple-order-mgr/shared/tools/productionFrontendGate.py`，SHA-256 `b9369f3006db95447679c2277d5c303d066d7f34dc057889a0f05742dbd1ad7b`。已修补原 `/tmp/aos-log-fix-20261021/release.py`：建目录后显式 `chmod`；复制前端后调用 `prepare/check`；正式 API 切换前重做 `check`；`link()` 改用统一 `switch`，包含失败回退。修补后 SHA-256 `7fdd4f20c1e0ddc11ed8d8296c7d1a8ef4492337213808f113088a4b2c6d8173`。线上发布目录里的原始脚本作为事故证据保留原样，不作为后续发布入口。

原脚本和安装摘要保存在 `/var/backups/apple-order-mgr/20261021-frontend-release-gate-v2/`。首次安装前只读门禁因现有 Google Fonts 外部样式被过度限制而拒绝，工具自动恢复原入口，未切业务版本；修正为只验本站制品并补回归后重新安装通过。首次失败的原脚本备份保留在相邻不带 `-v2` 的目录，未抹去失败过程。

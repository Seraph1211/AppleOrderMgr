## 实现入口

当前邮件 Worker 使用[src/services/emailParser.js](../../src/services/emailParser.js)，并直接调用 mailparser。解析实现统一收敛在 `src/services/`，不再保留根目录下的历史副本。

解析器负责字段提取；主题和发件人白名单由[邮件处理服务](邮件处理流程.md)校验，不能以解析成功证明来源可信。

## 邮件格式

MIME 可含 Base64 编码的 UTF-8 文本与 HTML。mailparser 读取正文后处理 HTML 实体、标签与换行，保留商品内容：

```text
型号1-产品名称 x 数量1@型号2-产品名称 x 数量2/取机人/身份证后四位/付款方式/-/-/标签
```

按 @ 切分商品，取机人信息在商品段之后。型号可含 /，不能直接把全文按 / 分割作为字段解析。标签提取和未知样本兼容性仍需单独用例验证。

## 字段与输出

| 输出                               | 当前来源与规则                                                                                  |
| ---------------------------------- | ----------------------------------------------------------------------------------------------- |
| appleId                            | 邮件称呼中 *** 后的邮箱                                                                         |
| orderNumber、orderUrl              | HTML 中 Apple vieworder 链接；当前匹配 W 加 10 位数字                                           |
| orderDate                          | 文本日期时间                                                                                    |
| products                           | model、name、quantity、image；邮件 image 初始为空，颜色容量仍包含在名称中，并非独立保证输出字段 |
| recipient                          | name、idLast4、tag                                                                              |
| paymentMethod                      | 商品行之后的付款方式                                                                            |
| emailSubject、emailFrom、emailDate | MIME 元数据                                                                                     |
| rawContent                         | 原始邮件编码内容，模型层加密后存储                                                              |

当前解析正则集中在源文件 extractAppleId、extractOrderDate、extractOrderLink、extractProductInfo、parseProducts；不在本文复制完整函数，避免产生第二份实现。

## 错误与一致性

Apple ID、订单号、链接、商品等必填信息不全时抛错。单个商品解析失败会被跳过，若全部失败才抛错；不能把解析成功视为多商品绝无漏项。下游验证、幂等和重试见[邮件处理流程](邮件处理流程.md)。

商品数量是邮件权威数据；官网取消后数量为 0 时保留原数量。基础资料匹配和加密快照见[快照匹配](../database/快照匹配.md)。

## 验收

使用合成 MIME 测试 Base64、HTML 实体、换行、含 / 型号、@ 多商品、尾部取机人、缺失字段和部分商品失败。历史“提取 13 字段”清单中的独立颜色/容量并非当前返回契约，不继续复制为保证。

# 文档检查工具说明

> 状态：当前有效
>
> 最近核对：2026-09-06
>
> 基线：main@0fd7f80 与当前未提交工作树
>
> 验证范围：本地工作树静态核对；未验证真实数据库、邮箱、官网和生产环境

## 命令

```bash
npm run docs:check
npm run docs:check:links
npm run docs:check:schema
```

总检查串行运行文档结构检查与模型字段覆盖检查，任一失败返回非零退出码。

## 范围

| 检查               | 实现与边界                                                                                                                                            |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 本地 Markdown 链接 | 检查目标文件及 Markdown 标题锚点；不联网检查外部网站                                                                                                  |
| 导航可达性         | 所有 docs Markdown 应从 docs/README.md 经文档链接可达，历史内容经 archive 索引进入                                                                    |
| 旧路径             | 检查有效文档与维护脚本中的已迁移路径；归档和迁移映射允许记载旧名                                                                                      |
| npm 命令           | 检查当前操作文档中的 npm run 及 npm --prefix frontend run 是否有对应脚本；历史命令不要求仍可执行                                                      |
| 模型字段覆盖       | [check-doc-consistency.js](../../scripts/check-doc-consistency.js)检查模型表名、字段名在数据库规范中出现；不校验类型、约束、索引或 Migration 执行结果 |

链接检查入口为[checkDocLinks.js](../../scripts/checkDocLinks.js)。所有检查只读，不连接数据库、不执行文档中的命令。

## 持续集成与提交前检查

仓库已有质量门禁调用 docs:check；新增门禁内容通过同一入口生效。[pre-commit-check.sh](../../scripts/pre-commit-check.sh)保留级联提醒，并运行完整文档检查。脚本存在不等于每位开发者已经安装 Git hook；本轮不修改本机 hook 安装状态。

## 故障处理

根据错误中的文件、目标或锚点修复引用；新增文件补齐索引。归档内容以历史文本保留旧路径，当前指南不得依赖已移除目标。修改维护规则见[文档管理规范](文档管理规范.md)。

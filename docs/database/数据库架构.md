## 权威范围与维护顺序

本页是数据库文档入口，记录当前模型的字段声明和已确认安全规则。数据库变更仍需先讨论并更新本文，再更新模型、Migration、接口和测试。

字段表中的类型、可空性、默认值来自当前模型静态声明；ORM 校验不自动等同于数据库 CHECK，模型索引也不证明 Migration 已落库。实际数据库类型、约束、索引与存量数据兼容性需通过隔离迁移核验，尚未全面验证。旧 SQL、触发器和明文插入示例已移至[历史资料](../archive/2026-09/整理前数据库设计.md)。

## 安全存储

- users.password 保存 bcrypt 哈希；Apple 密码、密保、取机人身份证和密码、订单敏感快照、邮件原文及解析结果使用 AES-256-GCM 或 JSONB 密文包装。
- FIELD_ENCRYPTION_KEY 与密钥版本负责加解密；FIELD_BLIND_INDEX_KEY 可单独提供盲索引密钥。不得把 JWT 密钥复用为字段密钥。
- recipients.id_card_hash 使用标准化身份证的 HMAC-SHA256，负责唯一性与精确匹配；后四位从明文派生，不从密文截取。不支持直接对密文模糊搜索。
- 默认 API 列表、详情与导出脱敏。当前取机人导出存在 admin 显式 includeSensitive=true 的敏感导出分支，必须单独审查授权与真实验收，不能宣称所有导出均不含明文。
- 结构迁移与存量明文转换分开，后者见[迁移指南](数据库初始化与迁移指南.md)。

## 状态与 JSONB 规则

- 账号/取机人状态：未使用、使用中、已下架、异常。
- 用户角色：admin、operator、readOnly；账号状态 active、locked。
- 订单状态：payment_due、payment_received、processing、shipped、ready_for_pickup、picked_up、payment_expired、delivered、cancelled、pickup_cancelled、unknown；pending、completed 仅兼容历史记录，不由新官网映射生成。
- products 保存有效商品数组，身份一致后的官网非空有效字段优先，数量允许为 0，型号缺失保留导入值或空值；official_products 保存最近官网商品结果，不存图片、动作链接或动态节点键。source_snapshot 保留首次合并前的导入商品、付款方式、日期与门店等白名单字段，供持续冲突对比；不保存密码、联系人、身份证或订单链接。validation_issues 保存当前冲突，普通差异不阻止官网合并；订单身份异常阻止业务字段写入和付款分配。
- pickup_status 新值为 not_ready、ready_for_pickup、picked_up、not_applicable、pickup_cancelled、unknown；旧 not_picked_up 保持历史兼容。不同商品阶段不能以首项代表整单，无法明确汇总时 status=unknown、official_status_needs_review=true；各项都处于已确认终态时 official_all_items_terminal=true。付款确认与人工任务四态独立。

## 关联与迁移核验

- orders.apple_id_ref → apple_ids.id，orders.recipient_ref → recipients.id；关联允许缺失时保留快照。
- recipients.apple_id_ref → apple_ids.id；crawl_logs.order_id → orders.id。
- 模型关联入口为[index.js](../../src/models/index.js)。订单刷新任务、调度和批次删除订单时级联清理；人工用户删除时 `requested_by/updated_by` 置空。关联别名和删除策略需与对应模型及 Migration 一起核对，不从历史示例直接重建约束。
- 结构演进入口为[migrations](../../migrations/)。本轮静态核对发现旧文档的 recipients.password 容量、email_uid 长度等与模型声明不一致，现已按模型标注，未改变数据库。
- email_uid 唯一字段尚未形成“邮箱身份 + UIDVALIDITY + UID”的完整语义；有 retry_count 字段不代表监听重试已经持久化。
- 订单官网金额与内部应结金额分离；付款人和内部结算表尚未实施，见[规划](../planning/付款人与内部结算方案.md)。

## 用户软删除（2026-09-09）

Migration `20260909000005-add-user-soft-delete.js` 为 `users` 新增可空 `deleted_at`（模型 `deletedAt`，DATE），Sequelize 开启 paranoid。默认查询排除软删除账号，历史任务负责人和邮件处理人关联显式保留已删除身份。删除时锁调度和用户行，存在 pending／processing／exception 付款任务则拒绝；否则锁号、清空会话、停止自动接单并设置删除时间。历史权限与审计不清理，用户名唯一约束保留，防止复用历史身份。

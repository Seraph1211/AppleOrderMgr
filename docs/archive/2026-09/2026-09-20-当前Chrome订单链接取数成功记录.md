# 当前 Chrome 订单链接取数成功记录

> 时间：2026-09-20 01:40—01:44（北京时间）
> 结论：当前用户 Chrome 环境、指定单的原始链接两次重新加载均取得有效可见订单信息；生产抓取修复尚未完成
> 授权：用户明确要求自行操控电脑，目标是通过订单链接取得订单信息；误发的截止时间要求已排除出本任务

## 操作与证据

1. 保留用户已经成功打开的原标签页，使用同一 Chrome 浏览器配置新建标签页，导航至已授权订单的原始 xc/cn/vieworder 链接；没有复制旧页面的临时访客 URL 或 Cookie。
2. 首次返回页面仍显示 loadingSpinner，稍后正常脚本完成加载，出现匹配订单号、下单日期、两个独立商品项及当前处理状态。
3. 在新标签页再次导航至同一原始链接；初次短等待未见商品，稍后观察到两个商品项、匹配订单号和加载图标消失。第二次导航后的明确观测距发起约 38.6 秒，这不是精确网络耗时，实际完成时点没有连续采样。
4. 仅通过可见 DOM 提取订单头和每个商品容器；识别“正在处理中”“已完成”“未完成”的对应步骤，未把轨迹文字出现当成当前状态。

读取字段：订单号与指定单一致，下单日为 2026-09-19；两个独立商品项均为 iPhone 18 Pro Max 256GB 黑色，当前阶段“正在处理订单”，付款步骤“已收到付款”为已完成，准备取货／已取货均未完成，门店 Apple 南京东路，预约原文“今天13:00–13:15”。根据本次北京时间观察日归一化预约日为 2026-09-20，同时保留原文。

页面未明确显示数量、金额、币种及原始官网状态码；结构化结果保留 null，不依据商品容器数推断每项数量，不将可见 DOM 冒充原始 orderDetail JSON。实际订单结果存于忽略目录 `test-artifacts/order-browser-profile-20260920/订单信息.json` 与同目录中文说明，不保存完整访客链接、Cookie、令牌或账号资料。

## 已证实与未证实

- 已证实：通过当前用户 Chrome 的原始订单链接，可重复取得该单的有效可见字段；之前只读查看旧页面的证据已经由两次新导航补强。
- 未证实：哪一种 Cookie、出口或浏览器环境差异是成功原因；没有单变量对照，不能将原因简单归为 Cookie 或 IP。
- 当前 Chrome 加载属于用户授权的正常浏览器操作，未改浏览器配置或接入服务器 Worker；不声称个人浏览器的所有原生子请求经过生产 PostgreSQL 限流。此前独立代理实验的逐请求限流证据见[对照记录](2026-09-20-官网订单浏览器对照验证记录.md)。
- 生产代理／全新会话未复现成功，因此未发布浏览器兜底或导入个人会话。没有订单回写、付款／取消动作、配置切换、部署或 Git 提交。

## 后续接入边界

当前成果可供用户核对该订单，并证明“当前 Chrome 辅助读取”路径有效。若要将该路径产品化为系统采集，应设计只读取正常页面业务字段的本机采集端、受控回传、订单身份校验和权限审计；不得直接复制个人浏览器凭据到服务器，也不能将此次单单成功标记为后台批量稳定性验收。

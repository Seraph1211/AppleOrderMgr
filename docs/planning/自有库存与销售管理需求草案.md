## 已确认的业务范围

| 事项       | 会话确认口径                                                                                       |
| ---------- | -------------------------------------------------------------------------------------------------- |
| 来源与单位 | 机器从全国 Apple 直营店取出。一笔来源订单通常有两台手机，按每台独立管理，不把每单数量固定为两台    |
| 唯一身份   | 以 SN（Serial No.，序列号）识别每台手机，多台手机可以关联同一来源订单                              |
| 收货与补录 | 每台机器已有照片和清晰 SN，收货时逐台登记；系统漏录时依据照片补录，来源订单可暂缺并后补            |
| 重庆仓库   | 目前两个仓库，位置精确到仓库即可，需要知道每台机器所在仓库，不管理货架或柜位                       |
| 接单方式   | 客户指定型号、容量、颜色和数量；先确认可售库存满足需求，再接单                                     |

| 跨仓交货   | 同一笔销售允许从两个仓库凑货，每台记录实际出库仓库；通常一次交齐，分批交货暂不作为主要流程         |
| 销售记录   | 每台记录 SN、实际售价和实际销售日期，并追溯客户及销售归属；以真正售出的日期统计销售                |
| 人员角色   | 区分销售负责人、交货人和登记人，可以同一人承担；销售负责人可以是内部员工或外部合作人               |

| 数据权限   | 管理员可看全部；其他内部人员按授权操作，成本、利润及回款信息分别控制，收发货权限不自动包含财务查看 |

| 全额转回   | 重庆销售负责人通常全额转回货款，其他费用另算；费用不直接冲减应转回的货款                           |

| 额外费用   | 记录快递费、跑腿费等出货费用；单台专属费用归具体机器，多台共用费用按台数均摊                       |

## 已确认的默认操作规则

| 事项         | 确认后的处理                                                                                       |
| ------------ | -------------------------------------------------------------------------------------------------- |
| 订单关联暂缺 | 有 SN 即可据实登记入库和销售，来源订单后补；照片中的 SN 必须经过核对，不编造身份或来源             |
| 成本确认     | 系统可带出拿货时对应规格的官网参考价，由内部人员确认；不能确认的成本标为待核实，不按零成本计算利润 |
| 接单取消     | 取消未交货需求后释放占用；暂不设置自动超时释放，避免仍有效的订单失去库存占用                       |
| 费用后补     | 允许后补，费用未确认时显示待完善；扣除已登记费用后的利润不冒充完整净利润                           |
| 回款关联     | 一笔到账可以关联多台机器或多笔销售；未转足部分保留待回款，不因部分到账标记全部结清                 |
| 录错更正     | 允许有权限的内部人员更正，保留修改前后内容、操作人及时间                                           |
| 历史录入     | 支持逐条补录及 Excel 批量导入，导入前核对与预览                                                    |
| 入库确认     | 以实际收到并核对机器为准，订单显示已取货不会自动变成重庆现货                                       |

## 暂定业务口径

明威提供的价格含义尚未实际核实。用户指定本阶段按以下假设设计：记录明威与买家的实际成交价，代卖费另算。该假设不代表已经取得真实结算明细或核实其收款方式。

暂按成交价计算收入和销售毛利，代卖费作为单独费用。后续取得真实明细后，核对价格含义、代卖费归属和转款方式，防止把已经扣费的结算价当作成交价后再次扣费。

## 重庆自销业务流程

1. **收货登记**：依据实物或留底照片核对 SN、型号、容量和颜色，登记实际仓库及可确定的来源订单。SN 必须明确，来源订单暂缺不阻止据实入库；按拿货时官网价确认成本，无法确认则显示待核实。
2. **库存查询**：内部人员按规格查询两个仓库的现货与可售数量，也可按 SN 查询某台机器的位置和记录。
3. **接单占用**：记录客户需求、销售负责人及各规格数量，确认可售数量足够后占用数量。此时不锁定具体 SN，也不形成已售记录或毛利。
4. **挑货交付**：从一个或两个仓库挑选匹配的机器，核对 SN、规格和数量，记录交货人、逐台售价、出库仓库与实际交货日期，通常整笔一次交齐。
5. **登记费用**：记录共用费用和机器专属费用，按确认口径分摊；费用尚未取得时标记待完善，后续补齐。
6. **登记货款交接**：客户款项由销售负责人代收时，分别记录代收及转回情况；公司实际到账与对应销售关联，转回货款不重复计算销售收入。

规格数量占用与实物身份分别记录。例如某规格现货 5 台，确认客户要 3 台后，其余客户可购买数量为 2 台；这 3 台具体对应哪些 SN，在交货时确定。不能把未分配 SN 的数量占用错误展示为某台已经被指定预留。

客户取消未交货需求后释放占用数量，不自动超时释放。接单修改和录错更正必须保留操作历史；此类接单取消不同于首期排除的售后退货。具体交互按后文产品方案建议细化。

## 明威代卖业务流程

1. 全国取出的机器可以直接发往明威，也可按实际情况从重庆发出，记录所涉及的 SN 和实际去向。
2. 发往代卖方的机器仍作为未售资产追踪，但不计入重庆仓库可直接发货的现货。运输、接收及代卖中的具体状态和确认方式待方案讨论。
3. 明威提供实际售出的 SN 与售价，内部人员登记对应机器的销售日期、收入及费用。未售机器继续留在代卖库存中。
4. 销售与货款回收分别跟进；代卖成交价和费用按上节暂定口径处理，具体到账关联方式待方案确定。

代卖库存可以分次售出，其中每次对最终客户的出货按实际销售记录登记。重庆常规销售“一次交齐”的约定不意味着一批寄给明威的全部机器必须同日售出。

## 毛利与费用口径

- 单台销售毛利 = 单台实际售价 − 单台官网成本价。
- 单台扣除已登记费用后的利润 = 单台销售毛利 − 单台专属费用 − 分摊到该台的共用费用。
- 整笔或渠道汇总以单台结果汇总；明威代卖费按暂定规则作为额外费用。
- 公司实际到账是资金交接结果，不能把到账金额再次当作销售收入，也不能把销售毛利当作已经到账的现金。

以下为说明分摊规则的假设示例：一次出货 3 台，共用快递费 30 元，每台分摊 10 元。其中一台另有跑腿费 20 元，则该台总费用为 30 元，另外两台各为 10 元，合计仍为 50 元。金额除不尽时，产品方案建议按分处理：先均分整数分，剩余分按确定的 SN 顺序逐台补一分，保存分摊结果，确保单台合计始终等于原费用。

用户已确认保留每台拿货时对应型号的官网成本值，官网后续调价不重算历史利润。录错由有权限人员明确更正并留痕。不能确认的成本标为待核实，对应毛利显示待核实，汇总同时提示未计入利润的机器数量；费用未补齐时明确显示待完善。成本未确认不等于免费取得机器，未填费用也不等于已经确认没有费用。

## 当前库存与历史补录

用户确认的启用顺序为：建立当前未售库存 → 记录启用后的新销售 → 逐步补录之前已经售出的机器、售价和回款。

补录遵循以下一致性要求，具体录入和校验交互见后文产品方案建议：

- 当前未售机器按真实位置记录，重庆仓库和代卖处分别可查。
- 启用前已经卖出的机器直接进入历史销售补录，不增加当前现货，也不再次扣减启用时盘点出的现货。
- 区分实际销售日期、实际到账日期和补录时间，历史补录归入真实业务日期，不归入补录当天销量。
- 按 SN 核对是否已经有机器记录，补充或关联已有记录，防止同一台重复建档和重复计入销量。
- 历史尚未转回的货款继续进入待回款统计；已回款记录补齐后保留对应关系。
- 所有机器都有照片可核对 SN；系统尚未录入的机器先依据照片完成 SN 登记，不设置无 SN 现货账。来源订单或成本资料暂缺时显示待补关联或待核实，后补不生成另一台机器。

用户已确认逐条补录、Excel 批量导入和导入前核对。当前仅整理需求与方案，未接收、导入或改写历史业务数据。

## 电脑与手机的使用方式

已确认电脑和手机都会使用，以电脑端为主，手机端需要适配。以下为已批准的交互安排：

- **电脑端**：以表格列表为主要工作界面，便于库存筛选、规格数量核对、接单、跨仓选机、费用与回款查看及历史补录，提供 Excel 导入预览和逐行错误核对。
- **手机端**：适配日常查库存、SN 扫码或图片识别、收货登记、挑货交付及销售记录查看等流程。采用适合窄屏的列表和分步表单，保留重要字段和操作，避免仅缩小桌面布局。
- **两端衔接**：建议共享同一笔接单、实机核对与登记结果，支持电脑接单后手机挑货；两端使用相同业务校验和数据权限，具体交互与并发反馈待设计。

视觉与响应式实现遵循[前端设计规范](../development/前端设计规范.md)。验收覆盖电脑常见宽度，以及 375px 手机布局、短视口、表单滚动与相机开启关闭场景。本轮浏览器及合成设备验证已执行，真实触屏硬件、系统软键盘和包装盒光学识别尚未验证，详见独立验收报告。

库存页面建议提供“规格汇总”和“单台明细”两个视图：前者用于判断能否接单，后者用于按 SN 查找具体仓库及出货核对。接单占用尚未指定仓库或 SN 时，汇总分别展示各仓现货与重庆整体占用、整体可售数量，不把占用任意分配给某个仓库。明威代卖库存单独展示，不计入重庆现货可售；建议字段与操作见下文。

## 产品交互方案

以下是依据已确认需求形成的产品交互方案，页面字段、状态和操作按配套编码实施方案及契约执行。本文保留需求口径，实现与验证状态以独立验收报告为准；业务规则以上文确认结果为基线。

### 收货与库存页面

现有取货记录保留按订单办理交接的职责。在已有订单的设备列表提供“确认入库”，复用已有 SN，再选择实际收到机器的仓库和时间；未实际收到的机器不确认仓库现货。新增从库存页面直接登记的入口，支持已知 SN、来源订单暂缺的情况。

收货表单按“核对 SN → 确认规格与仓库 → 确认拿货日期及成本”安排。支持相机扫码、图片识别和手动录入；识别结果须核对，保存成功后才展示为已登记。收货、拿货和系统录入时间分别表达事实，避免用今天的录入时间替代历史拿货日期。

照片可以关联到一批机器或多台 SN，支持复用既有留底照片；不强制一台重新拍一张。照片上传与私有访问的接入方式在技术方案中确定，不把现有 OCR 的临时图片自动视为已经长期保存的凭证。

库存页面默认“规格汇总”，另有“单台明细”和“流转记录”。建议字段如下：

| 视图     | 建议展示字段                                                                                   | 常用动作                                 |
| -------- | ---------------------------------------------------------------------------------------------- | ---------------------------------------- |
| 规格汇总 | 型号、容量、颜色、两个重庆仓库各自现货、重庆现货合计、已接单占用、重庆可售、代卖未售、在途数量 | 按规格筛选、查看机器、带入客户接单       |
| 单台明细 | SN、规格、当前位置、实物状态、拿货与入库日期、来源订单或待补关联、官网成本及确认情况           | 查详情、补订单、登记转仓或代卖、查看销售 |
| 流转记录 | 时间、SN、来源位置、目标位置、操作类型、经手人与登记人                                         | 按机器、日期或仓库查询                   |

单台详情集中显示来源、照片、位置变化、成本、销售、费用、货款关联和更正历史，字段按权限返回与展示。仓库和外部合作人提供简单维护入口；停用只影响新操作，不删除历史引用。客户以名称或商户称呼为主要识别，电话、地址等仅按交货需要选填。

### 接单占用与跨仓挑货

销售出货页面分别查询重庆自销和明威代卖销售。重庆新接单先填写客户、销售负责人、商品规格及数量；允许多种规格同单。售价可以先填写约定价格，交货确认前按每台核对实际售价。

建议销售状态为“草稿”“待出货”“已出货”“已取消”。草稿不占库存；确认接单时检查并占用数量；取消待出货单释放占用。待出货数量增加时重新校验可售，减少时释放差额，禁止静默覆盖其他操作人的修改。

客户销售单与 Apple 来源订单分别编号和关联，不能因两者都叫订单而混用。一个客户销售单可以包含来自多个 Apple 订单的机器。

挑货页先展示需求与已挑数量，按 SN 扫描、搜索或手动选择机器。机器必须符合规格、属于可交付现货、尚未售出且未被其他销售单选中。同一销售可以跨仓选机；保存的挑货结果对另一端可见。确认出货前，逐项检查每个规格数量与 SN 数量一致，核对逐台售价和实际交货人，完成整笔一次交货。

数量占用和已挑 SN 不能重复扣减：待出货数量包含已经挑出的机器；挑货只进一步确定实机，正式出货时同时减少仓库现货和该销售单占用量。多人接单或跨端挑同一台时，只能有一个有效结果，失败方刷新核对，不产生负库存或双重出货。

取消接单同时解除本单的实机选择。已售记录通过有权限的纠错流程处理，不直接删除历史或伪装成退货。销售价格允许真实亏损，利润可以为负数。

### 仓库转移与代卖登记

建议机器位置按“仓库中”“运输中”“代卖处”“已售”区分，来源订单待补和成本待核实作为独立提示，不混入实物状态。

跨仓转移登记明确 SN、起点、终点、交接人和时间。发出后记录在途，目的仓实际收到后确认到仓；同一台在途不能同时算两个仓库现货。交接已同时完成时可在一次操作中记录发出与接收事实，仍保留两端时间。

已挑入待出货销售单的机器不可直接挪走；其他仓库移出或送代卖也要检查剩余重庆可交付数量是否足以覆盖已接单占用，不能破坏已有承诺。在途和代卖机器不参与重庆即时可售数量。

代卖登记记录 SN 列表、代卖方、来源位置、发出和接收时间。全国门店取出后直发明威，可以直接记录真实去向，不能补造重庆入库。内部人员收到明威的销售明细后，按 SN 录入实际售价和日期，系统核对该台确实归其代卖且尚未售出；明威库存不通过重庆接单占用流程扣减。

### 销售费用与利润展示

销售详情提供“整笔共用费用”和“单台费用”。费用记录类型、金额、发生日期及备注，可选登记实际垫付人；首期重点是费用归属和利润计算，不新增完整报销或对外付款审批体系。

费用可先标记待完善，补齐后重新计算扣费后的利润并保留变更历史。未知成本的机器仍可据实登记销售，但其毛利不输出虚假数字。汇总同时显示销量、销售额、已确认成本对应的毛利、待核实成本台数及费用待完善情况，让部分可计算数据与完整利润结论明确区分。

费用分摊保持合计相等；修改费用时显示变更前后金额和受影响机器。官网成本只在明确更正时改变，不能随着参考价表更新或后补来源订单被自动覆盖。

### 回款页面与资金关联

分别记录客户付款事实和公司到账事实。收款去向建议支持公司直接收款、合作人代收；代收人默认销售负责人，可以按真实情况更正。若客户直接付公司，同一笔收款只计一次公司到账，不虚构销售负责人再次转回。

回款页面建议有“待转回汇总”“销售回款明细”“到账记录”三个视图。汇总按实际代收人展示已代收、已转回、尚未转回金额，点击后追溯对应销售及 SN；未确认客户付款的记录单独提示，不能直接认定销售负责人持有这笔钱。

到账登记填写实际到账日期、金额和实际转款人，再选对应销售及分配金额。一笔到账可分配至多笔销售或多台机器，一笔销售也可由多次转回补齐；这是代收款的交接，不是客户定金尾款功能。部分到账保留剩余未回款，且分配合计不能超过实际到账，也不能超过所选销售的未回款金额；未分配金额明确显示，不能假装已完成关联。

支持到账截图或备注作为辅助凭证，建议选填；内部人员根据实际账户记录确认到账。录入页面的成功提示只说明保存成功，不代替实际资金到账核对。费用另算，不从应转回销售货款中扣除。

回款是否完成与利润计算分别展示：实际出货日归集销量、销售额和毛利，到账日归集资金；同一销售不能因转款或重新关联到账而再次增加收入。明威的售价与费用采用已指定假设，真实结算口径核实后通过明确更正留痕。

### 核心记录字段建议

以下是产品层面的记录内容，尚非数据库字段、枚举或接口契约：

| 记录       | 主要内容与校验                                                                                        |
| ---------- | ----------------------------------------------------------------------------------------------------- |
| 手机       | SN 唯一且必填，型号、容量、颜色；来源订单允许暂缺；拿货日期、官网成本值及确认情况；照片关联与创建记录 |
| 实物位置   | 当前仓库或代卖方、在途起终点、发出接收时间；同一台不能同时出现在两个现货位置                          |
| 接单明细   | 客户、销售渠道、负责人、规格、数量、约定价及状态；按规格占用，不提前虚构 SN                           |
| 出货明细   | 客户销售单、SN、实际仓库、销售日期、逐台实际售价、交货人、登记人；同一 SN 不重复销售                  |
| 费用       | 类型、金额、发生日期、整笔或专属归属、具体分摊结果、费用完整性及变更记录                              |
| 客户付款   | 对应销售、付款日期、金额、实际收款去向与代收人、确认人；与公司到账分开                                |
| 公司到账   | 实际日期、金额、转款人、对应销售及分配金额、未分配余额、登记人、可选凭证                              |
| 历史与纠错 | 业务发生时间与登记时间分别保存，更正原因、前后内容、操作人及时间                                      |

### 权限与更正历史

管理员可看全部。普通内部人员逐项授予库存查看、收货、转仓、接单、出货、补录导入、费用登记及更正等操作；成本查看、利润查看和回款查看／登记分别配置。外部合作人不创建登录账号。

成本、利润存在可推算关系：知道售价和毛利即可算出成本。技术方案应把这一点体现在授权提示与权限依赖中，建议授予利润查看时同时要求成本查看，避免提供表面上的成本保密。回款权限独立于库存收发操作。

敏感金额的限制必须覆盖后端响应、详情、合计、导出和历史记录，不能仅隐藏列。库存授权不扩大来源 Apple 订单现有 TAG 范围；未获来源订单权限时，只允许访问其已授权库存记录和必要来源提示，不开放完整订单、账号或联系方式。来源订单未知的机器按库存功能授权处理，不能因为没有订单就跳过权限检查。

更正需显示受影响记录和前后差异，保留原始依据；已出货、已关联回款或已用于费用分摊的记录不得通过普通删除清空痕迹。更正 SN、售价、成本和到账金额后检查关联及汇总，避免仍保留旧关联导致重复统计。

### Excel 导入与历史启用

建议按业务目的提供“当前未售库存”“历史销售”“历史回款”三种导入模板，分别标明必填字段、日期格式和关联规则。当前库存每台必须有 SN 和真实位置；历史销售必须有 SN、实际销售日期和售价；来源订单可待补。回款导入要能对应既有销售或进入明确的待关联状态。

导入流程为“选模板上传 → 解析预览 → 核对重复与差异 → 确认写入”。预览按行给出错误原因，区分新增、可补充和冲突；冲突不能静默覆盖。重传同一批记录应识别已经登记的内容，不新增第二台机器、第二笔销售或第二次到账。相同日期与金额不足以判定同一笔到账，须使用稳定的记录标识及人工冲突核对。

模板保持成本与回款字段权限；无对应权限的人员不能通过导入或导出绕过限制。照片沿用既有留底资料逐步关联，Excel 导入不以自动扫描个人相册或聊天记录为前提。

启用时确定业务切换时间并登记当时未售机器，之后发生的销售照常登记。补录切换前已售机器只补历史，不影响当前实物现货；若同一 SN 与现货或新销售冲突，进入核对，不自动改写。具体切换日期、真实仓库名称和导入文件在启用时填写，不是今晚需求讨论的阻塞项。

### 统计与日常查询

首期提供与业务记录可核对的统计：各仓及代卖处未售台数、重庆可售与占用数量、按实际销售日期的销量与销售额、单台和销售负责人毛利、扣已登记费用后的利润、按代收人的待转回金额和按到账日期的实收金额。

统计按渠道、人员、规格和日期筛选，每个汇总可进入构成明细。费用后补和成本更正会更新对应历史销售利润并保留记录；到账晚于销售时，不把销售改归到账日。库存占用未指定仓库时只在重庆总体展示，避免各仓重复减同一笔占用。

## 后续技术工作与交付顺序

当前业务需求已足够进入编码，明威真实结算保留已指定假设。目标结构、接口、事务、文件分工、迁移和验收已经写入[编码实施方案](自有库存与销售管理编码实施方案.md)，剩余工作按开发任务执行，无需重复询问已经确认的口径。

1. **开发启动**：按实施方案的四类入口、字段、状态与手机流程编码；页面原型可随前端开发产出，不再作为等待用户讨论的前置门槛。
2. **契约实现**：按已写入权威入口的目标数据与 API 契约实现实物身份、旧绑定兼容、来源订单可暂缺、照片授权、数量占用、资金关联与权限审计；使用正式 Migration。
3. **重庆主流程实现与验收**：优先完成库存、接单占用、跨仓整单交货、费用毛利和回款，验证电脑及手机。代码与测试为后续阶段，当前没有开始。
4. **代卖及历史导入交付**：完成明威库存与逐台销售、当前库存初始化和历史销售／回款导入，并验证与重庆统计合并后不重复计数。代卖属于本轮总范围，不因重庆优先而被删除。
5. **启用准备**：核对真实仓库和人员、成本参考数据、启用时点与导入预览，再按相应授权执行上线、盘点和历史导入。开发自测、真实业务验收与生产发布分别记录。

用户已授权交由子 Agent 在隔离工作区编码，由主 Agent 独立验收并安排返工直至本地技术验收通过。生产迁移、真实业务数据写入或发布仍按相应操作授权执行。

## 后续验收场景草案

以下为需求推导的验收场景，本轮实际执行证据见专项清单及独立验收报告；用例本身不代表真实业务已经验收：

1. 同一来源订单的两台手机分别进入不同仓库，能按 SN 找到位置和来源。
2. 同规格现货 5 台，已接单占用 3 台后，可售显示 2 台；多人接单不能重复占用超出可售数量的机器。
3. 客户购买 3 台，两个仓库分别出 2 台和 1 台，交货前核对全部 SN、规格和数量；每台归属实际出库仓库，不重复出库。
4. 共用费用与单台专属费用分别分配，单台费用合计等于整笔实际登记费用。
5. 外部销售负责人昨天售出 3 台、今天全额转回货款，销量毛利归昨天，到账归今天，转款不增加销量或收入。
6. 一批手机直接送往明威，未售时保留代卖库存；收到其中部分 SN 的销售明细后，只确认这些机器已售。
7. 已有 SN 但来源订单待补时，按最终确认的规则登记及补齐，补录不生成另一台机器。
8. 补录启用前历史销售和回款，不改变启用时真实现货数量，不重复累计已经存在的销售。
9. 取货扫码、人工取货状态、取货结款、库存入库、销售收入和销售回款各自保持含义，不因衔接而相互误改。
10. 电脑端接单与手机端挑货读取同一笔业务及最新占用情况；375px 触屏、短视口及软键盘展开时，重要字段和提交操作可用，扫码失败或取消不误登记成功。
11. 每台收货必须录入经实物或照片核对的 SN；来源订单暂缺仍能入库、销售和后补关联，系统不生成无 SN 占位机器。
12. 官网参考价变更不会改变已确认单台成本；成本待核实时不产生零成本高毛利，费用待完善时清楚提示利润计算范围。
13. 取消待出货需求释放占用与已挑实机；订单长时间未交付不会自动释放仍有效的占用，增加数量及移动机器不会造成超卖。
14. 一笔到账关联多笔销售，或一笔销售分次转回，剩余金额正确；公司直接收款不再生成重复转款，回款更正保留历史。
15. 普通收发货账号不能通过接口、汇总、导出、导入、照片或操作历史获取未授权成本、利润、回款及来源订单资料；管理员可按确认范围查看全部。
16. Excel 导入先预览，重复 SN、矛盾仓库、重复销售及回款关联冲突可识别；重复提交不新增重复业务记录，历史补录日期和当前库存独立。
17. 3 台均摊 1 元时得到 0.34、0.33、0.33 元，顺序确定且合计仍为 1 元；费用补录、更正与重新查看不会产生金额漂移。

上述验收场景均为待执行计划。当前仅完成需求与产品方案文档，尚未开发、运行功能测试、导入真实数据或发布。

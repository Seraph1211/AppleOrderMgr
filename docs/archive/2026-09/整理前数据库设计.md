## 🔐 v3.0 安全存储约束（优先于下方历史示例）

自 v3.0 起，数据库中的敏感字段不得保存明文：

- `apple_ids.password`、`apple_ids.security_qa`、`recipients.id_card_number`、
  `recipients.password`、`orders.apple_password`、`orders.recipient_id_card` 使用
  AES-256-GCM 信封格式保存，密钥由 `FIELD_ENCRYPTION_KEY` 注入。
- `email_logs.raw_content` 与 `email_logs.parsed_data` 可能包含完整账号、身份和订单信息，必须分别使用文本密文与 JSONB 密文包装保存。
- `recipients.id_card_hash` 保存标准化身份证号的 HMAC-SHA256 盲索引，用于唯一性校验和精确匹配；
  不支持通过密文做模糊检索。
- 密钥版本由 `FIELD_ENCRYPTION_KEY_VERSION` 标识。应用只写当前版本，并通过 `FIELD_ENCRYPTION_KEYS_JSON` 兼容读取已配置的旧版本密钥。
- 盲索引可使用独立的 `FIELD_BLIND_INDEX_KEY`；若轮换该密钥，必须在单一事务中重建全部盲索引。
- 普通列表、订单详情和导出不得返回 Apple 密码、密保答案、完整身份证或完整地址。
- 迁移只调整字段容量、唯一索引和盲索引结构；存量明文转换必须运行独立迁移任务，并在执行前完成备份和密钥确认。

下文 v2.0 中的“明文存储”与明文示例仅作为历史结构说明，不再代表允许的实现方式。

## 1️⃣ users - 用户表

### 表定义

**用途**：管理系统登录用户，实现基于 JWT 的认证和角色权限控制

**表名**：`users`

**字段列表**：

| 字段名                  | 类型         | 约束            | 默认值       | 说明                           | 示例值                            |
| ----------------------- | ------------ | --------------- | ------------ | ------------------------------ | --------------------------------- |
| **基础信息**            |
| `id`                    | SERIAL       | PRIMARY KEY     | -            | 主键ID，自增                   | 1                                 |
| `username`              | VARCHAR(50)  | UNIQUE NOT NULL | -            | 用户名（登录用）               | `admin` / `user01`                |
| `password`              | VARCHAR(255) | NOT NULL        | -            | 密码（bcrypt 加密）            | `$2b$10$...`                      |
| **角色权限**            |
| `role`                  | VARCHAR(20)  | NOT NULL        | `'operator'` | 用户角色                       | `admin` / `operator` / `readOnly` |
| `status`                | VARCHAR(20)  | NOT NULL        | `'active'`   | 账号状态                       | `active` / `locked`               |
| **安全字段**            |
| `failed_login_attempts` | INT          | NOT NULL        | 0            | 连续登录失败次数               | 0-5                               |
| `locked_until`          | TIMESTAMP    | NULL            | -            | 锁定截止时间（NULL表示未锁定） | `2026-07-19 10:30:00`             |
| `force_password_change` | BOOLEAN      | NOT NULL        | FALSE        | 是否强制修改密码（首次登录）   | `true` / `false`                  |
| **审计字段**            |
| `last_login_at`         | TIMESTAMP    | NULL            | -            | 最后登录时间                   | `2026-07-19 09:15:30`             |
| `last_login_ip`         | VARCHAR(50)  | NULL            | -            | 最后登录IP                     | `192.168.1.100`                   |
| **时间戳**              |
| `created_at`            | TIMESTAMP    | NOT NULL        | NOW()        | 记录创建时间                   | `2026-07-19 08:00:00`             |
| `updated_at`            | TIMESTAMP    | NOT NULL        | NOW()        | 记录更新时间                   | `2026-07-19 09:00:00`             |

### role 字段枚举值

| 角色值     | 含义       | 权限说明                                           |
| ---------- | ---------- | -------------------------------------------------- |
| `admin`    | 管理员     | 全部功能 + 用户管理 + 删除操作                     |
| `operator` | 业务操作员 | 查询、修改、脱敏导出和受控刷新，不能删除或管理用户 |
| `readOnly` | 只读用户   | 仅查询脱敏数据                                     |

### status 字段枚举值

| 状态值   | 含义 | 说明                           |
| -------- | ---- | ------------------------------ |
| `active` | 正常 | 可以正常登录                   |
| `locked` | 锁定 | 连续登录失败后被锁定，禁止登录 |

### 索引

```sql
CREATE UNIQUE INDEX idx_users_username ON users(username);
CREATE INDEX idx_users_role ON users(role);
CREATE INDEX idx_users_status ON users(status);
CREATE INDEX idx_users_last_login_at ON users(last_login_at DESC);
```

### 约束

```sql
-- 唯一约束：用户名唯一
CONSTRAINT uk_users_username UNIQUE(username),

-- 检查约束：角色只能是 admin、operator 或 readOnly
CONSTRAINT chk_users_role CHECK (role IN ('admin', 'operator', 'readOnly')),

-- 检查约束：状态只能是 active 或 locked
CONSTRAINT chk_users_status CHECK (status IN ('active', 'locked')),

-- 检查约束：失败次数不能为负数
CONSTRAINT chk_users_failed_attempts CHECK (failed_login_attempts >= 0)
```

### 触发器

```sql
-- 自动更新 updated_at 字段
CREATE TRIGGER trigger_users_updated_at
BEFORE UPDATE ON users
FOR EACH ROW
EXECUTE FUNCTION update_updated_at_column();
```

### 示例数据

```sql
-- 默认管理员账号（密码：admin123）
INSERT INTO users (
  username,
  password,
  role,
  status,
  force_password_change
) VALUES (
  'admin',
  '$2b$10$YourBcryptHashHere',
  'admin',
  'active',
  true
);

-- 普通用户示例（密码：user123）
INSERT INTO users (
  username,
  password,
  role,
  status
) VALUES (
  'user01',
  '$2b$10$YourBcryptHashHere',
  'user',
  'active'
);
```

### 业务规则

1. **账号创建**：
   - `username` 长度 3-50 字符，只允许字母、数字、下划线
   - `password` 使用 bcrypt 加密（salt rounds = 10）
   - 首次创建的管理员账号必须设置 `force_password_change = true`

2. **登录失败锁定**：
   - 连续失败 5 次 → 锁定 15 分钟
   - 锁定期间禁止登录（`status = 'locked'` 且 `locked_until > NOW()`）
   - 成功登录后重置 `failed_login_attempts = 0`

3. **密码策略**：
   - 最小长度 6 位（可在应用层扩展复杂度要求）
   - 强制修改密码后清除 `force_password_change` 标记

4. **安全审计**：
   - 每次登录成功后更新 `last_login_at` 和 `last_login_ip`
   - 登录失败时递增 `failed_login_attempts`
   - 达到阈值时设置 `status = 'locked'` 和 `locked_until`

5. **角色权限**：
   - `admin` 可以管理用户、删除数据
   - `user` 只能查看和修改订单，不能删除

```json
  "question2": "工作",
  "answer2": "136",

  "answer3": "142"
}
```

**字段说明**：

| 字段名      | 类型   | 说明              |
| ----------- | ------ | ----------------- |
| `question1` | String | 密保问题1（朋友） |
| `answer1`   | String | 密保答案1         |
| `question2` | String | 密保问题2（工作） |
| `answer2`   | String | 密保答案2         |
| `question3` | String | 密保问题3（父母） |
| `answer3`   | String | 密保答案3         |

### status 字段枚举值

| 状态值   | 含义   | 说明                               |

### 约束

```sql
-- 唯一约束：标准化身份证号的盲索引唯一
CONSTRAINT uk_recipient_id_card_hash UNIQUE(id_card_hash),

-- 外键约束：关联到apple_ids表

  REFERENCES apple_ids(id)
  ON DELETE SET NULL
  ON UPDATE CASCADE
```

### 业务规则

1. **唯一性判断**：
   - 基于标准化身份证号的 `id_card_hash` 判断唯一性
   - 同一身份证号只能有一条记录

2. **自动字段填充**：
   - `id_card_last4` 与 `id_card_hash` 由应用在加密前从明文派生
   - 禁止使用数据库触发器从 `id_card_number` 密文截取后四位

3. **姓名处理**：
   - `last_name` 和 `first_name` 分开存储
   - 查询时拼接：`last_name || first_name AS full_name`

4. **地址字段**：
   - 省、市、区、街道分字段存储
   - 查询时拼接：`province || city || district || street_address AS full_address`

5. **状态管理**：
   - `未使用`、`使用中`、`已下架`、`异常` 的含义以上方枚举表为准

- 官网支付状态为 `paid` 且取货状态为 `not_picked_up`

## 📋 典型查询场景

### 场景0：用户认证和管理

```sql
-- 登录验证：根据用户名查找用户
SELECT
  id,
  username,
  password,
  role,
  status,
  failed_login_attempts,
  locked_until,
  force_password_change
FROM users
WHERE username = 'admin'
  AND status = 'active'
  AND (locked_until IS NULL OR locked_until < NOW());

SELECT
  id,
  username,
  role,
  status,
  last_login_at,
  failed_login_attempts,
  created_at
FROM users
ORDER BY created_at DESC;

-- 解锁被锁定的用户
UPDATE users
SET
  status = 'active',
  locked_until = NULL,
  failed_login_attempts = 0,
  updated_at = NOW()
WHERE id = 1;
```

```sql
  (r.last_name || r.first_name) AS recipient_name,
  r.id_card_last4,
  (r.province || r.city || r.district || r.street_address) AS full_address
FROM orders o
JOIN apple_ids a ON o.apple_id_ref = a.id
LEFT JOIN recipients r ON o.recipient_ref = r.id
WHERE r.id_card_hash = :id_card_hash
ORDER BY o.order_date DESC;
```

### 3.3 orders - 订单主表

**用途**: 存储订单核心信息

```sql
CREATE TABLE orders (
  id SERIAL PRIMARY KEY,
  order_number VARCHAR(50) UNIQUE NOT NULL,       -- Apple 订单号（W + 9位数字）
  apple_id_ref INT REFERENCES apple_ids(id) ON DELETE CASCADE,
  recipient_ref INT REFERENCES recipients(id) ON DELETE SET NULL,

  -- 产品信息（JSONB 数组，支持多商品）
  products JSONB NOT NULL,                        -- 商品列表
  /*
  [
    {
      "modelId": "MG714CH/A",
      "name": "iPhone 17 鼠尾草绿色 256G",
      "quantity": 2,
      "status": "READY_FOR_PICKUP",
      "imageUrl": "https://..."
    },
    {
      "modelId": "HNPW2ZM/A",
      "name": "Belkin Secure Holder 挂绳",
      "quantity": 1,
      "status": "READY_FOR_PICKUP",
      "imageUrl": "https://..."
    }
  ]
  */

  -- 订单状态
  status VARCHAR(50) DEFAULT 'submitted',         -- 订单状态
  /*
  状态值：
  - submitted: 已提交（邮件刚收到）
  - processing: 处理中
  - ready: 准备就绪可取货
  - shipped: 已发货
  - delivered: 已送达
  - cancelled: 已取消
  - pickup_cancelled: 取货已取消
  */

  -- 订单信息
  order_url TEXT NOT NULL,                        -- Apple 订单详情链接
  payment_method VARCHAR(50),                     -- 付款方式（支付宝/微信/信用卡）

  -- 取货信息
  pickup_store VARCHAR(255),                      -- 取机门店（如：Apple 重庆万象城）
  store_directions_url TEXT,                      -- 门店营业时间与路线 URL

  -- 时间信息
  order_date TIMESTAMP,                           -- 预订时间（来自邮件）
  order_placed_date DATE,                         -- 下单日期（来自官网）
  estimated_delivery TIMESTAMP,                   -- 预计送达
  actual_delivery TIMESTAMP,                      -- 实际送达

  -- 原始数据
  email_raw TEXT,                                 -- 邮件原文
  crawled_data JSONB,                             -- 从官网爬取的完整 JSON

  -- 时间戳
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

-- 索引
CREATE INDEX idx_orders_order_number ON orders(order_number);
CREATE INDEX idx_orders_apple_id_ref ON orders(apple_id_ref);
CREATE INDEX idx_orders_recipient_ref ON orders(recipient_ref);
CREATE INDEX idx_orders_status ON orders(status);
CREATE INDEX idx_orders_order_date ON orders(order_date DESC);

-- JSONB 索引（提高商品查询性能）
CREATE INDEX idx_orders_products_gin ON orders USING GIN(products);

-- 注释
COMMENT ON TABLE orders IS '订单主表';
COMMENT ON COLUMN orders.order_number IS 'Apple 订单号，格式：W + 9位数字';
COMMENT ON COLUMN orders.products IS '商品列表（JSONB 数组），支持多商品';
COMMENT ON COLUMN orders.status IS '订单状态：submitted/processing/ready/shipped/delivered/cancelled/pickup_cancelled';
COMMENT ON COLUMN orders.email_raw IS '邮件原文，用于审计和问题排查';
COMMENT ON COLUMN orders.crawled_data IS '从 Apple 官网爬取的完整 JSON 数据';
```

```sql
  id, order_number, order_url, status
```

### 5.3 统计某个取机人的订单数量

```sql
SELECT
  r.name,
  r.tag,
  COUNT(o.id) AS order_count,
  SUM((o.products::jsonb -> 0 ->> 'quantity')::int) AS total_quantity
FROM recipients r
```

### 5.5 爬虫成功率统计

```sql
SELECT
  DATE(created_at) AS date,
  COUNT(*) AS total_crawls,
  SUM(CASE WHEN success THEN 1 ELSE 0 END) AS success_count,
  ROUND(AVG(response_time), 2) AS avg_response_time
FROM crawl_logs
WHERE created_at >= NOW() - INTERVAL '7 days'
GROUP BY DATE(created_at)
ORDER BY date DESC;
```

### 6.2 创建触发器（自动更新 updated_at）

```sql
-- 创建通用更新触发器函数
CREATE OR REPLACE FUNCTION update_updated_at_column()
RETURNS TRIGGER AS $$
BEGIN
  NEW.updated_at = NOW();
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- 为 orders 表添加触发器
CREATE TRIGGER trigger_orders_updated_at
BEFORE UPDATE ON orders
FOR EACH ROW
EXECUTE FUNCTION update_updated_at_column();

-- 为 apple_ids 表添加触发器
CREATE TRIGGER trigger_apple_ids_updated_at
BEFORE UPDATE ON apple_ids
FOR EACH ROW
EXECUTE FUNCTION update_updated_at_column();

-- 为 recipients 表添加触发器
CREATE TRIGGER trigger_recipients_updated_at
BEFORE UPDATE ON recipients
FOR EACH ROW
EXECUTE FUNCTION update_updated_at_column();
```

### 8.1 索引优化

- ✅ 为常用查询条件创建索引（status, order_date）

```sql
CREATE INDEX idx_orders_status ON orders(status);
```

## 权威范围与维护顺序

本页是数据库文档入口，记录当前六个模型的字段声明和已确认安全规则。数据库变更仍需先讨论并更新本文，再更新模型、Migration、接口和测试。此次整理只纠正文档，不修改模型或执行迁移。

字段表中的类型、可空性、默认值来自当前模型静态声明；ORM 校验不自动等同于数据库 CHECK，模型索引也不证明 Migration 已落库。实际数据库类型、约束、索引与存量数据兼容性需通过隔离迁移核验，尚未全面验证。旧 SQL、触发器和明文插入示例已移至[历史资料](../archive/2026-09/整理前数据库设计.md)。

## 安全存储

- users.password 保存 bcrypt 哈希；Apple 密码、密保、取机人身份证和密码、订单敏感快照、邮件原文及解析结果使用 AES-256-GCM 或 JSONB 密文包装。
- FIELD_ENCRYPTION_KEY 与密钥版本负责加解密；FIELD_BLIND_INDEX_KEY 可单独提供盲索引密钥。不得把 JWT 密钥复用为字段密钥。
- recipients.id_card_hash 使用标准化身份证的 HMAC-SHA256，负责唯一性与精确匹配；后四位从明文派生，不从密文截取。不支持直接对密文模糊搜索。
- 默认 API 列表、详情与导出脱敏。当前取机人导出存在 admin 显式 includeSensitive=true 的敏感导出分支，必须单独审查授权与真实验收，不能宣称所有导出均不含明文。
- 结构迁移与存量明文转换分开，后者见[迁移指南](数据库初始化与迁移指南.md)。

## 状态与 JSONB 规则

- 账号/取机人状态：未使用、使用中、已下架、异常。
- 用户角色：admin、operator、readOnly；账号状态 active、locked。
- 订单状态：pending、processing、shipped、ready_for_pickup、completed、delivered、cancelled、pickup_cancelled、unknown。
- products 保存邮件商品数组，当前解析元素为 model、name、quantity、image；数量以邮件为准，图片由官网补充。official_products 保存官网商品结果；validation_issues 保存校验结果。
- security_qa 和 parsed_data 的数据库值是加密包装，不是可以直接复制到 SQL 中的明文对象。API DTO 与数据库存储格式分开。

## 关联与迁移核验

- orders.apple_id_ref → apple_ids.id，orders.recipient_ref → recipients.id；关联允许缺失时保留快照。
- recipients.apple_id_ref → apple_ids.id；crawl_logs.order_id → orders.id。
- 模型关联入口为[index.js](../../src/models/index.js)。关联别名和删除策略需与对应模型及 Migration 一起核对，不从历史示例直接重建约束。
- 结构演进入口为[migrations](../../migrations/)。本轮静态核对发现旧文档的 recipients.password 容量、email_uid 长度等与模型声明不一致，现已按模型标注，未改变数据库。
- email_uid 唯一字段尚未形成“邮箱身份 + UIDVALIDITY + UID”的完整语义；有 retry_count 字段不代表监听重试已经持久化。
- 订单官网金额与内部应结金额分离；付款人和内部结算表尚未实施，见[规划](../planning/付款人与内部结算方案.md)。

## 查询与验收

应用通过 Sequelize 模型访问需要解密的字段，禁止直接以明文 SQL 插入加密列。查询使用经过验证的参数、关联预加载和短事务；具体入口见[快照匹配](快照匹配.md)与[API 契约](../design/API设计.md)。

验收应逐表比较类型、nullable、默认值、唯一约束、外键和索引，再测试迁移 up/down/up 与真实数据转换。字段名覆盖检查通过只表示文档收录，不替代这些验证。

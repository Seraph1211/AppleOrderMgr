## 1. 目标与交付原则

严格实现已确认的“紧凑筛选＋大面积日志原文＋正文优先详情抽屉”。工作人员应能在浏览器100%缩放下选择服务器、实例、账号和连续日期时间区间，搜索、选择、复制日志，查看前后上下文并继续加载。

**只重构日志查询页面及其专属交互。其他页面的 UI、共享侧栏、顶栏、Logo、登录页、全局主题与全局字体保持原样。** 预览中出现的共享外壳仅提供上下文，不属于本次重构范围。

本需求包含已确认交互所必需的真实只读查询适配；不能仅接模拟数据、前端状态或 localStorage 后宣布完成。日志采集、存储迁移、Worker、通知、权限规则及保留期不在本次改造范围。标签管理复用既有正式保存能力，不新增标签业务规则。

阅读顺序：第2节范围 → 第3～9节 UI 和交互 → 第10节真实接口与数据口径 → 第11～13节隔离、验收及交付。可直接转发的[开发提示词](日志查询页面UI重构开发提示词.md)与本文件配套使用。

## 3. 已确认视觉与页面比例

### 3.1 风格

- 浅灰工作区、白色阅读面板、深灰正文，品牌蓝 `#1E3A8A` 用于主要操作、选中行和键盘焦点；浅蓝 `#EFF6FF` 用于选中背景。
- 日志是页面主体，不新增顶部统计卡片、大段说明或装饰性占位。筛选不能恢复成大卡片表单，不让一个短选项占据半屏宽度。
- 沿用项目现有字体资源与中文回退；普通 UI 沿用现有无衬线字，原文使用现有 Fira Code／等宽回退。不得为复现预览而全站换字。
- 图标沿用 Lucide React，主要为16px。操作采用轻量文字或“图标＋文字”；手机可缩为有可访问名称的图标。
- 白色控件、轻边框、小圆角；仅下拉、浮层和抽屉使用必要阴影。不得新增深色主题、渐变、玻璃效果或厚重蓝色焦点双框。

### 3.2 尺寸基准

| 项目               | 参考值与要求                                                                         |
| ------------------ | ------------------------------------------------------------------------------------ |
| 页面标题           | 24px、600字重；副文案约13px，“北京时间 · 最近90天”与真实保留策略一致                 |
| 桌面筛选           | 约32px高、12～13px文字，紧凑但保留可点击区域                                         |
| 服务器／实例／账号 | 约150／176／110px，按内容分配，不能均分占满整行                                      |
| 日期时间入口       | 单日全天约202px；单日自定义时间约272px；跨日约304px，随可用空间适应                  |
| 正文搜索           | 弹性占剩余空间；1440px默认条件约294px；跨日入口加宽时合理收缩，桌面通常不低于约190px |
| 日志正文           | 约13px、22px行高，维持原始缩进与换行；行号11～12px，作为辅助信息                     |
| 手机控件           | 输入文字16px、主要触摸目标至少44px；文字标签不挤成逐字竖排                           |
| 内容间距           | 紧凑工具栏后是采集状态和阅读面板，减少大块空白；正文面板尽量利用可用高度             |

尺寸以第14节参考图的关系与比例为准，不要求为了凑像素值牺牲完整文本、可访问性或真实数据适配。不得用整体 `zoom`、浏览器缩放或裁切内容冒充布局优化。

## 4. 主页面与筛选工具栏

### 4.1 排列与查询状态

固定顺序：**服务器 → 软件实例 → 全部账号 → 日期时间范围 → 搜索日志正文 → 查询 → 重置 → 更多筛选**。标签管理位于页标题区域右侧；不把标签管理表格直接展开在主页面。

- 1440px和1265px默认条件下尽量单行；长日期范围或长资源名称时优先合理分配宽度，空间不足有序换行，禁止页面横向溢出或把完整时间截掉。
- 工具栏始终可见，不提供整区“收起筛选”；查询、重置、刷新、切换上下文和退出专注都不能自动隐藏工具栏。
- 区分“当前已应用条件”和“正在编辑的草稿”。账号、日期时间、正文关键词及仅未识别账号在点击主工具栏“查询”后应用；日期面板“确定”和更多筛选“完成”只确认草稿。
- 服务器／实例保留现有资源切换逻辑；切换服务器清空原实例与账号，实例候选限定在该服务器下，清空旧结果、游标、选中与详情，避免短暂显示上一资源的日志。选择有效实例后按既有加载流程查询。
- 请求进行中防止重复提交；快速切换条件时取消或忽略过期响应，不把旧结果写入当前资源。
- 正文搜索保留现有匹配语义和200字符限制，不把普通关键词擅自改成正则表达式；空白按既有接口规则处理。
- “重置”清除账号、关键词、未识别开关和自定义时刻，保留当前服务器、实例及已应用的起止日期；恢复所保留日期范围的全天并从头查询。未确认的日期草稿丢弃，不偷偷切回另一服务器或其他日期。
- “刷新／重新查询”使用已应用条件从头加载，重置旧游标及选中。不能顺便提交尚未确认的筛选草稿。

### 4.2 服务器与实例下拉

- 紧凑触发框显示资源编号／名称及人工标签；选中摘要可适当缩短，但完整名称和标签可通过悬停或可访问名称读取。
- 采用已确认的浮层列表，不推开工具栏和正文；与触发器边缘协调，宽度随内容受限于视口，长标签在选项内换行，选项区内部滚动。
- 搜索名称、编号或标签，搜索框保留；列表显示选中勾选、悬停、无匹配、加载及读取错误状态。
- 服务器维持既有自然编号排序，例如 US01、US02…US10；实例以当前服务器为作用域。停用／移除资源沿用当前业务标识，不伪装成活跃资源。
- 支持方向键、Enter选择、Esc关闭、点击外部关闭并恢复合理焦点。下拉搜索框的Enter不得误提交主查询。
- 搜索或展开仅影响候选，不能把候选文字直接当作资源ID。

### 4.3 账号选择

- 位于日期时间左侧，默认显示“全部账号”；候选下拉尽量与触发框同宽，空间不足向上展开或限制高度，不超出视口。
- 可搜索、选择候选、直接输入编号、清空、返回全部账号；候选多时保留加载下一批与返回入口。
- **账号是字符串，`001`不能变成`1`。** 候选读取失败或无匹配时仍允许输入有效编号查询，不强制从候选选中。
- 候选必须使用当前服务器、实例及已应用日期时间范围；应用新范围后清空旧候选分页并重新读取，旧响应不得覆盖新范围。
- 未选实例或勾选“仅未识别账号”时禁用账号框。取消未识别开关后恢复可选，不能同时发送具体账号和“未识别”两个矛盾条件。

### 4.4 更多筛选

- 仅放次要条件“仅未识别账号”，不再常驻一整行开关。
- 轻量浮层有标题、关闭、开关和“完成”；开启后触发器显示数量1。关闭／完成不自动查询，主查询后才应用。
- 重置关闭开关；仅未识别不等于缺失数据、未知服务器或无日志。

## 5. 日期时间范围筛选（核心必做）

### 5.1 一个入口、两组完整端点

工具栏只有一个日期时间范围框，显示日历图标、范围摘要和展开箭头。**开始日期与开始时间必须同组，结束日期与结束时间必须同组。** 不得回退成上方选日期、下方分别选时间的布局，也不能只有一个日期。

桌面浮层约620px宽，左右两列：

| 左侧：开始日期时间                         | 右侧：结束日期时间                         |
| ------------------------------------------ | ------------------------------------------ |
| 开始日期输入＋开始时间输入（精确到秒）紧邻 | 结束日期输入＋结束时间输入（精确到秒）紧邻 |
| 独立月份标题、翻月按钮和日期日历           | 独立月份标题、翻月按钮和日期日历           |

- 两侧独立编辑、独立翻月；改开始端不得改变结束端，选完某天不自动跳到另一侧。
- 日期可输入也可点日历，时间支持时／分／秒输入。原生时间控件可随浏览器呈现，但必须能填写秒，不能只精确到分钟。
- 660px以下将完整端点组上下排列，组内日期与时间仍相邻；浮层限宽限高、内部滚动，确认操作可达。短屏自动选择上／下方向，不能超出窗口。
- 标题注明北京时间；底部保留“当天／近3天／近7天”、取消、确定。快捷项以**当前选中的结束日期**为基准，覆盖相应自然日全天，受保留期边界限制；悬停或可访问说明明确该基准。
- 默认按正式系统既有初始化策略展示当日全天，不固定预览日期。可选日期以服务端保留窗口为准，当前为最近90个北京时间自然日；越界日不可选，也必须在服务端校验。

### 5.2 草稿、校验与摘要

- 打开时从当前工具栏草稿初始化；编辑不立即查询。确定后只更新工具栏草稿，点击主“查询”才影响日志结果。
- 取消、关闭、Esc、点击面板外部均不提交面板内未确定修改，重新打开恢复上次确定值。关闭恢复触发器焦点。
- 校验完整的开始日期时间与结束日期时间；结束早于开始时显示明确错误并禁用确定。相等允许表示该秒，格式无效、日期越界也不能提交。
- 时间留空按该端全天边界归一化：开始 `00:00:00`，结束 `23:59:59`；不得把空时间当作当前时刻。
- 单日全天摘要可显示“YYYY/MM/DD｜全天”；自定义显示完整时段；跨日显示两端日期和秒级时刻。同年末端可省年份，跨年必须展示两端年份；完整 `title`／可访问名称始终含两端完整日期和秒。
- 摘要不使用省略号隐藏起止时刻。窄窗口允许控件变宽或自然换行，不拆成日期框和独立“全天”框。

### 5.3 连续区间及边界

例：北京时间 **`2026-10-23 16:23:55` 至 `2026-10-25 12:23:20`**。

应包含10月23日开始点之后、10月24日整天、10月25日结束秒内的记录。**禁止每天重复套用16:23:55—12:23:20，禁止只查起始日或只改变显示文案。**

按秒包含结束端：实现可等价使用 `loggedAt >= startAt` 且 `loggedAt < endAt + 1秒`。

| 记录的北京时间                       | 预期         |
| ------------------------------------ | ------------ |
| `2026-10-23 16:23:54.999`            | 排除         |
| `2026-10-23 16:23:55.000`            | 包含         |
| `2026-10-24 00:00:00.000` 至当天结束 | 全部位于区间 |
| `2026-10-25 12:23:20.999`            | 包含         |
| `2026-10-25 12:23:21.000`            | 排除         |

显示、请求、候选、排序及边界均使用同一北京时间语义，不能随操作者电脑时区偏移。无可确认原始时间的记录按既有解析规则明确处理，不能拿采集／上传时间冒充精确日志时间混入区间。

## 6. 日志原文阅读与采集状态

### 6.1 原文与选择

- 采用连续原文列表／表格，保留时间戳、账号、正文、原始缩进、多行XML、空片段及异常格式提示；不增加一行一张卡片或逐行操作列。
- 主列表左侧序号为当前列表位置，不伪装成源文件行号；真正来源行号在上下文和来源浮层查看。
- 默认自动换行；关闭后只在正文容器内部横向滚动，禁止整页横向溢出。按钮和工具栏不随正文横移。
- 点击记录浅蓝选中，随后可复制和打开上下文；未选中时相应操作禁用。选中文本和复制不得被行点击吞掉。
- 已应用关键词在原文与上下文中高亮，但复制仍是未加标记的原始文本；日志只作为文本渲染，不执行HTML／脚本。
- 异常解析／编码状态如实提示，原始字节查看能力保留，不能为清爽而丢弃异常记录。

### 6.2 阅读工具与追加

- 工具区保留“自动换行、专注阅读、复制选中、详情与上下文、刷新”，统一轻量图标按钮；手机可缩短为“专注、复制、上下文”或有可访问名称的图标。
- 复制保留原文换行和缩进，反馈成功／失败。复用项目现有剪贴板兼容／降级，不用复制渲染后的HTML或带行号拼接文本。
- 到底后自动追加，同时保留可见“加载更多／重试”入口；同一分页链串行读取。追加失败保留已加载日志。
- 显示“已加载N个片段”“下滑自动加载／已到当前结果末尾”，N来自已加载条目；接口无总数时不得编造总数。
- 仅按稳定日志ID合并重试重复项，不按正文去重；相同文字的不同真实记录必须保留。切换已应用条件、资源或重新查询后清空旧分页链。
- 阅读面板尽量利用当前窗口剩余高度，正文独立纵向滚动；窄屏和矮屏保证工具栏、错误反馈、加载按钮和末尾内容可达。

### 6.3 采集提示与错误

- 采集提示默认一行，例如“已扫描 · 待上传0个片段”，右侧提供采集详情。展开后显示既有扫描时间、文件数量、读取／总字节、异常、本地现存日期、过期未传等信息。
- “待上传0”不代表整天日志完整；断流、补传、缺文件、未发现本地文件和无查询结果分别表达，不能都显示“正常”。
- 保留加载、空结果、未选实例、接口错误、追加错误、状态读取失败及原地重试。空结果提示核对条件与采集状态，不把无结果解释为业务没有发生。

## 7. 详情与上下文（正文优先）

### 7.1 抽屉布局

**严格参照第14节新版通栏抽屉，以及用户提供的线上排版。** 不使用元数据摘要卡、单独“选中原文”卡和重复“上下文”小标题。

- 右侧抽屉宽约 `min(81vw, 1640px)`；900px以下全屏。高度 `100dvh`，到顶到底，无外部12px留白、大圆角或固定底部大操作栏。
- 标题栏桌面约48px：“日志详情与上下文”＋信息按钮；右侧仅定位选中、复制原文、关闭。
- 下方一行“该账号上下文／整个实例上下文”，自动换行位于右侧；再保留一行轻提示“上下滑动继续查看 · 选中日志以浅蓝色标记”。
- 正文是 `flex: 1; min-height: 0; overflow: auto` 的独立视窗，延伸到屏幕底部。1440×900正文从约117px开始，高约783px；1265×712约595px；390×844约720px。验收正常状态至少约80%窗口高度给日志视窗，不能再到屏幕中段才开始正文。
- 正文使用白底、等宽原文、原始文件行号、轻量细滚动条；选中日志浅蓝底和细蓝侧标记。多行正文保持原样，不把一条XML截成摘要。

### 7.2 范围、锚点与加载

- 从选中日志进入；已识别账号时默认“该账号上下文”，未识别时默认“整个实例上下文”且禁用账号模式。
- 该账号模式：选中记录所属服务器、实例与账号；实例模式包含同服务器／实例中的其他账号及未识别记录。
- 范围以选中锚点及正式上下文接口既有日期规则为准，不把主列表关键词或账号筛选再次套用到实例上下文；不能通过切换范围换成别的服务器或丢失锚点。
- 首次读取后选中记录尽量在视窗中部；切换范围仍保留同一锚点并重新定位。“定位选中”只滚动到该记录，不重新查询、不跳走主页面。
- 向上／向下滚动到边缘继续加载，保留可点击加载入口；根据真实 `hasMore` 状态显示开始／末尾。原始行号允许因跨文件而重号，不因此去重。
- 按稳定ID合并，无重复、无漏项，保持服务端稳定顺序；向前追加后固定用户原可见记录的位置，不跳回顶部或锚点；向后追加不自动拉走正在看的位置。
- 追加中保留现有正文，避免并发重复；失败在阅读区反馈且可重试当前方向，不能清空已读数据。快速切换范围或关闭时取消／忽略旧响应。
- 上下文按真实服务既有规则决定是否跨午夜；主筛选允许跨日不等于擅自扩大上下文日期边界。实现时以最新服务核对保留线上已有跨文件／跨日表现，若存在契约不一致需明确记录，不能伪造“已经全部加载”。

### 7.3 来源与辅助信息

- 标题旁信息按钮按需展开小浮层，显示日志时间、账号、来源文件、原始行号／片段号、文件版本，以及必要格式说明；有异常原始字节时继续提供Base64查看。
- 信息默认收起，展开覆盖局部而不推开正文，不改变正文视窗高度。关闭来源浮层不关闭整个详情；Esc优先关闭最上层浮层。
- 复制直接复制选中日志完整原文，不再重复展示一整块选中原文；小成功提示不能撑成大段占位。
- 关闭抽屉恢复主列表原筛选、选中、滚动位置和触发按钮焦点；支持关闭按钮、遮罩、Esc。背景锁定滚动，Tab／Shift+Tab停留在当前弹层。
- 手机标题操作可只留图标，但定位、复制、关闭仍可用且点击区域至少44px；不要为了放按钮把正文挤到半屏以下。

## 8. 专注阅读

- 从主日志工具栏一键进入全屏阅读，保留已应用资源／范围、已加载条目、选中、换行和追加能力，不另起一套查询。
- 保留退出、复制、详情与上下文等必要操作；退出或Esc恢复主页面原滚动和焦点。
- 在专注模式打开详情后，Esc先关闭详情／来源最上层，再处理专注退出；禁止一次Esc连关两层。
- 手机同样能退出，不能出现浮层后的页面仍被锁滚动或无法操作。

## 9. 标签管理

- 仅具有既有 `monitor.manage` 权限的用户显示入口；仅日志读取权限可查看已有标签，不能保存。服务端继续校验权限。
- 使用专属轻量表格弹窗，显示服务器／实例、名称与状态、标签输入、保存、清空及行内反馈；不移成新的页面，不扩大共享系统设置UI改动。
- 服务器自然编号排序与筛选一致；实例保持正确服务器关联，不能以相同本地实例编号跨服务器串改。
- 标签至多100字符、单行，保存及清空沿用既有校验与正式接口。逐行保存，不把关闭弹窗当作全量保存。
- 保存成功后选项标签和选中摘要立即一致，重新读取仍一致；失败保留草稿。并发版本冲突保留输入，重新读取最新版本后由用户确认再保存，禁止静默覆盖。
- 窗口关闭和重新打开的未保存草稿处理沿用既有行为，不误报保存成功。手机采用全屏／可滚动表格，当前行输入、保存／清空可达，按钮不逐字换行。
- 设备凭证、真实敏感路径和日志内容不得因UI整理新增到标签接口、前端控制台或截图中。

## 10. 真实接口适配与实现边界

### 10.1 当前证据与差距

2026-11-01正式开发补充核对：最新`origin/main f16ca0ac`已具备`startAt/endAt`连续范围与90天跨日双向上下文；下文“整理时”的旧副本证据不代表该主线或当前生产。本轮保留既有能力，按本需求补原始时间精确口径与同秒级区间账号候选，验证边界见[实施记录](../archive/2026-11/2026-11-01-日志查询UI实现与验收.md)。

预览仅在 `.taste-skill/log-query-ui/source` 前端副本、`fixture.cjs` 合成数据及5194本机服务运行。预览的 `endDate`、分页量24、固定日期、模拟错误关键词、模拟账号、自动打开详情参数和内存标签保存**不是正式业务契约，不得照搬上线**。

整理时核对本地 `src/services/monitorLogService.js`：列表 `filters()`仍含 `business_date=:date`，起止时刻均拼接同一个 `date`；`context()`本地源码校验仅有 `scope`。而[既有日志API使用指南](../deployment/AOS日志API使用指南.md)已记载上下文 `limit/direction/cursor`。这证明本地源码、文档与真实部署可能存在版本差异，**本文件未验证当前生产接口实现**。

开发先核对最新目标分支及有效[API契约](../design/API设计.md)、[日志说明](../design/服务器监控.md)、[既有日志API指南](../deployment/AOS日志API使用指南.md)，列出差距后实现，不宣称线上能力缺失或重复开发已经存在的能力。

### 10.2 必须落实的结果

1. 列表在真实接口上使用一个连续秒级时间区间，候选账号与其范围一致；前后端校验、时区及结束秒口径一致。
2. 旧单日调用、现有资源／账号／关键词／未识别条件继续兼容。接口参数采用目标分支已有效契约；若需新增跨日字段，先更新API文档再实现，不把mock的 `endDate`视为既定外部字段。
3. 查询游标绑定完整已应用条件，包括资源、区间、账号和关键词；换条件不能复用旧游标。排序与分页边界跨日一致，账号候选分页也需重新绑定范围。
4. 上下文初次读取与双向追加使用真实稳定ID及真实分页状态；若正式接口尚不支持，做范围内必要只读适配，并更新契约和测试。不可从主列表已经加载的一小段伪造完整上下文。
5. 保留认证、读取权限与标签管理权限；不新增敏感数据暴露，不改日志采集、存储结构、保留期或通知。
6. 沿用既有有界分页和索引／分块查询路径，不为UI加载全量90天原文到浏览器，不增加无界总数查询；大数据性能需独立验证，不能用几十条mock证明。
7. 未完成真实适配或验证时明确标记未完成；视觉完成、mock通过、接口通过和真实业务验收分别报告。

[现有测试指南](../testing/测试与验收指南.md)中的历史筛选布局（例如文档流展开、五项等宽／窄桌面横滚）不覆盖本次已确认的**独立日志查询路由**新布局。正式实现时按本需求更新该路由对应用例；服务器监控页嵌入区域和其他页面仍保留其既有规则，业务及安全契约不因视觉变更放宽。

## 11. 样式隔离、响应式与可访问性

- 使用日志查询专属根类、CSS Modules或显式组件变体；禁止无条件改写 `body`、`:root`、全局 `.btn/.input/table/pre`、共享弹层和字体加载。
- 允许共享底层修复时必须证明其他调用方外观与行为不变；`Layout`、路由外壳和共享菜单没有本次视觉改造授权。
- 检查1440×900、1265×712、768×900、390×844以及375px手机；浏览器100%缩放，不以改缩放比例验收。主页面、日期面板和上下文都要在短屏检查。
- 页面无横向溢出；原文不换行时只在正文容器滚动，浮层限宽限高；手机键盘打开后输入和确认可达。
- 鼠标聚焦不出现粗重双框；键盘 `focus-visible`清楚可见，不能全局 `outline:none`。下拉、日历、信息、复制和关闭均可键盘操作且有可访问名称。
- 弹层正确声明模态／非模态语义，限制焦点、恢复触发焦点及滚动锁；覆盖层关闭顺序正确，重复打开关闭不遗留监听或锁定。
- 加载、空数据、失败、禁用、保存中、并发冲突和已到末尾均有明确状态，不只交付数据齐全时的截图。

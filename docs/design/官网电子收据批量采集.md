# 官网电子收据批量采集

> 状态：2026-10-08 用户批准实现，服务器 CLI 已部署并完成有界验证；2 笔订单新增 4 条设备 SN，长期批量成功率未验收
>
> 范围：服务器批量读取已取货订单电子收据，校验后自动绑定订单设备，冲突转人工；不自动入库或改变取货／结款状态。
>
> 前置证据：[研究方案](../planning/官网电子收据采集研究方案.md)和[首次小样本验证](../archive/2026-10/2026-10-08-官网电子收据采集研究与小样本验证.md)。

## 运行入口与边界

提供独立服务器 CLI，使用明确的订单 ID 清单和操作者，冻结批次范围。支持运行、状态、停止、恢复与导出；成功结果自动回写订单设备。默认两个订单并发，同一 AppleID 串行排队，全部采集与重试共用现有 PostgreSQL 全局许可、账号锁及历史冷却。每单每批最多三次完整尝试，滚动 24 小时的既有次数保护保持。一次完整尝试包括详情、认证和收据，不再将收据阶段重复算作一次登录尝试；旧历史不重置。

本能力不恢复旧官网队列，不修改前端 API、原订单状态或日期。业务库沿用现有表和绑定规则，不通过 `sync/alter` 改结构。采集器和只读解析器不持有业务库写权限；生产应用进程中的独立绑定入口执行最终事务。依赖缺失或生产接口形状不符时拒绝写入。

## 采集与证据

访客 HTTP 详情必须核对订单身份，再使用本次 `orderDetail.d.signInURL` 登录。浏览器执行官方 AppleID 认证，HTTP 会话承接已验证商城登录与详情入口；电子收据使用同一浏览器上下文的原生传输。

在已有 CDP 网络拦截的订单详情页点击官网原链接；链接 target 及仅针对该精确 URL 的 window.open 显示目标固定为当前受控页。上下文守卫拒绝其他未受控新窗口，备用受控页面必须预建为空白页并等待拦截就绪。该请求及其重定向均执行目的地址、停止状态和 PostgreSQL 请求许可检查；禁止采用首次试验中未受控的新窗口导航。收据阶段只允许已校验的收据 URL，错误页、登录页或其他导航均拒绝。必须存在收据请求许可、非缓存 200 原文、完整响应 SHA-256 和前后相同代理出口，才可独立解析并进入绑定。

每次尝试保留独立输入、代理摘要、Gate run、加密详情／收据和结构化结果。账号、密码、Cookie、原始访问 URL 与代理认证不出现在普通日志或 Git。HTTP 541 更换出口；代理失败有限重试；IPRoyal 可根据既有私密认证配置自动分配新的粘性会话，禁止通过重置 Gate 历史恢复额度。验证码／双重认证／协议确认／凭据冲突转人工，不自动提交。

## 批次持久化与恢复

批次使用私密目录、独占宿主锁和原子落盘状态；同一批次只允许一个调度器，账号之间由共享数据库锁协调。调度器持续补位，不恢复逐订单固定等待。状态包括排队、运行、等待重试、待绑定、绑定中、成功、待人工、失败和停止。

每次执行前先持久化尝试意图；停止后不领取新任务，进行中的请求读取停止标记。进程崩溃不清除历史次数、账号冷却或原证据。恢复时采集中的不确定尝试保留为中断；绑定中的不确定提交先只读对账，不能直接重放写入。已有成功条目再次运行应跳过，不重复登录、绑定或审计。

## 原子设备绑定

1. 独立验证器重新解密和解析收据，核对详情订单号、商品总数量、显式 SN、重复 SN、来源摘要、请求许可与出口证据。
2. 生产入口重新核对操作者有效权限、订单身份、已取货范围及采集时业务快照。
3. 按现有库存全局锁与订单锁顺序，在一个事务内读取全部已有设备和涉及 SN；存在其他订单归属、已有设备不属于该收据、库存来源文字或快照变化时转人工，不覆盖或删改。
4. 同单同 SN 幂等；缺少的设备按现有 `legacy_binding` 规则关联设备档案，仅创建“已登记”档案，不创建入库、销售、退款或资金流水。所有设备、取货版本、来源审计在同一事务中提交，任一项失败整单回滚。
5. 回写前先持久化提交意图；事务事件保存批次／尝试及收据摘要，提交后独立回读。连接断开或超时属于提交结果未知，先对照事件与设备集合核验；冲突进入人工清单。

操作入口与配置见[批处理运维](../deployment/官网电子收据批处理运维.md)。

## 验收

- 单元测试覆盖输入、身份、解析、保护、并发、停止、有限重试、断点恢复及结果未知。
- 真实隔离浏览器覆盖收据首请求、重定向、资源、预算耗尽和取消，验证请求许可无漏计／重复计数。
- 真实隔离数据库覆盖整单原子回滚、重复绑定、跨订单 SN 冲突、操作者／快照变化和断连后只读对账。
- 新制品先少量新鲜采集，核验许可和正文；再执行预先固定的多账号批次，完整保留失败、重试、耗时、出口和资源证据。部分失败必须正确落入可恢复或待人工状态，不能以详情成功替代收据／绑定成功。
- 生产验收区分采集通过、绑定通过、独立回读通过和长期稳定性；失败和人工清单不能从分母移除。

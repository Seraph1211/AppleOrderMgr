### 工作路径

1. 无可复用会话时，从 `https://www.apple.com.cn/shop/goto/account` 进入账户中心；等待官方页面后台 Cookie 生成，在真实 IDMS 表单登录。仅 Cookie 存在或登录 HTTP 200 都不算订单成功。
2. 从官网提供的账户页进入订单列表，精确寻找目标订单，再跟随对应详情入口。列表只有商品短名时，不能当作完整规格交付。
3. 列表没有目标订单时，打开系统原有官方查单链接。访客订单可以不出现在账号列表中；工具不会执行“关联订单”或修改账号。
4. 已有服务器会话时，优先通过原始查单链接读取详情。会话到期或官网要求重新登录时，按账号冷却规则处理登录。持久会话按账号加密绑定，最长六小时，不延长原会话创建时间冒充更新。
5. 只接受官网 `orderDetail` 中完全匹配的订单号、完整商品集合、数量及逐项原始状态。`/shop/orderx/guestx/…?_a=fetchOrder` 的 JSON 与 HTML 内 JSON 模型均支持；加载页、空列表、其他订单和缓存响应均不能成功。

账号登录和联系人邮箱是不同字段。入口校验同时支持现有 `/xc/cn/vieworder/订单号/联系邮箱` 与 `/shop/order/list/订单号/联系邮箱`，不会把 Apple ID 自动当成联系邮箱。

凭据读取以订单账号为准：关联账号或同名账号唯一匹配时读取账号主表，并校验已有订单密码快照；订单未关联且账号主表没有匹配时读取订单已有的加密密码快照。引用冲突、重复账号、异常账号、解密失败或主表与快照密码不一致均停止，不通过回退掩盖冲突。此路径不新增账号、不更改关联或密码。

### 资源、预算与失败处理

2026-10-03 全量人工批次另有一次性监护 `apple-official-bulk-guard-20261003.service`。它只读检查该批次，在出口／限流异常、多个账号验证失败、连续失败或磁盘不足时优雅停止官网队列，保留待处理任务；不会自动恢复或重复提交。具体批次、状态文件和操作边界见全量执行与风险记录（实现工作树资料：`docs/archive/2026-10/2026-10-03-全量官网状态更新与账号风险评估.md`）。这不是定时全库刷新，也不等同于已实现账号每日登录预算。

- 单次一个浏览器，宿主机文件锁与 PostgreSQL 账号锁阻止重入；无后台定时查询。现有国内网帆套餐作为出口，不依赖本机 VPN，不新增采购。
- 独立工具默认每次最多 200 个请求，生产手动窗口为 300；均限 180 秒，外层守护 190 秒；所有官网 HTTP 请求、重定向、iframe 及 Worker 子请求统一取得 PostgreSQL 许可，210–229ms 间隔，对应不超过初始 5 RPS。取消和失败不退预算。
- 同一订单在交付工具内 24 小时最多三次运行；一次运行最多提交一次密码，同账号提交后至少冷却 30 分钟。研究阶段的其他尝试独立保留，不能将工具台账当作研究首次成功率。
- 429 至少冷却 30 分钟，并遵守更长的 `Retry-After`；541、代理鉴权或连接失败暂停当前出口。工具不连续自动重放失败请求。更换已授权国内出口仍沿用数据库原计数；没有有效备用时保留失败。
- 密码拒绝、双重认证或其他人工验证暂停账号 24 小时；不猜密码、不解锁、不替用户回答安全问题。
- 可用内存低于 1.5 GiB、宿主机 CPU 连续一分钟超过 85%、现有 API 连续三次不健康或超时时，守护程序停止该采集容器。浏览器上限 1 CPU／1 GiB，专用数据库上限 0.25 CPU／256 MiB。

历史研究与独立交付阶段累计硬上限为 `1470`，该阶段结束已用 `1223`。本轮上线沿用旧计数，生产有限累计上限为 `201470`。计数不会因重启、换出口、失败或迁移而归零。后续操作者需要新的有限请求窗口时，可在服务器 `private/collectorConfig.json`（`0600`）显式配置更高的**累计上限**，保持数据库旧计数；可选 `proxyFile` 仅接受 `private/` 内的文件名。未配置时使用 `maxTotalRequests=1470` 和 `fan-1.json`。更换文件不等于代理可用，须保留验证记录。

常见退出：`REQUEST_BUDGET` 为预算耗尽，`ORDER_ATTEMPT_LIMIT` 为单日次数已满，`ACCOUNT_BUSY`／`COLLECTOR_BUSY` 为正在执行，`*_COOLDOWN` 为持久化暂停，`AUTH_REJECTED`／`HUMAN_VERIFICATION_REQUIRED` 为账号问题，`NO_VALID_ORDER_DATA` 为未得到完整详情。冷登录加访客详情可能在 200 请求内无法完成；如果该次已经保存有效服务器会话，下一次有预算的手动命令可复用，不需要电脑登录。不得把这类中间状态称为成功。

输入阶段失败直接展示具体原因：`ORDER_CREDENTIALS_MISSING` 为订单或账号缺少密码，`ACCOUNT_REFERENCE_CONFLICT` 为关联冲突，`CREDENTIAL_SNAPSHOT_MISMATCH` 为两处密码不一致，`ORDER_INPUT_READ_FAILED` 为读取异常。固定错误码从标准错误透传，不展示原始日志；失败立即删除未完成的临时输入，不启动浏览器。历史任务保留原有错误码，新版本不重写旧审计记录。

HTTP 访客采样在代理探测前先只读取得单个冻结目标的当前链接和账号摘要，校验订单 ID、订单号、官方链接和输入时效，再由 `preflightGate.js --http ID` 通过研究库 `BEGIN READ ONLY`、8 秒语句超时查询当前账号的 account pause 与订单哈希对应的 24 小时尝试数。忽略仅用于密码提交的 login pause，不通过历史 sample_id 或旧账号尝试推断当前身份。命中账号冷却或滚动 24 小时十次限制时沿用 `ACCOUNT_COOLDOWN`／`ORDER_ATTEMPT_LIMIT`，保存明确的 `preflightOnly=true` 审计和计划／输入摘要；不探测代理、不请求 Apple、不新建研究 run／attempt、不改预算或冷却，也不记出口验证成功。预检查询或身份验证异常停止，不伪装暂缓。预检通过仅表示继续原流程；实际采集仍由原 Gate 再检查账号锁、冷却、次数、代理与预算，消除检查后状态变化带来的绕过。旧采样审计保持兼容，新预检审计必须严格证明零采集状态，不能用于官网回写。

浏览器收据批处理只顺序处理原冻结范围中缺 SN 的订单：已有本轮 HTTP `APPLIED` 时必须携带原 basis 与来源审计；没有该链时仅接受原计划 `dateMissing=false`、`serialsMissing=true`，且采样前只读核验原行、实际日期和设备快照未变。共用批次锁，跨模式检查 HTTP 未决／隔离与浏览器写入意图；已确认绑定跳过，未知或部分写入禁止重放。默认仅采集并只读核验，正式绑定须显式 `--apply`，不自动换代理、不重试登录。`DEFERRED` 只说明本轮暂缓，不表示字段补齐。

浏览器单样本在共享 sample 锁内先取得无密码输入，并使用 `preflightGate.js --browser ID` 查询当前账号的 account／login 暂停及同订单哈希的滚动 24 小时次数。详情和收据各占一次，因此新策略仅 `attempts<=8` 才继续探测；不足两次额度明确为 `RECEIPT_ATTEMPT_LIMIT`。预检允许后才读取密码，要求凭据账号 SHA256 与前置输入相同；实际 Gate 仍逐运行检查。暂停返回严格零探测、零 run、零研究写入审计；数据库、超时、身份异常停止批次，不能归为暂缓。每个目标开始与结果先持久留痕；中断／收据未验证／未知绑定保留未决，跨重启不得自动重做。此扩展的部署和生产验收状态以开发进度为准。

宿主入口为 `python3 runBrowserBatch.py --root ROOT --proxy-index INDEX [--ids ID,ID] [--limit N] [--apply]`，默认每轮 1 单、最多 20 单，固定原生浏览器模式和所选代理。默认演练仍会采集详情及收据并消耗官网次数，只是不写业务库；同计划随后 `--apply` 复用原演练审计而不重新采样，仍须由原核验器通过五分钟有效期和完整来源校验，过期停止，不刷新时间。已暂缓目标在同计划两模式中跳过，不将其标为业务完成；恢复此类目标需另行审查操作范围，不能删除记录绕过保护。HTTP 隔离目标在默认列表中排除，显式传入也拒绝。`BROWSER_BATCH_PASS_FINISHED` 仅代表本轮有界处理结束，`allFieldsComplete` 始终为 false。

长只读快照及收据核验期间仍可能收到 STOP 或新增未知回写意图。因此批次在快照返回后和每次子进程前重查原计划字节、STOP、清理阻断、HTTP 来源链与全局未知意图；收据绑定包装器还需在自身异步核验后、意图持久化前和 binder 调用前重复检查。全局意图必须严格解析，重复 JSON 键和 NaN 等非有限值均拒绝，不能以最后一个同名键掩盖未知状态。只允许精确匹配本调用刚写入的 `APPLY_STARTED` 通过自身意图检查，其他目标未知写也阻断。意图已保存而 binder 尚未启动时收到停止，保留意图待对账；binder 已启动的未知结果不能通过强杀、假定回滚或自动重试解除。

本批次浏览器采样默认使用 HTTP 登录页与 Shld 前置读取，再交给官方浏览器脚本认证；增加显式 `--native-browser` 对照模式，由原生浏览器从既有账户入口处理官方页面及 Shld，不导入 HTTP Cookie。两种采样模式均设置 `persistSessions=false`，禁止读取或保存磁盘会话，只允许当前进程上下文取数；旧产品调用默认行为保持兼容。模式写入审计，不改变账号锁、次数、登录冷却、STOP、实际出口、租约、预算和收据双运行号核验。完成前置读取、跳过 HTTP 引导或认证接口返回 200 均不代表订单及收据成功；不同账号、出口的对照不能单独证明 541 的根因。

收据阶段的 `RECEIPT_SESSION_REDIRECT` 仅表示出现了不同于详情中原始收据 URL 的文档请求，不能据此推断登录失效。为调查实际原因，有限记录浏览器报告的重定向来源、状态、Location 和被拦截目标；完整 URL 与敏感响应头只写入加密证据，普通日志仅保留脱敏摘要。诊断不放行新地址，不追加网络请求，不改变收据身份与来源校验。重定向及其他停止原因优先于迟到的成功响应，失败不得被迟到正文改写为成功。

同浏览器读取收据时，导航 Referer 只能使用当前页与本次详情响应 `urlHash` 精确一致、同官方主机且包含目标订单号的详情 URL。身份不符则停止，不从日志模板或其他订单构造来源。真实样本已观察到无 Referer 的收据 GET 被 303 转至 `/shop/order/sorry`；补充已核验 Referer 仅是有界行为验证，不代表已确认根因，不允许跟随错误页或放宽收据取数条件。

仅在收据采样模式中，首个有效详情可冻结为不可替换的候选，由主采集循环等待当前页面的实际收据链接渲染：最多 6 秒，且不得超出原总时限、租约、次数和请求预算；采用 DOM 条件等待，不增加固定逐单休眠。观察仅接受与该详情 invoiceUrl 完全一致的链接，把有限链接属性加密保存，不点击链接、不修改发票。超时独立记录，不能宣称页面已完成加载；STOP、风控、预算或来源地址漂移始终优先，不能在等待结束后被改写成成功。其他模式维持原行为。

批处理对账仅允许显式关闭已证明未启动采集的代理前置探测失败：同一待决 attempt 只有开始与 `probe-before` 失败记录、无运行号及容器启动、业务写入为零，且原私密审计、冻结范围和两种模式日志一致，目标不存在回写意图。对账在共享锁内追加独立事件与原审计摘要，保留原记录，不把订单标记完成；后续重新处理使用新 attempt，原限额和冷却不变。已启动采集、应用失败或提交结果未知不适用这一恢复入口。

已知只读网络失败允许同轮换代理重试：仅接受完整私密采样审计、正整数研究run、零业务写入、严格已移除容器、相符的时间与出口形状；稳定出口的HTTP_TIMEOUT/PROXY_CONNECTION_FAILED/REDIRECT_LIMIT，或这些终态、HTTP541、完整只读详情之后出口未通过的样本可重试。新结果必须使用新采样标识和代理索引，并由原Gate计入滚动24小时最多10次；同轮最多3个实际run，全局5 RPS及15分钟账号暂停保持。失败原文、未验证结果、拒用出口和旧记录均保留，失败样本永不进入apply。达到同轮上限只记录带明确失败标志的结束，仍属未完成目标；这与字段补齐不同。仅审计形状完整且采样容器确已清理才适用；未知进程、异常输出、清理失败和任何未知写入仍停止并对账。成功样本仍须原密文及事务核验，不因前次失败而放宽。

已关闭失败记录的历史回放与新关闭操作分别核验：新关闭仍要求当前无目标成功制品或回写意图；历史回放使用原关闭时间、原证明和原密文摘要，不把随后新的采样结果误认为旧尝试曾成功。历史回放仍重验原文件字节、失败请求链、出口拒用和原容器清理，原未验证出口永不升级。重新采样刷新输入前，必须按旧关闭事件绑定的摘要封存原输入精确字节；缺失或摘要不符则拒绝覆盖。历史回放优先读取该封存输入，并以原相对路径摘要与旧事件比较，新输入用于新采样。全局未知写入继续阻断；普通批次仍跳过隔离目标，恢复采集必须使用明确选定目标的独立操作，沿用持久Gate与原限额，不删除日志或重置计数。

对于 HTTP 541、`HTTP_TIMEOUT` 或第三个 GET 的 `PROXY_CONNECTION_FAILED` 后出口复查失败的只读采集，另设显式失败隔离对账，不能套用前置失败恢复。允许的窄形状仍为三个 GET、前两条已封存 303、第三次无响应，原审计 `originalOutcome` 必须与已结束的研究 run 原终态精确相同；不能把其他超时或未知成功归入此入口。必须核验原审计、研究运行及唯一尝试记录、只读请求密文、无结果和任何回写意图、冻结订单行与日期及设备绑定未变、容器确已清理、前置出口已列入拒绝集合；证据不完整则维持停止。隔离只追加绑定原审计与新鲜只读核验摘要的事件，允许继续其他订单，该单保持未完成且本批禁止重试；不补造第三次响应或出口验证，不清除次数及冷却。新增 `HTTP_TIMEOUT` 只扩展终态枚举，其余密文、业务未变、时效及出口未知证明不放宽；每个目标使用独立新生成的只读证明。未知成功、写入结果未知和任何业务数据冲突均不能由此解除。

另支持一个与上述条件分开的四次 GET 失败形状：原终态只能是 `PROXY_CONNECTION_FAILED`，前三次响应为 303、303、200，第四次没有响应；全部请求正文为空，前三次无请求头，第四次仅有精确指向第三请求的 Referer。两个 Location 必须等于下一次原请求，第三正文须通过原 GCM、SHA 和事件核验，第四请求必须是该正文提供的同源 `SHIELD_CHALLENGE`，没有 POST 或成功制品。原审计必须缺少 `egressAfterError`，前后实际出口摘要均存在且不同，并都保留在拒用集合。研究终态与请求数、唯一未登录尝试、全部原文和新鲜双库证明仍需匹配；隔离事件额外绑定实际后置出口摘要，回放时重验。不得与旧三次 GET、后置探测失败／空摘要形状混用条件；本分支仅关闭已证明无回写的失败记录，不将变化出口认证为成功，也不允许重试该目标。

同一批次目标在最终出口未知失败前，可以有一至两次已明确结束的普通 `HTTP_541`，包含最终失败在内最多三个 run。每条前置审计必须与日志中的完整原审计严格一致，证明目标身份、独立 run 和 attempt、顺序时间、前后实际出口一致、容器清理完成及零业务写；对应出口必须仍在持久拒绝集合，且目标不得存在成功、收据或回写制品。任何其他前置结果、类型异常、缺失审计、时间重叠、重复身份或未决写入均拒绝隔离。新隔离事件按采样顺序封存前置审计文件名、原文字节 SHA256、run 和 attempt，重放时重新核验全部条件及摘要；历史单样本隔离事件可以没有此前置列表，但多样本事件不可省略或删改。最终失败仍单独通过原密文链与新鲜双库证明，不因前置 HTTP 541 而降低要求，也不将隔离目标标记为完成或允许本计划重试。

浏览器批次另设精确的只读失败隔离入口：仅接受已有 HTTP `APPLIED` 来源链、日志仅留下 `target_started`，其后唯一匹配目标、代理及时间的原生浏览器审计明确为 `EGRESS_CHANGED_OR_UNVERIFIED`／`PROXY_CONNECTION_FAILED`，密码未提交、服务器会话未复用、无收据，且前后实际出口不同并均已持久拒用。该入口只接受研究 run 为已结束的 `collect`／`PROXY_CONNECTION_FAILED`、唯一尝试 `loginAt=null`，及原目录恰含 `state.json`、`events.jsonl`、一个已认证解密的登录页响应正文；state、研究 run 和 permit 事件的请求数必须一致，并处于既有 1–300 上限内。原审计、state、事件及正文 SHA/GCM 必须相互匹配，身份及摘要从原文件和证明取得，不硬编码订单或运行号；出现成功结果、收据或浏览器回写制品一律拒绝。新鲜双库证明须核对当前订单完整行与原 HTTP `afterHash` 一致、设备仍为原 HTTP 回写快照，并绑定 HTTP 原审计和结果文件的原文摘要。

浏览器隔离持有现有 batch／sample／apply 三锁，前后复查 STOP、清理阻断、计划原字节、全局未知写入及两模式未决日志；只向原日志追加绑定全部证据摘要的隔离事件，不伪造 `sample_finished`、收据、登录成功或出口验证。该单仍未完成，在本计划的两种浏览器批次模式中均跳过，显式选择也拒绝；原独立 sampler 不读取批次日志，运维不得直接调用被隔离目标。其他失败、已提交密码、未知写入、缺失或冲突证据继续阻断，不能扩大此入口解释。历史日志格式保持原有语义。

#### HTTP 自循环重定向失败的隔离

HTTP 只读详情入口达到导航上限并返回 `REDIRECT_LIMIT`、随后出口复查失败时，允许独立核验九次 GET 的窄形状：首个原订单链接返回 303 与空正文，其 Location 精确指向允许的访客页；后八次 GET 为同一精确 URL，每次返回 307 且 Location 均精确返回该 URL。九次请求的 headers 均为空、body 均为 null，九个响应、正文密文及事件逐项匹配，后八个正文一致且均不含可用订单详情；不存在第十个请求、POST 或成功结果。不把此分支混入原三 GET 或四 GET 隔离合同。

原审计必须为 `originalOutcome=REDIRECT_LIMIT`、九次请求、后置出口为 null 且 `egressAfterError=RUNTIME_COMMAND_FAILED`，采集容器已移除，前置实际出口仍在持久拒用集合。其余正式隔离条件不变：完整 GCM／SHA／身份与研究 run／唯一 attempt 核验、新鲜双库证明确认原行／实际日期／设备未变、全局无未知写入、无结果／收据／回写意图、原日志追加封存、目标保持失败且禁止本计划重试。不得凭该证据认定页面已成功、出口稳定或继续跟随重定向。

#### 已确认收据失败的只读收尾

浏览器详情成功但收据被官网重定向拒绝时，可以显式封存 `DETAIL_READY_RECEIPT_FAILED`，不将收据或订单标为成功。首版仅接受原生浏览器审计明确为 `RECEIPT_SESSION_REDIRECT`、前后实际出口一致且核验通过、容器已移除、已有 HTTP APPLIED 来源链，以及完整的详情原文、收据 GET／3xx／跳转阻断诊断和两次研究 run／attempt。详情身份、原模型 invoiceUrl、Referer、重定向 Location、被阻断目标、请求数量与时间须从原密文、事件和数据库记录交叉核验，不按固定订单或固定总请求数推断。保留详情成果和原登录记录／冷却，认证行为不等同于零外部副作用；禁止任何收据成功制品或新的绑定意图。

收尾需要五分钟内的只读双库证明：当前业务完整行、实际日期和设备快照必须与旧 HTTP 回写基线精确一致，全局无未知写入、STOP 或清理阻断。历史失败审计缺少 Docker exit／OOM 字段时，不补造正常退出证明；核验结果明确 `processExitVerified=false`，只确认容器已移除、本次无业务回写、失败成果不能用于写入，并允许另行处理其他目标。state／审计矛盾、身份或密文失败、清理未知、未知写入和不满足该阶段证据的情况继续阻断。

正式收尾在三把共享锁内追加独立 `failed_read_only_closed` 事件，封存原审计与核验摘要，`targetCompleted=false`、`apply=null`；不得补造缺失的 `sample_finished`，不得删除原详情或失败文件。两种批次模式均不再采样该目标，显式选择也拒绝。收尾与继续批次是两个操作，既有账号／代理冷却、次数、预算和出口保护仍有效；此入口不重新登录，不清除保护，不恢复失败收据的可写时效。具体发布状态与真实验证见部署说明和当日补录记录。

### 工作路径

1. 无可复用会话时，从 `https://www.apple.com.cn/shop/goto/account` 进入账户中心；等待官方页面后台 Cookie 生成，在真实 IDMS 表单登录。仅 Cookie 存在或登录 HTTP 200 都不算订单成功。
2. 从官网提供的账户页进入订单列表，精确寻找目标订单，再跟随对应详情入口。列表只有商品短名时，不能当作完整规格交付。
3. 列表没有目标订单时，打开系统原有官方查单链接。访客订单可以不出现在账号列表中；工具不会执行“关联订单”或修改账号。
4. 已有服务器会话时，优先通过原始查单链接读取详情。会话到期或官网要求重新登录时，按账号冷却规则处理登录。持久会话按账号加密绑定，最长六小时，不延长原会话创建时间冒充更新。
5. 只接受官网 `orderDetail` 中完全匹配的订单号、完整商品集合、数量及逐项原始状态。`/shop/orderx/guestx/…?_a=fetchOrder` 的 JSON 与 HTML 内 JSON 模型均支持；加载页、空列表、其他订单和缓存响应均不能成功。

账号登录和联系人邮箱是不同字段。入口校验同时支持现有 `/xc/cn/vieworder/订单号/联系邮箱` 与 `/shop/order/list/订单号/联系邮箱`，不会把 Apple ID 自动当成联系邮箱。

凭据读取以订单账号为准：关联账号或同名账号唯一匹配时读取账号主表，并校验已有订单密码快照；订单未关联且账号主表没有匹配时读取订单已有的加密密码快照。引用冲突、重复账号、异常账号、解密失败或主表与快照密码不一致均停止，不通过回退掩盖冲突。此路径不新增账号、不更改关联或密码。

### 资源、预算与失败处理

2026-10-03 全量人工批次另有一次性监护 `apple-official-bulk-guard-20261003.service`。它只读检查该批次，在出口／限流异常、多个账号验证失败、连续失败或磁盘不足时优雅停止官网队列，保留待处理任务；不会自动恢复或重复提交。具体批次、状态文件和操作边界见全量执行与风险记录（实现工作树资料：`docs/archive/2026-10/2026-10-03-全量官网状态更新与账号风险评估.md`）。这不是定时全库刷新，也不等同于已实现账号每日登录预算。

- 单次一个浏览器，宿主机文件锁与 PostgreSQL 账号锁阻止重入；无后台定时查询。现有国内网帆套餐作为出口，不依赖本机 VPN，不新增采购。
- 独立工具默认每次最多 200 个请求，生产手动窗口为 300；均限 180 秒，外层守护 190 秒；所有官网 HTTP 请求、重定向、iframe 及 Worker 子请求统一取得 PostgreSQL 许可，210–229ms 间隔，对应不超过初始 5 RPS。取消和失败不退预算。
- 同一订单在交付工具内 24 小时最多三次运行；一次运行最多提交一次密码，同账号提交后至少冷却 30 分钟。研究阶段的其他尝试独立保留，不能将工具台账当作研究首次成功率。
- 429 至少冷却 30 分钟，并遵守更长的 `Retry-After`；541、代理鉴权或连接失败暂停当前出口。工具不连续自动重放失败请求。更换已授权国内出口仍沿用数据库原计数；没有有效备用时保留失败。
- 密码拒绝、双重认证或其他人工验证暂停账号 24 小时；不猜密码、不解锁、不替用户回答安全问题。
- 可用内存低于 1.5 GiB、宿主机 CPU 连续一分钟超过 85%、现有 API 连续三次不健康或超时时，守护程序停止该采集容器。浏览器上限 1 CPU／1 GiB，专用数据库上限 0.25 CPU／256 MiB。

历史研究与独立交付阶段累计硬上限为 `1470`，该阶段结束已用 `1223`。本轮上线沿用旧计数，生产有限累计上限为 `201470`。计数不会因重启、换出口、失败或迁移而归零。后续操作者需要新的有限请求窗口时，可在服务器 `private/collectorConfig.json`（`0600`）显式配置更高的**累计上限**，保持数据库旧计数；可选 `proxyFile` 仅接受 `private/` 内的文件名。未配置时使用 `maxTotalRequests=1470` 和 `fan-1.json`。更换文件不等于代理可用，须保留验证记录。

常见退出：`REQUEST_BUDGET` 为预算耗尽，`ORDER_ATTEMPT_LIMIT` 为单日次数已满，`ACCOUNT_BUSY`／`COLLECTOR_BUSY` 为正在执行，`*_COOLDOWN` 为持久化暂停，`AUTH_REJECTED`／`HUMAN_VERIFICATION_REQUIRED` 为账号问题，`NO_VALID_ORDER_DATA` 为未得到完整详情。冷登录加访客详情可能在 200 请求内无法完成；如果该次已经保存有效服务器会话，下一次有预算的手动命令可复用，不需要电脑登录。不得把这类中间状态称为成功。

对未返回标准 407 挑战的代理，可在其私密 JSON 中显式加入布尔 `preemptiveAuth: true`。默认关闭；启用后只在容器 `127.0.0.1` 的临时端口接收官方 HTTPS CONNECT，向配置的上游预先发送认证，任务结束销毁全部连接。认证不会进入 Apple TLS 内容，407／429／541 及更长 Retry-After 仍执行原暂停。代码已在服务器验证，未增加持久监听、开放端口或 API 配置入口。

亦优现有套餐的十分钟参数尚不满足稳定固定出口验收，试验结束恢复 `fan-bulk-20261003.json`，保留队列暂停。短效节点不能通过一次提取后无限沿用；当前未实现自动续取、剩余有效期准入或账号稳定出口调度。切换兼容模式不是清空暂停的理由。

输入阶段失败直接展示具体原因：`ORDER_CREDENTIALS_MISSING` 为订单或账号缺少密码，`ACCOUNT_REFERENCE_CONFLICT` 为关联冲突，`CREDENTIAL_SNAPSHOT_MISMATCH` 为两处密码不一致，`ORDER_INPUT_READ_FAILED` 为读取异常。固定错误码从标准错误透传，不展示原始日志；失败立即删除未完成的临时输入，不启动浏览器。历史任务保留原有错误码，新版本不重写旧审计记录。

### 部署构成与数据边界

当前持久目录 `/var/www/apple-order-mgr/shared/official-orders` 包含 `release/` 代码、`deps/` 依赖、`private/` 输入／密钥／加密会话／结果、`evidence/` 加密原文和脱敏台账、`pgdata/` 专用 PostgreSQL。专用库停机复制后在同名容器恢复，旧研究目录 `/var/tmp/apple-account-research-20261003` 及停止的 `apple-account-research-db-backup-20261003` 作为迁移前备份保留。队列设为 systemd 开机启动，数据库设为 unless-stopped；已验证进程重建和持久化迁移，整机重启、凭据更新及长期保留期另行验收。

运行依赖已在服务器就绪：Docker、Python 3.6 队列及 Python 2/3 兼容资源守护、`flock`、Playwright 镜像 `mcr.microsoft.com/playwright@sha256:eff16c30e6f3f4af0a03fa4b706120d5e9b0891c344a27d64559aff5900a4a27`，内含 Node.js 24、Chromium 153 和 Xvfb。Node.js 原生 WebSocket 要求 22+。JS 依赖已从既有研究环境复制到持久目录 `deps/` 并只读挂载；不向生产 API 安装浏览器。宿主队列显式使用 UTF-8 解析子进程及结果，兼容服务器 ASCII 默认 locale。

专用数据库仅允许 `apple-account-research-db/apple_account_research`。显式迁移入口为 `npm run official:migrate -- /research`，SQL 在 `scripts/officialOrder/migrations/001-initialize.sql`；相应 down 文件保留旧 `runs`、`budget` 审计表，不能用于重置预算。运行器本身不建表或 `sync/alter`。

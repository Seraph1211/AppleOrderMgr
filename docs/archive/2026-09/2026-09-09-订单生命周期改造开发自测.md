## 目标与实际范围

按[已批准方案](../../planning/真实订单生命周期与官网数据映射优化方案.md)实施显式生命周期、官网权威数据与来源冲突、准确付款截止、付款任务保护和前端展示。最新决策为未付款／支付待确认的非终态订单每 60 秒自动刷新；官网确认付款后只手动刷新，页面打开不再触发官网访问。

未新增官网状态历史表；不开放商品图片、取货说明、动作 URL 或令牌；不自动更改冲突订单号；不推导实际付款／取货时间。内部任务四态仍由员工维护。配送、退款和退货新语义不在本轮实现范围。

## 关键实现与兼容

- init_data 优先；未知枚举保留原值并提示核对，多商品逐项保存，混合阶段阻止新付款分配；全部终态停止自动刷新。
- 官网有效数量（含 0）、商品、金额、付款方式和门店优先；首次合并前保存非敏感导入来源，重复刷新不消除原始冲突。官网缺失型号保留可唯一匹配的原型号，不使用动态订单项键充当商品身份。
- 金额、币种和准确截止在节点消失、null、解析失败时保留最后有效值，诊断区分 missing/null/invalid/value。
- 截止优先官网 Epoch，回退有时分的官网创建时间加 30 分钟。同步、分配共用事务级锁；网络请求不在事务内。错单保护与分配共用锁，不跨订单覆盖。
- 排队的自动任务执行前重新检查付款资格；跳过不会伪造最后成功时间。page_open API 保留空结果兼容契约。
- 新增 10 个 orders 字段和截止时间索引；up 不无依据回填历史状态。down 会删除本轮来源／官网元数据并把新增状态回退旧枚举，因此仅用于隔离测试，不是默认生产回滚办法。
- 订单列表固定行首叹号，不受列隐藏配置控制；提示支持悬停、聚焦、点击、Escape 和窄屏定位。详情显示原始阶段、观测时间、截止、履约提示和字段差异。
- 仪表板、渠道聚合及订单／邮件人工处理／付款页面筛选兼容新增状态；官网收款只标记付款任务差异，不自动把任务改为完成。

## 可复现命令

普通验证在仓库根目录执行：

```bash
docker compose -f docker-compose.dev.yml exec -T api npm run lint
docker compose -f docker-compose.dev.yml exec -T api npm test -- --runInBand
docker compose -f docker-compose.dev.yml exec -T api npm run docs:check
docker compose -f docker-compose.dev.yml exec -T frontend npm run lint
docker compose -f docker-compose.dev.yml exec -T frontend npx vite build
git diff --check
```

仅在确认不存在同名库后，创建专用可丢弃库。本次命名固定，集成测试有精确名称门禁；测试会清空该库中的合成数据，严禁改为真实库：

```bash
docker compose -f docker-compose.dev.yml exec -T postgres sh -c 'createdb -U "$POSTGRES_USER" apple_order_mgr_lifecycle_test_20260909'
docker compose -f docker-compose.dev.yml run --rm --no-deps -e DB_NAME=apple_order_mgr_lifecycle_test_20260909 -e DB_NAME_TEST=apple_order_mgr_lifecycle_test_20260909 -e DATABASE_URL= migrate
docker compose -f docker-compose.dev.yml exec -T -e DB_NAME=apple_order_mgr_lifecycle_test_20260909 -e DB_NAME_TEST=apple_order_mgr_lifecycle_test_20260909 -e DATABASE_URL= -e RUN_LIFECYCLE_DB_INTEGRATION=true -e RUN_PAYMENT_INTEGRATION=true api npx jest test/officialOrderLifecycle.integration.test.js test/accessControlPayment.integration.test.js --runInBand --coverage=false
```

生命周期集成最后一项执行正式 Migration 的 down/up，并校验兼容数据。CLI 与模型同时覆盖 DB_NAME／DB_NAME_TEST，清空 DATABASE_URL，禁止被旧连接串覆盖。该隔离库没有连接邮件／爬虫 Worker。

浏览器使用系统已安装 Chrome 的临时独立用户目录，启用本机专用调试端口，不连接日常浏览器账号。容器中 Chrome 缺失，因此使用容器 Puppeteer 连接本机的专用 WebSocket：

```bash
docker compose -f docker-compose.dev.yml exec -T -e RUN_LIFECYCLE_BROWSER=true -e LIFECYCLE_BROWSER_WS="$LIFECYCLE_BROWSER_WS" api node scripts/testLifecycleBrowser.js
```

执行前将 LIFECYCLE_BROWSER_WS 设置为新建临时 Chrome 的实际端点；不能沿用旧会话端点。脚本创建独立浏览器上下文，拦截全部 /api/ 请求并拒绝非本地资源，仅访问本地 Vite。截图写入容器 /tmp/lifecycle-order-list.png、/tmp/lifecycle-order-mobile.png、/tmp/lifecycle-order-detail.png；它们是可再生成的临时证据，不提交 Git。

## 失败与复测

- 最初旧状态／零数量测试与新批准规则不符，按新契约改为验证真实结果；未降低身份、事务或权限断言。
- 集成测试初稿误认为任务版本从 1 开始且遗漏幂等键；核对现有模型版本从 0 开始和接口要求后修正测试输入，29 项集成最终通过。
- 修复了新增异步空入口、缩进和测试字段命名导致的 Lint 错误；最终 Lint 退出 0。
- 浏览器容器缺少 Chrome，改用系统临时无账号实例；窄屏脚本等待侧栏 200ms 收起动画完成再点击，避免点中导航层。冲突浮层从滚动即关闭改为锚点重定位，可将鼠标移入阅读。最后一轮浏览器检查通过。
- 窄屏既有分页区域仍有横向溢出／文字挤压；属于原有分页组件布局，本轮未顺手改动。新冲突浮层本身经过可视区域边界断言。

## 未验证与下一步

- 本轮未访问真实 Apple、邮箱、代理、真实付款入口，也未刷新或写入真实订单。新订单最终 PICKED_UP、配送、多商品真实拆分、退款、退货和不同付款方式仍需另行授权验证。
- 浏览器仅为合成 API 的开发自测，不是连接后端的端到端业务验收；员工付款操作、真实数据冲突与所有角色人工流程仍待验收。
- 开发库没有执行本轮 Migration，SequelizeMeta 对新迁移计数为 0；当前代码需要另行授权迁移及运行环境切换后才能用于开发库联调。不要直接启动 Worker 触发未授权外部访问。
- 生产未进行任何操作。生产迁移、备份恢复演练、发布及回滚需要独立授权。
- 旧订单没有首次官网来源快照时，以当前存储值作为首次比较基线；无法重建此前已经丢失的邮件原值。旧状态不批量猜测回填。

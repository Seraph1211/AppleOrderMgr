## 数据模型

渠道来自订单关联的 recipients.tag，不存在独立渠道表。列表以有非空 tag 的订单聚合，因此仅给取机人设置标签不保证渠道立即出现在列表。

## 当前能力

| 接口                          | 说明                                          |
| ----------------------------- | --------------------------------------------- |
| GET /api/channels             | 按订单关联档案 tag 聚合渠道统计                       |
| GET /api/channels/:tag/stats  | 指定标签的状态与取机人统计                    |
| GET /api/channels/:tag/orders | 分页订单，支持 page、pageSize、status、search |
| PUT /api/channels/:tag        | 请求体 newTag，更新取机人标签及授权配置           |

标签作为 URL 路径片段需要编码。读取需要有效登录会话和 channels.read；渠道订单额外要求 orders.read。改名需要 channels.rename 且用户订单范围为全部。

`GET /api/channels/:tag/stats` 的 `completedOrders` 统计 `email_order_status=picked_up` 的邮件推定已取货订单，页面显示“已取货”。该数值不统计人工 `pickup_records.status`，不表示已结款。

## 金额与状态

金额来自 order_amount，按已确认的机型容量单价乘商品数量求和；缺失使用聚合空值处理并返回 missingAmountOrders，amountSource=catalog。页面显示待确认数量及“按官方售价计算”。paidOrders 使用 payment_status=paid；列表中的 deliveredOrders 只统计 picked_up，不再将非法历史 completed 视为已取货，不能误解为仅 delivered 状态。状态统计兼容新 payment_due、payment_received、payment_expired；商品数量使用官网优先的有效值，原导入值保留在来源快照。当前映射币种固定 CNY；已付款、已取货金额是对应状态分组的映射总额，不代表实际收付款。

## 改名规则

控制器拒绝空白或超过100字符的标签、相同名称、没有关联订单的原渠道，以及已有档案或授权的新标签。通过后在同一事务中更新取机人 TAG、用户授权和审计；保留订单来源字段。ordersUpdated 表示实时归类发生变化的订单数，recipientsUpdated 表示修改的档案数。

改名与基础档案写入、付款调度共用事务锁；非空标签保留原文，不修剪、不猜测映射。并发与审计失败回滚需由隔离 PostgreSQL 验收。

## 脱敏与入口

渠道订单返回脱敏手机号，隐藏 Apple 订单链接。实现见[控制器](../../src/controllers/channelController.js)、[页面](../../frontend/src/pages/Channels.jsx)及[订单明细页](../../frontend/src/pages/ChannelOrders.jsx)。验收方法见[渠道管理验收清单](../testing/渠道管理验收清单.md)。

### 下单日期筛选（2026-09-13）

渠道订单明细支持北京时间下单起止日期，按 orders.order_date 过滤；订单列表总数、分页及渠道订单统计采用同一日期条件。取机人数量仍为该渠道关联人数。清空日期恢复全部日期，筛选不扩大渠道和权限范围。

### 用户订单 TAG 范围（2026-09-18）

渠道列表、统计、订单明细都与当前用户 orderAccess 相交，依据关联 recipients.tag 判断。不可见渠道按不存在返回；统计不暴露其他 TAG 的订单。改名在同一事务替换用户授权 TAG、递增权限版本并追加权限审计；目标 TAG 已有订单或用户授权时拒绝。本人付款任务也须与此订单范围相交。

## 订单取机人 TAG 统一契约（2026-10-14）

本轮已实现、验收并生产发布，证据见[统一方案](../planning/订单取机人TAG统一方案.md)。所有来源及历史订单的业务 TAG 唯一读取 `orders.recipient_ref` 关联的 `recipients.tag`，档案修改实时生效。NULL、空串、全空白为缺失；非空值保留原字符串并区分大小写精确匹配。未关联或缺失不回退来源。`orders.tag`、`source_recipient_tag` 及 AOS 快照仅保留原始记录，不覆盖。

订单响应 `recipient_tag`、`tag` 为当前值或 null，新增 `recipient_tag_state`（unlinked／missing／present）；付款对应 `recipientTag` 和 `recipientTagState`。列表、详情、导出、筛选候选、仪表板、渠道聚合和用户 TAG 范围采用相同规则；缺失值不构成真实渠道或授权 TAG。本人付款任务所有权须与当前 TAG 范围相交，不要求额外的 orders.read。

自动分配对所有来源按当前 TAG 匹配规则，候选人也必须具有当前 TAG 范围；缺失只允许全部范围账号接单。无匹配规则沿用普通账号集合，已分配历史任务不自动转派。新企微通知采用当前值，旧投递记录保留。渠道改名仅更新档案 TAG 和授权配置，不改来源快照。修改既有档案 TAG、删除、导入覆盖 TAG、补关联等影响订单范围的操作要求全部范围及原功能权限。

## 商品名称统一（2026-10-15）

渠道订单商品白名单增量提供 displayName 和名称核对状态，完整名称由共享规则映射；历史来源名称仍可在证据中查看，渠道、权限及金额口径不因名称转换改变。参见[已确认实施方案](../planning/全系统商品名称规范化实施方案.md)。

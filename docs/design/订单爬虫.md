### 订单凭据读取与失败分类（2026-10-03 修复授权）

输入始终以订单保存的 Apple ID、订单号和原始链接确定身份。账号主表无匹配且 `apple_id_ref` 为空时，允许使用订单加密密码快照，不要求先补录账号。账号匹配按去除首尾空格及忽略大小写进行；已有唯一主表记录时沿用主表密码，并在存在订单密码快照时校验两者一致。

非空账号引用必须指向同一账号；多个候选、异常账号、引用冲突、密码缺失、解密失败及快照密码不一致均明确失败，不能静默换账号或使用联系人邮箱。输入阶段只读事务，不修改账号库、订单关联或业务字段。成功输入的凭据来源仅保存在服务器私密文件，不返回管理台。

输入错误通过受控 JSON 错误码传递到宿主队列及前端；仅允许固定错误码，不把原始异常、凭据或链接作为错误文本。输入失败清理本次临时文件、不启动浏览器。旧失败任务保持原审计记录，用户重新提交时执行新逻辑；不自动批量重放。

## 2026-10-03 独立浏览器取数历史

当前另有独立手动工具，输入系统 ID 后只读获取关联账号和原始链接，使用服务器国内代理、Xvfb/Chromium 从账户中心登录；列表缺少目标时再使用既有访客链接。服务器会话加密、账号绑定、有限时效，新进程重新请求官网；不使用用户电脑 Cookie 或网络中继。

`officialOrderParser` 只接受订单号精确匹配、完整商品集合、数量和原始状态；列表短名不冒充详情规格，加载页、空列表、缓存或缺字段不成功。支持 HTML JSON 模型与 `/shop/orderx/guestx/…` 的 `fetchOrder` JSON；未知合法原始状态保留，不推断业务付款或取货阶段。

`officialOrderGate` 在专用 PostgreSQL 持久化 5 RPS 许可、累计预算、单日订单次数及账号／代理冷却；浏览器全部子请求和重定向同样计数。源响应与会话加密，普通路径清除令牌、订单号和联系人。原始取数器只读，结果按次写入私密文件；手动队列验证结果后仅回写官网状态及观测时间，不发通知。

三个样本及新进程复用已真实验证，完整产品可靠性仍待验收。操作和限制见[服务器官网订单取数](../deployment/服务器官网订单取数.md)，后续范围见[重建方案](../planning/服务器端订单链接采集重建方案.md)。本节不恢复下述已退役能力。

### 亦优代理兼容验证（2026-10-04）

用户授权试用现有亦优国内套餐。实测同一出口对未携带代理认证的 CONNECT 返回 502、预先携带正确认证返回 200，浏览器因此无法等到标准 407 挑战。已增加显式 `preemptiveAuth` 兼容模式：仅在采集容器回环地址建立短期 CONNECT 转发器，只向所选代理发送其认证头；Apple 的 TLS 仍由浏览器端到端验证，不解密或注入网页请求。目的域仍限官方 HTTPS 白名单，请求仍经过现有 PostgreSQL 许可，失败不自动换出口或重试登录。

兼容代码已部署到服务器采集器，两个订单三次真实查询通过；默认出口未切换，全量队列继续保护性暂停。十分钟配置下，同一代理的两次成功自有站点请求相隔约三分钟，来源 IP 不同，中间另有 CONNECT 502。有效期不等于出口粘性，不能仅凭该参数恢复批量。短效端点自动更新和访客链接优先仍待实现；证据见[亦优验证记录](../archive/2026-10/2026-10-04-亦优代理验证与全量队列核查.md)。

`officialOrderParser` 只接受订单号精确匹配、完整商品集合、数量和原始状态；列表短名不冒充详情规格，加载页、空列表、缓存或缺字段不成功。支持 HTML JSON 模型与 `/shop/orderx/guestx/…` 的 `fetchOrder` JSON；未知合法原始状态保留，不推断业务付款或取货阶段。

`officialOrderGate` 在专用 PostgreSQL 持久化 5 RPS 许可、累计预算、单日订单次数及账号／代理冷却；浏览器全部子请求和重定向同样计数。源响应与会话加密，普通路径清除令牌、订单号和联系人。原始取数器只读，结果按次写入私密文件；手动队列验证结果后仅回写官网状态及观测时间，不发通知。

三个样本及新进程复用已真实验证，完整产品可靠性仍待验收。操作和限制见[服务器官网订单取数](../deployment/服务器官网订单取数.md)，后续范围见[重建方案](../planning/服务器端订单链接采集重建方案.md)。本节不恢复下述已退役能力。

### 亦优代理兼容验证（2026-10-04）

用户授权试用现有亦优国内套餐。实测同一出口对未携带代理认证的 CONNECT 返回 502、预先携带正确认证返回 200，浏览器因此无法等到标准 407 挑战。已增加显式 `preemptiveAuth` 兼容模式：仅在采集容器回环地址建立短期 CONNECT 转发器，只向所选代理发送其认证头；Apple 的 TLS 仍由浏览器端到端验证，不解密或注入网页请求。目的域仍限官方 HTTPS 白名单，请求仍经过现有 PostgreSQL 许可，失败不自动换出口或重试登录。

兼容代码已部署到服务器采集器，两个订单三次真实查询通过；默认出口未切换，全量队列继续保护性暂停。十分钟配置下，同一代理的两次成功自有站点请求相隔约三分钟，来源 IP 不同，中间另有 CONNECT 502。有效期不等于出口粘性，不能仅凭该参数恢复批量。短效端点自动更新和访客链接优先仍待实现；证据见[亦优验证记录](../archive/2026-10/2026-10-04-亦优代理验证与全量队列核查.md)。

## 当前规则

- 新订单仍由现有邮件或 AOS 入库链路接收，入库事务继续创建付款任务并登记企业微信推送；不再创建官网刷新计划或任务。
- 订单管理恢复原官网状态列并放在订单号后，邮件状态仍保持原口径；渠道、仪表板和付款页面继续使用邮件状态。
- 历史官网已付款、退款或终态证据转换为独立的 `payment_assignment_hold_reason`，即使付款任务完成后重开也继续阻止自动和手工重新分配。
- 历史限制不阻止已有负责人继续执行重开、本人处理、读取付款链接或付款码；界面显示限制提示。
- 单纯超过来源下单时间 30 分钟只阻止自动分配，保留手工交接能力。
- 已退休刷新、代理和系统日志接口返回 HTTP 410 及稳定错误码 `FEATURE_RETIRED`。

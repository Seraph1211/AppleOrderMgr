## 现象与修复

订单列表直接显示 `PAYMENT_DUE_STORED_ORDER` 与 `PAYMENT_RECEIVED`。前后端展示字典缺少这两个已采集的原始状态，未知值按原文回退。

按现有官网生命周期观测与合成样本，分别补齐“待付款”“已付款”。前端列表、详情、筛选共用映射；后端 Excel 导出同义。同义待付款标签沿用琥珀色，已付款使用浅青柠色，与可取货区分。不改官网原值、邮件付款事实、付款任务资格及取货判断。

## 提交与制品范围

代码提交 `b4931622ab0c11c7f9d9a2828690b0ec7411fa60` 已推送 main。隔离 main 工作树只提交两份常量、现有 Excel 回归用例和对应说明／进度，原工作区既有改动未修改。

基于生产 `20261022-payment-cmb` 的 API 与前端 builder 叠加两份常量，发布 ID `20261023-official-payment-labels`。生产 API 与本地基础镜像文件层一致，配置差异仅为旧 Docker 空默认字段；候选365份源码全部匹配预期，其中API只改一份常量。前端203份源码比对仅一份常量改变；保留生产招行24期及其他增量，不用 main 全量源码覆盖现网。

## 生产验收

维护助手首次将多行JSON按末行解析而失败，已产生的106个维护标记保留，未启动API切换。修正整段JSON解析，通过唯一标记补齐恢复清单，再挂起新增25个自动批次。首次106个批次按原先未暂停状态恢复并清除临时原因，后续25个按保存的字段恢复；不声称首次恢复保留了未记录的历史原因文本。最终131个批次全部恢复，维护标记剩余0，无取消任务或中断在途请求的操作。助手、失败日志、恢复策略与清单均保留于发布证据目录。

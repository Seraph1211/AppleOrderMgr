## 配置来源

- [CLI 迁移配置](../../config/config.js)与[模型连接配置](../../src/config/database.js)均读取 `DB_*`。
- 默认数据库名为 `apple_order_mgr`；test 环境的 CLI 使用 `DB_NAME_TEST`，但当前模型连接仍读取 `DB_NAME`。隔离测试必须显式对齐两者，不能只设置 NODE_ENV=test 就认为数据库已隔离。
- PostgreSQL 14+；TLS 使用 `DB_SSL`、`DB_SSL_REJECT_UNAUTHORIZED`。本页不保存实际凭据。

## 新建本地开发库

确认连接的是本地或专用测试实例，先创建与 `.env` 中 `DB_NAME` 一致的数据库，再在仓库根目录执行：

```bash
npm run db:migrate
npm run db:seed:admin
```

首次管理员用户名为 admin，密码通过 `ADMIN_INITIAL_PASSWORD` 注入，首次登录强制改密。不要把全部种子文件作为首次生产初始化的默认步骤。

`npm run db:init` 当前只测试连接并提示执行迁移，不会同步模型或自动创建表。表定义见[数据库架构](数据库架构.md)。

## 存量敏感数据

```bash
# 默认只读盘点
npm run security:migrate
```

加 `-- --execute` 才会写入数据；执行前需要备份、密钥确认、回滚方案和对应数据写入授权。结构迁移成功不能证明存量明文已转换，状态见[敏感资产处置记录](../security/敏感资产处置记录.md)。

## 迁移验证与回滚

仅在可丢弃的隔离库验证 `up → 校验 → down → up`。`npm run db:migrate:undo` 回滚最近迁移；`npm run db:reset` 会回滚全部迁移再重建，不属于日常生产修复命令。

需要检查字段、类型、唯一约束、外键、索引和数据兼容性；模型静态检查不能替代真实 Migration 验证。模型与 Migration 漂移尚未全部通过隔离库核验。

## 备份与恢复要求

发布前对目标数据库和上传目录制作受控备份，记录时间、版本及恢复步骤；备份不得入库。先在隔离环境验证恢复，再制定生产窗口。密钥与密文必须具有配套恢复能力。

生产操作见[部署指南](../deployment/生产环境部署指南.md)，不从旧文档复制服务器地址或数据库口令。

- [产品与接口文档](https://market.aliyun.com/detail/cmapi00037894)。
- [已购服务控制台](https://marketnext.console.aliyun.com/bizlist)。
- 调用地址：`https://zidv2.market.alicloudapi.com/idcheck/Post`。
- 请求方法：`POST`；请求 Body 的必填字段为 `realName`、`cardNo`。
- 支持 AppCode 鉴权；接入时只使用所购服务的已有凭据，由后端加载，禁止进入前端、仓库或日志。已复核请求示例，采用 `application/x-www-form-urlencoded; charset=UTF-8`。
- 文档明确：`error_code=0` 表示请求成功，是否匹配由 `result.isok` 的布尔值决定。HTTP 成功不能直接解释为身份一致。
- 服务商按 HTTP 状态扣次数，核验不一致也可能扣次。接口异常、超时和未知返回不得当成不一致，不进行无条件自动重试。

## 页面及操作

沿用现有浅色蓝色样式和表格组件。页面包含「单人核验」「Excel 批量核验」「核验记录」三个页签，保留核验历史。

1. 单人核验：姓名、身份证号输入框；提交前验证必填、格式、有效日期与校验位；展示一致、不一致或未取得结果及原因。
2. 批量核验：下载只有「姓名」「身份证号」两列的 `.xlsx` 模板，身份证列设置为文本。
3. 上传只做预览：显示原始行号、有效行、空行、格式错误、重复项和预计请求数。数字单元格已发生精度损失、科学计数法或公式证件号必须提示修正，不能猜测恢复。
4. 点击「开始核验」后才调用供应商。相同姓名和身份证组合在同批内只请求一次，各原始行仍保留对应结果；同证件不同姓名不能合并成一次结果。
5. 后台保存批次进度，刷新页面可继续查看；提供停止未开始项目的操作。已发出的请求不能撤回，已完成结果保留。
6. 支持按结果筛选及导出 Excel；按用户批准展示、导出完整姓名、证件号和业务结果。批次结果保留输入行号，便于与原文件对应。
7. 第一版只支持中国大陆 18 位居民身份证，与现有取机人数据规则保持一致；如需港澳台证件，另行确认具体证件类型与接口规则。

## 权限、历史与执行

- 复用现有用户权限目录，不新增角色。管理员默认可用，普通用户单独授权；查看、单人核验、批量核验和导出分动作检查。
- 普通用户只查看本人提交的批次和记录，管理员可查看全部。列表、详情、进度与导出在后端执行相同数据范围检查。
- 保存核验历史，完整身份证及姓名加密保存；页面与导出显示原文，日志不采集身份字段；保存操作人、批次、原始行号、核验时间、结果和供应商流水号，不保存无业务用途的完整原始响应。
- 新增专用批次／明细表和正式 Migration，数据库与 API 契约已先更新，再实现模型、路由和页面。
- 专用核验执行器采用持久化任务、有限并发和速率控制，不复用 Apple 爬虫代理和刷新队列。
- 批次提交使用服务端预览令牌及幂等控制，防止双击或请求重放重复消耗。准备状态可恢复；请求已发出但结果未落库的中断状态标为结果未知，不自动重新计费调用。
- 余额耗尽或凭据错误时停止继续发送，保留尚未执行项目。真实剩余次数以供应商可核实来源为准，不用本地请求数伪装成实时余额。

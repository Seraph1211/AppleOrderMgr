## 故障与回退演练口径

`stockLegacy.integration.test.js` 启动实际 Node 子进程，库存事务写入后、提交前发出确认标记；父进程使用 SIGKILL 终止，随后数据库确认实物、事件和幂等操作均未提交，再以原请求键恢复并只生成一笔。另通过真实事务持有模块锁触发 5 秒等待超时。两项证明数据库事务恢复；主 Agent 的 PG 会话终止与双连接死锁属于另组独立证据。

旧应用兼容验证采用“在新 schema 中按旧应用字段插入 nullable bridge”模拟旧版本写入，随后执行正式 repair 命令核对 UUID/SN/订单/原时间及 registered 状态。没有部署或启动历史应用制品，因此不能声称已完成真实应用降级。模块关闭保留已有库存、资金和审计，仅拒绝新库存业务写入；旧取货接口继续可用。生产发布、备份恢复和应用回退需要对应环境的独立执行记录。

## 修复与边界

- 迁移 CHECK 显式拒绝 NULL 绕过、NaN/Infinity；带业务数据 down 在统一咨询锁下拒绝清表。
- sourceOrderId 可后补；已确认成本不能通过二次注册或历史导入变更规格/拿货日期。成本更正同步销售快照，价格目录调整不改历史。
- 代收人与到账付款人的合法联动纠错在一个事务里完成；先更新事实再重建关联，任一余额不平则整笔回滚。
- 列表先在数据库分页，再只加载目标关联；批量收货结果在可重复读快照内物化，统计采用聚合 SQL，避免逐台重载全部业务表。外部 `internalExport` 参数不能越过 20/50/100 分页限制，内部导出才允许 5000。
- 数据库意外断连返回 `STOCK_CONNECTION_LOST` 503，锁超时/死锁返回 `STOCK_BUSY` 503；16 项分类单测及主 Agent 实际断连验证覆盖，原键重试。
- 幂等同时包含路径目标ID，记录实际用过的权限码；重放重新鉴权并重新做字段投影，不返回旧敏感响应。公开错误不包含 SQL、财务载荷或私有签名 URL。
- 序列号输入、相机拒绝和 OCR 失败界面已有备选；真实包装盒扫码、真实照片识别/计费 OCR、真实 OSS 上传读取、真实客户资金及现场仓库盘点尚未进行。这些不冒充本地合成验收结果。
- 前端日常入口提供付款后状态及到账摘要，移除重复登记入口；在途详情可打开关联转运；期初表单采用明确切换时点；日期控件保留秒；到账重新分配成功后关闭并刷新。以上均由实际 API 浏览器回读验证，异常边界另用明确的浏览器模拟。
- 首期真实退货、换货不在范围。误录更正保留事件、原费用分摊和反转款项记录，不物理删除业务主记录。
- 未提交/推送/部署，未执行生产迁移或真实历史导入。恢复旧应用期间新出现的空桥接可运行 `npm run stock:repair-bridges` 只读盘点，再在有管理员审计身份的显式命令中补齐；生产执行须单独记录。

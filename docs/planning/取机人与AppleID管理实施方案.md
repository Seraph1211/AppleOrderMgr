# 取机人与 Apple ID 管理实施方案

> 状态：本地实现与合成验证完成；真实导入及生产发布待执行
>
> 最近核对：2026-09-17
>
> 基线：main@ec2c1d8；用户在本会话批准按本文编码
>
> 验证范围：已有代码与腾讯文档表头、模板公式样例；未做真实资料全量核对、导入或生产发布

## 目标和边界

完善基础档案、一次性表格导入、当前绑定和历史追溯、名下订单、信息模板导出。首次导入后由系统维护，不持续同步腾讯文档。真实资料差异必须先预览，由用户逐项确认；本轮开发只使用合成数据，不执行真实导入、部署、提交或推送。

## 已确认业务规则

1. 取机人按标准化完整身份证去重，姓名不一致视为冲突。姓、名保留原始分列，兼容复姓；只有姓名时不能自行猜测复姓。
2. 每人只有一个原始 TAG，不拆分城市／负责人，不重新拼接，不允许同时归属多个渠道。
3. 真实联系电话可空，独立于下单手机。下单手机号随机生成合法大陆手机号格式，下单邮箱为该号码加 @vvv8.net；不要求收信、短信或随机地址实际可达。生成只影响档案，不改订单快照。
4. 取机人包含姓名、身份证、TAG、当前账号及密码、真实电话、下单手机号／邮箱／省市区街道、状态、备注和订单数。Apple ID 包含账号、密码、三组密保问答、国家（默认中国）、状态、备注；不保留独立昵称概念。
5. 状态为未使用／使用中／已下架／异常。新建默认未使用；取机人来源“已挂服务器”和“已挂 需下架”映射使用中，“已进表 未挂”映射未使用，不另存来源状态。大陆账号表只读 K 列状态，忽略 J、M；香港账号也只读 K 列状态，地区统一中国。
6. 任一时刻取机人与 Apple ID 双向唯一，允许双方未绑定；历史可多对多。换绑结束旧记录并新建历史记录，初始导入只记观察时间，不伪造历史开始时间。绑定／解绑／换绑不改变使用状态，已占用账号拒绝静默抢占。
7. 订单归属按每张订单实际取机人和账号分别保存。张三用 A、B 下的订单均计入张三；A 下李四的订单不计入张三。换绑不迁移旧订单；只补关联外键，不覆盖历史快照、TAG、付款任务。
8. 表格重复不等于无条件覆盖。空值可补齐，相同值合并；非空差异逐项展示，用户选择保留已有、采用来源或跳过。密码／密保差异不回显明文；数据库在预览后变化则拒绝旧预览，要求重新核对。

## 来源与模板

- 取机人及当前关联：[汇总表](https://docs.qq.com/sheet/DTEtMUEtGSmNGd2JQ?tab=eweuyz)，兼容各城市／渠道工作表。
- 账号：[2026-AppleID](https://docs.qq.com/sheet/DTFFvcVNoR2FkbFFj?tab=l1iul1)，仅两个以“26年AppleID”开头的工作表；不导入 25 年表。
- 取机人 A—N：Apple ID、密码、下单手机号码、Email、省、市、区、街道地址、使用状态、姓、名、身份证号码、TAG、信息导入模板。额外支持真实联系电话、备注。
- 账号列：A 账号、B 密码、C 国家、D/E 第一组问答、F/G 第二组、H/I 第三组、K 状态；大陆 L 备注；香港 L 是公式，不能当备注。
- 空账号允许取机人无绑定；仅账号无密码且库中不存在时列为待补资料，不生成假密码。取机人表自带新账号及密码时，需账号导入和绑定权限才能联合创建。
- 支持标准模板及腾讯文档导出的 xlsx、多文件多工作表，保留文件／工作表／行号用于冲突定位。身份证必须是文本，拒绝已丢精度的数值单元格；不执行源表公式。
- 导出 N 列遵照已核对公式：A/B 账号密码，C 下单手机，J/K 姓名，D 邮箱，E/F/G 省市区，H 街道，L 身份证，M 原始 TAG；连续逗号、WECHAT 和固定配置后缀及结尾占位保持一致。导出包含状态、真实电话、备注并可导回。敏感导出显式授权，普通导出脱敏且不生成可用录入串。

## 实施设计

- 数据层：新增 recipients.real_phone、apple_ids.notes、orders.recipient_id_last4，保留 phone 为下单手机号以兼容 AOS 匹配。迁移复制既有昵称到备注，旧 phone 不猜测为真实电话。新增绑定历史，数据库唯一索引约束当前关系；存量重复先阻断迁移，不自动选一个人。
- 绑定统一走事务和锁；普通编辑携带当前绑定版本用于防止并发覆盖。账号和取机人状态不随绑定变化。批量分配仅处理无绑定取机人、未使用且无绑定的账号。
- 订单关联：保存来源身份证尾号，完整证件＋姓名优先，姓名＋尾号及 AOS 明确联系资料仅在唯一且无冲突时匹配。提供历史未关联订单预览和选中执行；无充分证据保持待关联。
- 页面：表格展示资料、备注、当前绑定、订单数；订单数进入明细，查看绑定历史；完整编辑地址／真实电话／下单资料／备注，指定账号换绑及解绑；账号密保在已有 secrets 权限下查看编辑。
- 导入：预览与执行分离，服务端持有原始数据，客户端只提交会话令牌与冲突选择。事务内重新检查资料版本和唯一绑定；文件内、跨文件及已有档案统一判重。出错不泄露秘密或半批写入。

## 验收条件

1. 重复身份证合并；同名不同身份证不合并；同身份证不同姓名必须确认；复姓正常。
2. 双向唯一约束及并发换绑／分配无双占用，历史可追踪，状态不联动。
3. 张三 A→B、A→李四时，订单统计分别正确；导入后补关联只修改空外键。
4. 真实电话不被生成覆盖，邮箱生成规则唯一为 @vvv8.net，空字段可以清空。
5. 腾讯两个账号工作表按位置正确映射，香港国家转中国，重复表头不误读。
6. 导入差异先确认；令牌不可跨用户／重复使用；预览后资料变化拒绝执行；无权限不能联合写账号／换绑或查看密保。
7. 导出字段可回导，录入串与已核对公式逐字一致，身份证文本、公式注入处理和敏感权限有效。
8. 前后端 lint、相关单元测试、隔离 PostgreSQL 迁移 up/down 和并发测试、前端构建、文档检查；浏览器合成验证与真实业务验收分别记录。

## 入口和数据来源

运行入口为[crawlerService.js](../../src/services/crawlerService.js)，独立调度入口为[crawlerWorker.js](../../src/workers/crawlerWorker.js)。抓取、解析和校验逻辑统一由当前服务维护。

使用 axios 获取 Apple 订单页，通过 cheerio 读取 script 中的订单 JSON，无需执行网页 JavaScript。当前服务提取失败时进入错误和重试流程。

请求仅接受 `https://www.apple.com.cn/xc/cn/vieworder/{订单号}/{Apple ID}` 对应的合法来源与身份；校验协议、主机、端口、路径、用户信息和本地身份，返回结果的订单号也必须匹配。

## 同步流程

1. 加载订单及关联信息，检查订单是否符合刷新条件。
2. 在数据库事务外，经代理访问官网并重试。
3. 从 `orderDetail.orderItems.c` 遍历商品，提取状态、取货信息、金额、商品数据。
4. 对照邮件商品进行校验；取消订单的官网零数量不覆盖邮件数量。
5. 开启短事务、锁定订单，比较 updatedAt 和身份，拒绝网络请求期间已变更的旧结果。
6. 保存官网字段、校验结果、刷新状态及爬取日志；失败按代码路径记录日志或暂停。

官网金额保存 official_order_amount、币种和解析错误。未识别金额保持缺失，不能用固定价格代替。产品字段、状态枚举和日志字段见[数据库架构](../database/数据库架构.md)。

## 代理与重试

- 实际抓取要求 `PROXY_ENABLED=true`；关闭时不会自动回退为直连。
- [proxyManager](../../src/utils/proxyManager.js)维护内存代理池和失败计数。初始化按需获取代理，周期自动刷新已禁用。
- 默认请求间隔 5–10 秒，配置为 `CRAWLER_DELAY_MIN`、`CRAWLER_DELAY_MAX`；重试等待随尝试次数递增。
- `CRAWLER_MAX_RETRY` 默认 3，规范上最多 3 次；请求超时由 `CRAWLER_TIMEOUT` 控制。
- HTTP 541 立即废弃对应代理并累计风控次数；其他失败累计达到阈值后废弃。无可用代理时尝试刷新，代理刷新失败或连续风控可能暂停调度。
- “每 IP 每分钟少于 10 次”是策略约束，当前未证明存在独立的持久化每 IP 限流器；不能把请求延迟等同于该指标已验收。

## 自动调度和暂停

`AUTO_ORDER_REFRESH_ENABLED` 默认 false；启用后按 `AUTO_ORDER_REFRESH_INTERVAL_MS`（默认 300000ms）扫描。已完成、已送达、已取消、取货已取消等终态，以及已付款且已取货的订单停止自动刷新；订单校验异常也可能关闭该订单刷新。

暂停和运行中状态仍在 Worker 内存中。独立 Worker 模式下 API 只能返回日志观测信息，恢复接口返回 409，不能替另一进程恢复。排障后由受控运维处理，见[快速运维手册](../deployment/快速运维手册.md)。

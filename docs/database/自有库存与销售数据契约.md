## 简化台账增量契约（2026-10-04）

已批准的[简化版方案](../planning/自有库存简化版方案.md)通过第二份正式迁移增量演进；旧实物、销售、资金和审计表继续为事实来源，不建立平行账、不删旧资料。

- `stock_units` 增加 `order_number_text`（可空，最长100）、`notes_ciphertext`（加密备注）、`extra_expense_amount`（可空 NUMERIC(14,2)，有限非负单台费用）。售出后费用同步到原费用及分配表，误售恢复作废该次费用并清空此字段。
- `stock_sales` 增加 `simple_ledger`（默认false）、`payment_verification`（known/unknown，默认known；unknown仅历史简化销售）。新批量售出在同一事务内按每台创建独立销售，用户操作仍以SN为入口。
- 历史出库仓 `stock_sale_units.from_location_id`、日期未知的 `stock_collections.received_at` / `stock_receipts.received_at` 可空。仅历史简化销售允许销售人、出货人空缺；正常新售两者必填。不得伪造历史日期或人物。
- 人工核定官网成本允许拿货日期暂缺，目录版本成本仍要求拿货日期。待补成本为NULL，不将入库日自动当作拿货日。
- 待关联订单号沿用订单读取和原TAG边界；关联已有订单需原取货和来源关联权限。`order_number_text` 仅保存尚未关联的号码，成功绑定后清空，展示由原订单权限投影；旧取货绑定／解绑同样清理冗余文本，不能在解绑后将受限来源降为普通文本暴露。身份、成本与销售事实不因补订单号重建。
- 所有新命令仍经原事务锁、requestKey、version、权限和审计；仅warehouse在库或local已售进入台账，旧多台/部分到账保留并限制不兼容修改。
- 新迁移 down 仅在无增量资料、无simple_ledger销售、无新增空值且可恢复旧约束时允许；有业务数据拒绝回退。第一份迁移不改写。

## 公共字段与约束

- 表名使用 `stock_`，模型使用 `Stock` 前缀，属性为 snake_case 字段对应的 camelCase。除事件、单例与关联表另述外，主键 `id UUID`；所有新模型都在 `src/models/index.js` 显式注册。
- 可变业务表统一有 `version INTEGER NOT NULL DEFAULT 0 CHECK(version>=0)`、`created_at/updated_at TIMESTAMPTZ NOT NULL`、`created_by/updated_by INTEGER NULL` 外键关联 users，删除 SET NULL。人员删除不删除业务记录，事件另保存姓名快照。
- 金额一律 `NUMERIC(14,2)`，币种固定 CNY，不允许 NaN/Infinity 或负收入、负成本、负费用；API 使用两位小数字符串。内部精确转换为整数分运算，不用二进制浮点分摊。利润允许负数，只计算不额外存一份可变利润字段。
- 日期 `*_on DATE` 表示拿货日；业务时间 `*_at TIMESTAMPTZ`，客户端发送带时区 ISO 8601，报表按 Asia/Shanghai 日界限归集。录入时间与实际发生时间独立。
- 除导入预览过期清理外，不提供业务主记录物理删除。下列 UUID 业务外键默认 ON DELETE RESTRICT；稳定配置用 `is_active` 停用。JSONB 默认不存账号、密码、完整订单链接或付款链接。
- 所有枚举必须有数据库 CHECK；服务层另校验状态迁移及跨表不变量。更新同时校验 `expectedVersion`，不能用启动 `sync/alter` 建表。
- 表中“可空”才允许 NULL；其他列必填，默认值另列。`notes_ciphertext TEXT NULL` 使用现有 `fieldEncryption` 保存备注，字符串业务标签限制长度，证据只能记录受控对象键。

`stock_units` / StockUnit 使用公共字段，另有：

| `official_cost_amount`  | NUMERIC(14,2) 可空           | confirmed 时必填且>0；人工确认，不随价格目录或订单补关联改变                                |

| `cost_basis_ciphertext` | TEXT 可空                    | 人工核定依据或异常说明；成本权限控制                                                        |
| `origin_mode`           | VARCHAR(24)                  | legacy_binding/opening/current/history，记录最初建档来源，后续操作不重写                    |

不在 stock_units 冗余保存来源 orderId，来源订单唯一权威关联继续保存在 `pickup_devices`。新增 `pickup_devices.stock_unit_id UUID NULL UNIQUE`，组合外键 `(stock_unit_id,serial_number)` 指向 stock_units 的 `(id,serial_number)`，ON UPDATE CASCADE，ON DELETE RESTRICT；原 order_id 仍必填，原 id、唯一 SN 与条码字段不改。

迁移按现有 pickup_devices 的 SN 创建 registered 主档并回填 stockUnitId，保留原设备 UUID、时间和订单关系；不推定规格、仓库、取货、成本或已售。列保持可空用于代码回滚兼容；新旧扫码服务桥接上线后必须双写。应用回滚期间可能新出现空 stockUnitId，恢复时由显式幂等修复命令补齐，不能把数据库启动变成隐式迁移。

原“解除绑定”仍删除该条 pickup_devices 绑定并保留原审计，stock_units 及库存、销售、照片记录保持存在。重新绑定生成新的 pickup_devices UUID，旧解除请求重试不能解除新关系。新库存页关联／更换来源也调用同一事务服务；更换时需同时能访问旧、新订单并校验当前 bindingId，绝不凭订单后四位、姓名或照片推测来源。

## 导入预览

`stock_import_jobs` / StockImportJob：UUID 主键及公共字段，`kind VARCHAR(24)` 为 opening/historical_sales/collections/receipts；`file_hash CHAR(64)`、`preview_hash CHAR(64)`、`source_label VARCHAR(100)`、`payload_ciphertext JSONB`、`result_refs JSONB DEFAULT '{}'`、`status VARCHAR(16)=preview`（preview/committed/expired）、`expires_at TIMESTAMPTZ`。索引(createdBy,status,createdAt)。预览有效 24 小时，最大 500 行、单文件 10MiB，不引入新 Worker；过期预览通过显式维护命令清理，已提交结果保留。

资金表的 externalRecordKey 在非空时分别唯一，导入资金记录必须提供；同日期同金额不能据此合并或判断重复。数据库写入的实际唯一键固定为 SHA-256(sourceLabel规范化值 + NUL + 原始外部键trim值)，sourceLabel做NFKC与trim，外部键不改变大小写；原始键保留在加密导入载荷和事件中。模板明确要求来源内稳定，换文件或排序不换键。库存按 SN，已售实机按有效 saleUnit 唯一约束防重。解析载荷加密，提交时重新检查当前权限、版本与库存，不直接照抄旧预览。

## 必需索引及迁移边界

- 实物：(product_id,state,location_id)、(location_id,state)、serialNumber 唯一；取货：(stock_unit_id)唯一及原 orderId 时间索引。
- 销售：(status,channel,created_at)、(shipped_at,salesperson_id)、saleNo 唯一；saleLines(productId,saleId)；saleUnits(saleLineId)、有效实物部分唯一。
- 流转：明细(stockUnitId,status)、头(status,createdAt)；费用(saleId,status)；付款(saleId,status)、(collectorId,receivedAt)；到账(payerId,receivedAt,status)，分配(saleUnitId,status)、(receiptId,status)。所有外键建必要索引，列表关联预加载避免 N+1。
- 迁移按主资料／实物兼容、销售流转、费用资金、附件审计导入分组；具体新文件以当时最新时间序号命名，不能修改已经发布的旧 Migration。
- up 使用事务，逐步回填并验证一对一 SN 身份，保留原字段与业务状态；全部新业务默认关闭。仅回填 registered 主档不算入库，不产生销量或货款。
- down 只在没有新业务数据、没有新模块业务事件、没有新附件且可证明所有主档均是兼容桥接身份时允许回退；有真实业务必须拒绝删除并采用保留 schema 的应用回滚。旧设备绑定数据永远保留。隔离库必须演练空库 up/down/up、旧绑定回填和有业务数据拒绝 down。

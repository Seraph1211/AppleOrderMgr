# 订单 TAG 来源与取机人兜底方案

> 状态：2026-10-16 本地实现与独立验证完成，未提交或发布本次调整
>
> 最近核对：2026-10-16
>
> 范围：全部历史与新增订单及订单衍生业务。2026-10-14 档案 TAG 唯一来源版本为历史基线，当前生产情况见开发进度。

## 目标与统一规则

1. AOS 来源订单优先使用 `source_recipient_tag` 保存的原始 TAG；来源为 AOS 且 TAG 非空时，即使没有取机人档案或旧关联错误，也使用该来源值。
2. AOS TAG 缺失，或订单没有 AOS 来源时，以订单保留的来源姓名与显式身份证后四位唯一匹配系统取机人，使用其当前 TAG。不能仅凭 `recipient_ref` 或预加载的旧关联档案使用 TAG。
3. 缺少有效姓名／尾号、来源与订单姓名冲突、多个候选、无候选或唯一候选 TAG 为空，最终 TAG 为 null。完整身份证快照可能来自旧档案补充，不作为要求完整身份证一致的额外条件，也不在 SQL 中截取密文。
4. 不区分代抢例外。代抢人员不在取机人库时，有 AOS TAG 仍正常使用；缺 TAG 且无候选时保持缺失。

NULL、空串和全空白 TAG 均视为缺失；有效值保留原字符串，完整匹配、区分大小写，不拆分、不自动改名。匹配使用完整姓名和四位尾号（末位 X 大写归一），不以手机号、邮箱替代。最新只读核查的1243条订单来源第16列均为后四位，不据此推断未入库文件。

`orders.tag` 保留历史证据，不作为额外回退；原始 AOS 记录和来源字段不改写。不新增档案、不自动补关联、不调整已有任务处理人和付款状态。档案 TAG 变化只影响正在使用档案兜底的订单，AOS TAG 有值的订单保持来源值。

## 影响范围

| 模块 | 统一要求 |
| --- | --- |
| 订单列表、详情、筛选、候选、导出 | 使用最终 TAG；过滤在分页前完成，不能先分页再匹配 |
| 仪表板、渠道、订单统计 | 按最终 TAG 聚合，与订单访问权限相交；档案自身统计仍按档案字段 |
| 用户权限、附件、照片、库存来源、批次、后台发信 | 每次查询或操作按最终 TAG 校验，不从旧关联档案重新推导 |
| 付款任务与调度 | 所有权、功能权限和最终 TAG 范围取交集，不额外要求 orders.read |
| 自动分配 | 最终 TAG 匹配规则及处理人授权；缺失仅全部范围账号可接单；既有任务不自动转派 |
| TAG 规则／授权候选 | 展示实际最终 TAG，不以取机人库的全部标签代替订单可用值 |
| 新企微通知 | 采用相同最终值；旧投递保留，不补发 |
| 资料写权限 | 新建、删除、修改姓名／证件／TAG、导入等可能改变兜底候选或授权范围，须具备全部订单范围及原功能权限 |
| 渠道改名 | 含 AOS 固定来源 TAG 的渠道拒绝改名，避免只改档案却宣称订单已改变；纯档案兜底渠道可事务更新档案、授权及审计，保留原始来源 |

## 实现与兼容

共享 JavaScript 读取和 SQL 表达式生成最终值；序列化优先读取查询计算列，不能使用旧关联档案覆盖结果。查询采用有界候选计算或批量读取，避免逐订单数据库请求。旧 `recipient_tag`／`recipientTag` 字段名保留兼容，前端称“订单 TAG”，缺失状态不能误报有 AOS TAG 的订单为缺失。

订单显示姓名优先来源快照，避免旧关联姓名与最终TAG对应身份混淆；详情顶层 `recipient_name` 表示订单身份，嵌套 `recipient` 继续表示实际关联档案。付款增量返回 `recipientName`。不改变表结构。订单外键继续承担关联记录功能；TAG 的安全兜底匹配与是否已人工补关联分开。已知来源姓名矛盾不能因为旧外键存在而放宽。

## 验收标准

- AOS TAG 与档案不同、无关联或关联错人时仍使用 AOS TAG；非 AOS 来源不得误用来源同名字段。
- 空 AOS TAG 下，未关联但有唯一候选可兜底；错关联不得串用旧档案；重名同尾号、缺尾号和来源姓名冲突不兜底。
- 普通与 Unicode 空白均为缺失，合法 TAG 首尾空白和大小写保留；SQL 与 JavaScript 输出一致。
- 档案 TAG 修改实时影响兜底订单，AOS 订单稳定；筛选、分页、导出、统计、权限、付款一致。
- 同一登录令牌在兜底 TAG 变化后立即按新范围访问；新增同名同尾号导致歧义时旧授权不得继续生效。
- 自动分配规则、处理人授权与并发复核使用最终 TAG；不迁移已分配任务。
- 渠道 AOS 固定来源改名拒绝，纯兜底改名及权限／审计原子提交；资料创建、身份修改不能被有限范围用户用来扩权。
- 开发容器 lint／业务测试／前端构建／文档检查，独立 PostgreSQL 与桌面／手机合成浏览器验证通过后主审验收。

## 发布边界

本轮先完成编码、独立测试和主审。发布需要使用当时真实生产基线，保留其他并行功能；业务备份和隔离恢复排除约定的 AOS 监控日志明细及原始文件，不删除生产日志。权限可见范围将因 AOS 优先而改变，发布前须只读核对最终 TAG、授权集合与分配命中变化，不能以健康检查代替业务验收。

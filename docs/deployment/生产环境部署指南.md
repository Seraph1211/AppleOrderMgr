## 适用范围

本文描述仓库当前部署文件及发布步骤。历史服务器部署记录已经[归档](../archive/2026-07/部署与数据库操作记录.md)，本轮没有连接生产环境。不得根据本文认定线上版本、路径或服务名称已经更新。

## 运行拓扑

| 部件           | 当前仓库配置                                                         |
| -------------- | -------------------------------------------------------------------- |
| api            | Compose 服务；容器和宿主机均使用 3000 端口；RUN_WORKERS_IN_API=false |
| email-worker   | 独立进程执行 start:email-worker                                      |
| crawler-worker | 独立进程执行 start:crawler-worker                                    |
| PostgreSQL     | Compose 之外的数据库；通过 DB_* 显式指定                             |
| Nginx          | 宿主机示例配置，HTTPS 静态页面与 /api 反向代理到 localhost:3000      |

参考 [docker-compose.yml](../../docker-compose.yml)、[Dockerfile](../../Dockerfile)、[Nginx 示例](../../nginx-apple-order-mgr.conf)。数据库在宿主机时，容器内 localhost 指向自身；应使用实际可达的主机地址，配置已提供 host.docker.internal 映射。

## 发布前准备

1. 明确批准发布的代码版本、目标目录、三个服务名称、数据库及现有共用服务边界。
2. 验证依赖、构建、测试、文档门禁，按[测试指南](../testing/测试与验收指南.md)区分静态、集成和业务证据。
3. 备份数据库、上传目录、当前部署配置和可恢复版本；密钥通过受控环境注入。
4. 对齐 DB_*、JWT、字段加密、IMAP 发件人白名单、代理、FRONTEND_URL 和自动调度开关。生产 CORS 默认值仍是 localhost:3001，必须显式设置实际前端 Origin，不能沿用默认值。
5. 检查 Nginx 域名、证书和静态目录。当前示例 /uploads 为公开静态访问；付款截图访问控制尚未闭环，应在发布验收中处理，不能宣称该路径已有私有文件权限。

## 构建与结构迁移

在目标版本的受控构建/迁移环境执行：

```bash
npm ci
npm --prefix frontend ci
npm --prefix frontend run build
```

迁移必须由能够访问目标数据库、安装完整依赖的专用进程执行：

```bash
NODE_ENV=production npm run db:migrate
```

Dockerfile 使用 `npm ci --omit=dev`，而 sequelize-cli 属于开发依赖，因此不能假设应用运行镜像中可以执行 db:migrate。迁移进程的 DB_HOST 需按其所在网络设置，不照抄容器专用地址。

首次部署再执行管理员种子；存量敏感数据转换是独立写入步骤，详见[数据库指南](../database/数据库初始化与迁移指南.md)。应用启动不会自动同步表结构。

## 启动与切换

以下命令仅供已批准的发布窗口使用，在目标项目目录执行：

```bash
docker compose config --quiet
docker compose build api email-worker crawler-worker
docker compose up -d api email-worker crawler-worker
```

将已构建前端放到经核对的 Nginx 静态目录，配置检查通过后按目标环境流程切换。不要以整机停服、删除全部容器或重启共用数据库作为默认部署步骤。

## 发布验收

- api readiness 通过，数据库结构与批准的 Migration 一致。
- 三个服务分别运行；检查 Worker 日志和实际处理数据，API 健康不代表 Worker 健康。
- 登录/改密、授权、列表、导入导出、邮件入库、官网补全按发布范围完成业务验收。
- 验证静态资源、前端 API 路径、金额缺失、脱敏和截图访问边界。

## 回滚

回滚前明确数据库是否仍向后兼容。应用和前端回退到保留版本；存在结构或数据变化时按已验证方案恢复，不能默认执行所有 Migration down。记录恢复范围、丢失窗口及验证结果。

日常检查见[快速运维手册](快速运维手册.md)，故障定位见[故障排查](故障排查.md)。

# 日志筛选五项单行布局发布适配说明

> 状态：当前有效；仅前端已正式发布，2026-10-25完成独立只读复验与收尾。
>
> 日期：2026-10-24（北京时间）

本轮在 `20261024-log-labels` 实际生产前端上调整服务器、软件实例、账号编号、日志时间范围、正文关键词五项筛选的桌面布局与外观。保留点击后在正常文档流直接展开的下拉列表、标签管理、跨日查询、元信息、原文下载及原有权限行为。仅替换静态前端，不构建或替换 API，不执行 Migration，不重启任何容器，不修改用户已经配置的真实标签。

## 制品复现

- [制品白名单](制品白名单.json)记录六个生产前端文件的修改前后 SHA-256；[生产增量补丁](production-overlay.patch)以当前生产标签版本的源码为修改前版本。
- `Dockerfile.frontend` 继承 `apple-order-mgr-frontend-builder:20261024-log-labels-amd64`，只复制白名单文件，在本地独立 `main` 构建目录执行现有前端 lint 与 Vite 构建，目标平台为 `linux/amd64`。
- 复现前从基线前端构建镜像读取 `/app/src`，放到独立构建目录的 `frontend/src`，先运行 `python3 <本目录>/verifySource.py before <构建目录>`。
- 在构建目录依次执行 `git apply --unidiff-zero --check <本目录>/production-overlay.patch`、`git apply --unidiff-zero <本目录>/production-overlay.patch`，再执行校验脚本的 `after` 模式。补丁使用零行上下文，修改前摘要校验不可省略。
- 前端归档、manifest 和操作脚本只在本轮测试及主 Agent 截图验收完成、代码提交后打包一次；manifest 的 `codeCommit` 指向本轮实际提交，另记录独立构建源的 commit、tree、六文件摘要和全部静态文件摘要。冻结后不得重写归档或在上传期间重新打包。

工作区保留较旧的日志日期和时间字段布局，本轮同步可移植的视觉及下拉组件改动。生产采用此处六文件补丁，不能把工作区旧 `MonitorLogs.jsx` 整体覆盖生产，避免丢失跨日查询、导出和生产权限适配。

## 仅前端发布边界

新发布目录继承上一版本 `release.env`、`docker-compose.prod.yml`、`images.override.yml` 的原文及旧 API／Worker 镜像。配置中原有版本标识继续指向运行组件；新前端版本以本轮 manifest 的 `releaseId`、`frontendOnly=true` 和静态文件摘要为准，不能因为 `current` 指向新目录就推断 API 已替换。实际 API 的 Compose 工作目录仍可指向上一发布目录。

本轮重新备份业务数据库并在隔离 PostgreSQL 15 恢复验证，覆盖新增标签数据；按项目约定排除 AOS 日志明细及原始文件。共享业务文件对比上一份已逐文件恢复验证的备份：验证旧归档摘要并核对当前文件摘要，未变文件复用，新增或变更文件仅作增量归档和恢复读回，删除项单独记录，不重复全量归档。

正式切换前后核对全部容器（含 API）的 ID、镜像和启动时间，真实标签摘要、库存现行配置与开关、Migration 记录、共享环境及 Nginx 配置均须保持不变。发布统一执行 `productionFrontendGate.py` 的 `prepare`、实际 Nginx 用户 `33:33` 的 `check`、`switch` 和 `verify`。失败只通过该门禁恢复旧前端指针，不回灌业务库、不回退标签、不操作 API 或 Worker。

## 前置条件

使用专用测试库、合成标签和三个角色。准备有订单渠道、仅取机人标签、无金额订单、多种状态订单以及中文/空格/特殊字符标签。以下是待执行清单，不代表已经通过。

| 编号  | 场景       | 检查点                                                                        |
| ----- | ---------- | ----------------------------------------------------------------------------- |
| CH-01 | 渠道列表   | 有订单的非空标签聚合；仅取机人标签不误算为已建立渠道                          |
| CH-02 | 状态和金额 | paid 与 picked_up（兼容 completed）口径准确；不使用固定单价；显示缺失金额情况 |
| CH-03 | 分页筛选   | page/pageSize、状态、搜索、空结果和非法参数                                   |
| CH-04 | 订单明细   | 手机脱敏、Apple 链接不泄露，字段和分页层级正确                                |
| CH-05 | 合法改名   | orders、recipients 同事务更新；返回影响行数，其他标签不变                     |
| CH-06 | 非法改名   | 空值、相同名、不存在原渠道、已有目标订单标签被拒绝                            |
| CH-07 | 特殊输入   | 中文、空格、斜杠、百分号、超长名称；URL 编码和错误提示                        |
| CH-08 | 角色       | readOnly 不能改名，operator/admin 按权限执行，未登录被拒绝                    |
| CH-09 | 并发与回滚 | 两个改名请求及数据库失败，确认无部分更新                                      |
| CH-10 | 已知缺口   | 仅存在取机人标签的目标名、空白规范化、跨币种统计需单独判断                    |

执行后记录每项结果及证据；未执行保持待执行，不将历史报告中已勾选状态带入本清单。实际规则见[渠道管理说明](../design/渠道管理说明.md)。

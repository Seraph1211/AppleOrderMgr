# 库存状态核对来源纠正

## 问题与修正

用户要求每 30 分钟读取系统内“官网订单状态”，原库存生命周期实现误接 Apple HTTP 队列。停止生产领取器并等待在途结束后核查，库存自动任务无 queued/running；已有 326 条记录（293 成功、33 失败）保留。原人工批次不取消、不解除保护暂停。

API 内部定时器每分钟扫描到期历史订单，每单 30 分钟持久间隔，库存事务锁保证多实例互斥。只读取 orders.official_raw_status；库存不创建官网批次和请求。状态为空或 UNKNOWN 保留原状态；订单级退货数量和 SN 未知时逐台人工核实。来源观测时间及状态完全一致时，可复用已有逐项证据。原人工官网刷新仍可保存新事实，失败不再覆盖库存本地核对结果。页面改为“系统状态核对”。无数据库迁移。

## 验证与发布准备

43 项单元测试、62 项库存真实事务测试和 39 项官网任务测试通过。全仓首次 137 套通过、1 套因缺少硬编码隔离数据库连接失败；补齐独立测试数据库后该套 17 项通过；重跑全仓 138 套／2566 项通过，613 项环境门控跳过，所需库存及官网集成已单独运行。前后端 lint 无错误，Vite 构建、1440/375px 页面验收及文档检查通过。浏览器使用合成接口；生产不创建测试销售／退货。

发布制品以 20261010-stock-name 为基线，仅替换 API 与相关前端，保留现行 finishGroup 取货日期写入兼容差异。构建入口 scripts/releases/20261010-stock-local-check/。约 584MB 业务快照备份排除 AOS 日志数据（保留结构），SHA-256：fad5e90ee0271a6e511b8adaa34d370d9517787f5dfa789cb77394cd6ec7f430。隔离 PostgreSQL 恢复后 104 张业务表行数及摘要、75 项迁移全部一致，生产发布进行中。

## 回退边界

回退应用可切回上一发布目录，但须同时停止官网领取器，防止旧版恢复自动 HTTP 入队；保留新观测和审计，不覆盖业务数据库。修正再次上线后才恢复人工官网执行器。

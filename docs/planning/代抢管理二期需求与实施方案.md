## 目标和授权

在已有代抢管理上简化客户登记、完整生成软件模板、统一页面权限，并支持一笔委托关联多个 Apple 订单。用户授权新 Worktree 中完成文档、子 Agent 开发和测试，由主 Agent 做功能验收和代码 Review，通过后提交、合入 main 并部署生产。子 Agent 使用 GPT 6.1 Sol / medium。原主工作区未提交工作保留，不混入发布。

原始需求：[Notion Work Notes](https://app.notion.com/p/3fa597f347fa8044ae72dba989217556)。本方案包含会话中的后续确认，取代原需求中存在歧义的描述。软件截图仅作为导入名称依据，不是 Apple 实时商品目录。

## 已确认业务规则

### 委托和登记

- 每次粘贴一位客户的一笔需求；需要分别抢到的不同商品由工作人员拆成多笔代抢单。
- 一笔单可以包含多个候选商品，表示任选，使用半角 `|` 分隔；每个候选写完整型号、颜色、容量。默认数量 1，可填写数量。不建立多条独立需求及部分完成工作流。
- 每笔独立管理账号和模板，沿用正整数自增编号，不重置历史编号，不保证无空号。
- 固定字段：姓名、身份证后四位、手机号、邮箱、机型、取机城市、支付方式、订单来源、备注。可选：取机门店、数量、平台订单号。
- 身份证结构化字段和导出仅保存后四位，字符串保留前导零及末尾 X。2026-10-16 用户确认：粘贴原文或手工填写可能是完整18位／15位号码，识别校验后提取尾四；兼容身份证、身份证号和原后四位字段标签，无效或冲突提示核对。既有客户原文加密保存和受权限控制的原文展示保持。
- 支付缺省微信；数量缺省 1，预览提示。来源必填，提供闲鱼、淘宝、小红书及可填写的其他来源。
- 明确且完整的信息支持一键登记，歧义进入预览核对；不得将未知颜色或商品猜测后保存。保留原始文本和核对编辑入口。
- 城市必填；门店可选填，以 `|` 分隔。未指定门店默认全选城市当前门店，保存固定代码集合，不因以后新增门店扩张。指定门店需有效且符合所填城市。
- 账单地址沿用现有生成能力，随解析生成可编辑草稿；不让城市已明确的用户被迫重复选择门店、手动生成地址。
- 备注仅展示、阅读、人工修改；日期、颜色或其他文字均不作为匹配和软件执行规则。
- 平台订单号可重复（同一客户平台单可拆为多笔代抢）；内部编号唯一。重复粘贴提示疑似重复，允许明确继续另建，不静默合并。

### 账号

- 新单从专用 AppleID 池随机分配一个状态为“未使用”或“使用中”且未被代抢活跃分配占用的账号，事务与并发锁保护；池空仍保存并提示待分配。
- 保留追加、手选、更换所需的分配和释放能力及历史；每个账号同时只能被一笔委托占用。
- 成功、取消不自动释放；工作人员确认外部软件停止后释放。系统不控制外部软件任务。

### 四态与多订单关联

- 四种状态：待处理、抢购中、已成功、已取消。有页面权限者可以自行修改状态和备注，包括结束状态恢复，不强制重建委托或额外重抢表单。
- 人工成功可通过备注说明原因，不新增强制原因表单；原客户备注保留。状态变更有操作人、时间、前后状态和来源记录。
- 支持修改客户资料；编辑不改已入库 Apple 订单，不删除账号分配/关联/事件历史。
- 一笔代抢单可关联多个 Apple 订单；同一 Apple 订单仍不能同时归属多笔代抢单。人工关联可用于记录抢错商品，保留账号及客户身份核对。
- 自动匹配继续核对分配账号时间范围、客户姓名/手机号/证件尾号、邮箱无冲突、任选商品中任一完整组合、数量、门店。备注不参与匹配。匹配结果幂等。
- 新关联满足要求可自动设成功；不要求付款。Apple 后续取消不回退代抢状态。
- 人工改回待处理/抢购中后，已有关联不再触发成功，新匹配关联可触发成功。取消状态下新关联只补记录，不改状态；修改备注不得引起状态变化。
- 不新增有效/无效关联标记、需求完成量或复杂重抢流程；问题由工作人员备注说明。解除误关联保留历史和原因，被解除订单不自动重新关联。
- 详情展示关联 Apple 订单列表：系统订单 ID、Apple 订单号、官网采集状态、商品信息，必要时门店及官网状态观测时间。未采集显示未获取，不用邮件状态冒充官网状态。不负责付款、取货、退款业务。

### 软件模板与精确映射

- 每个当前占用账号生成一行；保留既有 CSV 字段顺序、空占位及未涉及的配置后缀。
- 门店字段填软件名称，多个名称以 `|` 连接，不含 `(Rxxx)` 或省市后缀；内部按门店代码映射，不能直接去掉 Apple 前缀猜名称。

### 权限与安全

- 页面统一一个权限：具有权限即查看、编辑、修改状态、复制含密码模板、管理专用池、关联纠错。不给其他页面附带权限。
- 服务端统一校验，不能只隐藏按钮。沿用 proxy_orders.read 作为唯一有效页面权限；旧细分权限退役并兼容现有授权数据，不残留可绕过路径。
- 普通列表/详情不返回密码；密码仅复制/明确账号操作需要时返回，接口 no-store。保留加密原文、密码和脱敏审计，不日志输出客户原文或完整模板。
- 没有删除委托/账号历史的需求。不得在生产执行真实 Apple 抢购或合成业务写入验收。

## 实施设计

1. 先更新数据库/API 契约：新增订单来源、候选商品集合、多订单关联历史结构，移除平台单号唯一限制，保留旧字段兼容迁移。将既有单条商品和官方关联可靠回填，不丢状态、备注、分配、历史。旧单来源无法确认时不猜渠道，保留历史兼容/明确待补。
2. 建立纯函数映射与严格校验：解析候选、城市默认门店、支付和 TAG，预览缺项和歧义，完整模板字段级断言。历史商品不在新目录时仍可查看，导出提示核对。
3. 服务端：随机账号分配；可逆人工四态；幂等多订单匹配及人工状态防覆盖；统一权限。避免按全量生产订单无界扫描和 N+1。
4. 前端：沿用浅色表格，保留加载/空/错误/窄屏；便捷登记、候选编辑、来源/支付选择、门店默认勾选、关联多单表格及官网状态。状态和备注就地编辑。
5. 子 Agent 开发自测后独立测试；主 Agent 逐项功能验收、代码 Review 和迁移审查；修复后复测，不以文档声明替代验证。
6. 干净功能分支提交，验收后合入 main，使用与验收一致的 main 干净制品部署。原工作区未提交变更不参与发布。

## 2026-10-16 代抢订单软删除（已授权）

- 列表和详情提供删除入口，普通确认后软删除；不物理删除代抢单、官方订单关联、分配及审计历史。
- 删除使用当前页面权限，校验expectedVersion并在事务内锁定委托。有活跃账号占用时必须明确确认外部软件已停抢，再结束占用；不修改AppleID账号状态。没有占用的订单无需停抢确认。
- deletedAt记录软删除时间。普通列表／搜索／计数、详情、编辑、状态及备注修改、分配、复制、重复提示和自动匹配均排除已删除订单；批量复制混入已删除项时整体拒绝。已删除记录不可通过旧页面继续操作。
- 删除不是取消，不改变原业务状态；保留数据用于审计，本轮不新增回收站和恢复入口。生产发布不会自动删除任何现有订单。

## 2026-10-16 列表字段与状态展示（已授权）

- 代抢订单列表的数据字段固定顺序：编号、姓名 / 身份证、手机号、邮箱、机型、取机城市、支付方式、订单来源、备注、状态、登记时间、更新时间。选择列位于最左，操作列位于最右，不增加其他业务数据列。
- 编号沿用内部代抢编号；姓名与身份证后四位同列，保留前导零与 X；邮箱使用客户邮箱。机型展示完整型号、颜色、容量及候选 `|` 分隔，不将不同候选合并或截断信息。
- 取机城市优先使用已登记城市，历史记录无城市时仅可从全部已知且同城的门店代码推导；不能确认时显示“—”。缺失字段统一使用清晰占位，不推测客户信息。

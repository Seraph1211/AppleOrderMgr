## 内部 GET 核验接口封装方案（2026-10-16，已批准开发）

本节是新增规划，不属于上方已发布范围。用户已批准开发测试并由Main审查后提交发布：员工通过 HTTPS GET，仅传姓名、身份证号、令牌即可核验。基线为本地 `main@c7b4e83` 与当前工作树；已静态核对路由、供应商适配、执行器、字段校验、日志及数据库文档，没有核查生产运行配置、实时套餐余额或发起真实核验。

### 接口与返回

端点 `GET /api/internal/v1/identity/verify`，沿用系统 HTTPS 域名。已在独立Worktree开发，尚未生产发布。参数固定为三个单值字符串：

| 参数           | 内容          | 规则                                                                    |
| -------------- | ------------- | ----------------------------------------------------------------------- |
| `name`         | 姓名          | URL 编码；复用现有非空、长度及控制字符校验，允许姓名中的间隔点          |
| `idCardNumber` | 身份证号      | 文本传入；首尾去空格、末位 x 转 X，复用大陆 18 位、出生日期与校验位校验 |
| `token`        | 员工 API 令牌 | 独立随机令牌，不能使用阿里云 AppCode 或后台登录 JWT                     |

拒绝重复键、数组、对象及非约定参数，不猜测或纠正姓名、证件字符。调用方用 URL 参数构造器编码，不拼接未经编码的姓名。无需额外登录、签名、时间戳或客户端请求编号。

正常取得确定结果返回 HTTP 200，例如：

```json
{
  "success": true,
  "requestId": "本次访问编号",
  "data": {
    "verificationId": "核验记录编号",
    "status": "matched",
    "matched": true,
    "message": "姓名与身份证号一致",
    "verifiedAt": "2026-10-16T02:00:00.000Z",
    "reused": false
  }
}
```

不一致为 `status=mismatched`、`matched=false`，仍是 `success=true`，表示已取得确定结果。不回传姓名、完整身份证、性别、生日、地区或供应商原始响应；历史页面继续执行既有权限及原文规则。

| HTTP 状态 | 场景                                           | 处理                                               |
| --------- | ---------------------------------------------- | -------------------------------------------------- |
| 400       | 参数或身份证格式错误                           | 不请求供应商                                       |
| 401       | 令牌缺失、错误、过期或已撤销                   | 统一认证失败，不请求供应商                         |
| 403       | 账号停用或身份核验权限被撤销                   | 不请求供应商                                       |
| 405       | HEAD、POST 等非 GET 方法                       | 不请求供应商；显式拦截 Express 默认 HEAD 回退      |
| 429       | 本地速率、额度或执行槽位限制                   | 安全错误码及适当 `Retry-After`，本次没有新发起核验 |
| 502       | 供应商返回无法解释                             | `RESULT_UNKNOWN`，不得解释成不一致                 |
| 503       | 服务关闭、供应商鉴权／额度异常或基础设施不可用 | 返回受控错误；是否已经发出请求由明确信息说明       |
| 504       | 已调用但超时／连接中断、结果未知               | `RESULT_UNKNOWN`，不自动重试                       |
| 409       | 重复访问命中尚未解决的未知结果                 | 提供既有核验记录编号，要求核查后处理               |

错误统一为 `success=false`、`requestId`、`error.code/message`；有已建记录时返回 `verificationId`，已调用但无法确定结果时明确 `status=unknown`、`matched=null`。实现时给现有适配层补充受控内部原因码，以区分超时、异常响应、鉴权和额度；不要从中文 message 反推错误类别。现有页面状态语义保持。

### 复用、同步执行与重复请求

复用 `identityInputService`、`identityProviderService`、现有字段加密和核验历史。对调用方同步返回；后端沿用固定供应商 HTTPS POST，AppCode 仅服务器读取。

1. 为新路由挂载专用令牌认证，位置在全局后台 JWT 认证之前，并保留访问审计。路径未匹配、方法错误和异常分支也必须进入专用安全处理。
2. 抽取现有执行器的全局 PostgreSQL 锁、请求起点间隔及中断恢复为共享执行组件；后台单人、Excel、新 GET 接口共用一个供应商在途请求和至少 500ms 起点间隔。不能单独调用 provider 绕过限制，也不能让后台恢复逻辑把正在同步执行的请求误标为中断。
3. 新 GET 第一版不排长队；获取共享执行槽失败时立即返回 429，不创建将来会偷偷执行的排队任务。取得槽位后重查权限、额度、服务开关并持久化 processing，再调用供应商；供应商超时沿用现有 8 秒，反向代理响应预算建议 15 秒并在测试中核实。持续批量负载下 GET 可能返回繁忙，这是第一版边界。
4. 复用现有批次／明细保存 API 调用，来源新增 `api`、关联员工及令牌记录；来源枚举和执行器权限选择需一起更新，不能把 api 当作 Excel 权限。请求前落库、结果后落库，中断或结果落库失败一律未知，禁止重发补偿。
5. 不增加第四个必填参数，按“员工＋标准化姓名＋身份证”的带密钥摘要实现数据库原子防重。已确认确定结果在完成后 600 秒内复用，返回原 `verificationId/verifiedAt` 和 `reused=true`；不同姓名不能合并，跨员工不共享结果。进行中的相同请求返回繁忙，不新增供应商调用。请求编号每次不同，核验编号可以相同。
6. 600 秒保护是去重窗口，不是永久幂等保证；窗口外明确的新请求可能重新扣次。未知结果不因窗口到期自动释放重试，需管理员结合供应商调用证据明确处理并审计后再允许重验；提供此处置入口。客户端断开后已发送请求仍尽力保存，进程重启按同一恢复规则处理。
7. 供应商鉴权、额度或限流异常触发跨进程共享暂停状态，阻止所有入口继续发出调用，由管理员核查恢复，不能只暂停 Excel 队列。

### HTTPS GET 的保护边界

HTTPS 无法消除 URL 在浏览器历史、服务器日志及第三方监控中的留存风险，见 [OWASP 查询字符串泄露说明](https://community.owasp.org/vulnerabilities/Information_exposure_through_query_strings_in_url)；GET 还需考虑预取和自动重试，见 [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html)。按用户要求保留 GET，不额外增加调用必填参数。

- 新接口 HTTP 入口直接拒绝，不携带参数做 301／302 跳转；调用方必须首次就使用 HTTPS。此举不能挽回客户端已用 HTTP 发出的明文。
- 所有成功和错误响应使用 `Cache-Control: no-store`、`Referrer-Policy: no-referrer`；禁用该路径的代理／CDN缓存和代理自动重试；不提供 JSONP，不开放任意来源跨域。
- Nginx／入口层访问日志使用不含 query 的路径，排查错误日志、WAF／CDN及监控采集；原始 URI、Referer、参数和 token 均不得进入日志。只改访问日志格式不能证明错误日志安全，需用合成参数覆盖上游断开、错误 URI、405、限流及超时验收，必要时关闭该路径原始错误日志并由安全审计替代。
- Nginx虚拟主机访问日志统一改为仅记录method/uri（不含query）的安全格式，内部API访问由应用固定路径结构化日志记录。虚拟主机关闭包含原始请求行的error_log，含location解析前的错误也不落原始URI；运维诊断需改查应用日志及请求编号，无法继续依赖该虚拟主机Nginx原始错误明细。发布时须用合成探针验证真实入口的大小写、编码路径、HTTP/HEAD/404/上游断连和超时。
- 本地 `requestLogger` 使用路由模板，本轮已将全局 404 改为固定受控消息和路径，内部前缀使用专用错误兜底并去除输入。生产网关实际配置需实施时另行核对，仓库模板不代表生产已保护。
- GET 会触发付费核验，不应制作可被聊天软件预览或浏览器预取的带真实参数链接。接入说明明确关闭自动重试；建议员工工具发请求，直接地址栏访问仍存在历史留存。上述措施降低服务端泄露与重复扣次风险，不能保证隐藏调用方本地历史。

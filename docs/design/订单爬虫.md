# 官网订单爬虫退役说明

> 状态：已退役
>
> 生效日期：2026-09-22

官网订单链接爬虫、代理 Provider、刷新队列、浏览器采集扩展和系统爬虫日志均已退出运行链路。订单生命周期展示、筛选、付款资格和企业微信推送改用官方订单邮件证据，实施范围见[官网订单链接爬虫下线与邮件状态接替方案](../planning/官网订单链接爬虫下线与邮件状态接替方案.md)。

## 当前规则

- 新订单仍由现有邮件或 AOS 入库链路接收，入库事务继续创建付款任务并登记企业微信推送；不再创建官网刷新计划或任务。
- 订单、渠道、仪表板和付款页面只展示邮件订单状态、邮件付款状态、邮件取货信息及其证据时间。
- 历史官网已付款、退款或终态证据转换为独立的 `payment_assignment_hold_reason`，即使付款任务完成后重开也继续阻止自动和手工重新分配。
- 历史限制不阻止已有负责人继续执行重开、本人处理、读取付款链接或付款码；界面显示限制提示。
- 单纯超过来源下单时间 30 分钟只阻止自动分配，保留手工交接能力。
- 已退休刷新、代理和系统日志接口返回 HTTP 410 及稳定错误码 `FEATURE_RETIRED`。

## 历史数据

退役 Migration 将刷新任务、批次、计划、系统状态和爬虫日志移动到 PostgreSQL `archive` schema，并撤销应用角色的写权限。`archive.order_official_retirement_snapshots` 保存订单退役时的官网字段快照。首版只允许运维受控查询、导出和恢复，不提供管理台入口。

归档数据不参与当前业务查询、统计、分配或通知。恢复必须先备份并使用 Migration 回滚或受控 SQL，不能直接修改归档记录。

## 发布与回滚

生产发布采用扩展迁移、应用无中断切换、最终归档迁移的顺序。邮件接收、AOS 入库、订单邮件 Worker 和企业微信 Worker 在维护窗口内保持运行。维护窗口上限 15 分钟，详细步骤以[生产环境部署指南](../deployment/生产环境部署指南.md)和本次发布记录为准。

如需回滚，先切回旧应用版本，再回滚最终归档 Migration 和扩展 Migration；禁止通过重新启用已删除的单个 Worker 拼接新旧版本。

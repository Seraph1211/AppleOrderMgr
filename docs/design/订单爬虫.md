## 入口和数据来源

兼容抓取入口为[crawlerService.js](../../src/services/crawlerService.js)，独立调度入口为[crawlerWorker.js](../../src/workers/crawlerWorker.js)。持久化任务、策略、限流与代理 Provider 位于 `src/services/crawler/`；现有抓取、解析、校验和短事务写入仍由兼容门面维护，后续再完成 Parse、Validate、Persist 的物理拆分。

使用 axios 获取 Apple 订单页，通过 cheerio 读取 script 中的订单 JSON，无需执行网页 JavaScript。当前服务提取失败时进入错误和重试流程。

请求仅接受 `https://www.apple.com.cn/xc/cn/vieworder/{订单号}/{Apple ID}` 对应的合法来源与身份；校验协议、主机、端口、路径、用户信息和本地身份，返回结果的订单号也必须匹配。

## 同步流程

1. 加载订单及关联信息，检查订单是否符合刷新条件。
2. 在数据库事务外，经代理访问官网并重试。
3. 从 `orderDetail.orderItems.c` 遍历商品，以首个订单项的 `orderItemStatusTracker.d.currentStatus` 作为订单状态第一权威来源，提取商品、状态和取货信息；金额仅在官网响应实际提供时解析。
4. 对照邮件商品进行校验；取消订单的官网零数量不覆盖邮件数量。
5. 开启短事务、锁定订单，比较 updatedAt 和身份，拒绝网络请求期间已变更的旧结果。
6. 保存官网字段、校验结果及爬取日志；Worker 同步任务最终状态和下一次调度，失败保留旧业务状态并写入脱敏错误摘要。

官网金额保存 official_order_amount、币种和解析错误。未识别金额保持缺失，不能用固定价格代替；真实已取货页面的可见 HTML 和内嵌订单 JSON 均可能不提供金额，此类“官网未提供”需要与“提供了金额但格式无法解析”分开处理。产品字段、状态枚举和日志字段见[数据库架构](../database/数据库架构.md)。

### 真实终态页面结构

2026-09-07 对真实已取货订单执行只读结构分析：可见主内容的状态轨迹包含“已收到付款”和“已取货”，内嵌 JSON 的 `orderDetail.orderItems.orderItem-*.orderItemStatusTracker.d.currentStatus` 为 `PICKED_UP`；`orderHeader.d` 提供订单号、下单日期和退货套件标记，`orderItemDetails.d` 提供商品、数量、取货方式和日期。该样本的可见 HTML 与订单 JSON 均没有金额、币种、价格或总计字段。

订单级状态首先读取 `orderDetail.orderItems.c` 指向的首个订单项；该项缺失时再按 `orderItem-*` 键顺序寻找，兼容 `orderItem-1of2-*` 等真实键形。已确认的映射为 `PICKED_UP → completed`、`PAYMENT_EXPIRED_STORED_ORDER → cancelled`，后者同时映射 `paymentStatus=unpaid`；此外仅对与现有状态枚举同名且语义明确的 `PROCESSING`、`SHIPPED`、`READY_FOR_PICKUP`、`DELIVERED`、`CANCELLED` 和 `PICKUP_CANCELLED` 做标准化。未知值保持 `unknown` 并回退到去除 `script/style/template/noscript/footer`、隐藏节点和辅助文案后的订单可见文本。在获得真实退货样本前，不推断未观测到的退货状态枚举。

支付状态文本解析同样只能使用上述清理后的文本。“已收到付款”映射为 `paid`；`completed`、`delivered` 和 `ready_for_pickup` 先按已付款处理，不能再被隐藏脚本中的“退款”覆盖。订单总计标签和金额同时不存在时，表示官网未提供金额，金额与解析错误都保持 `NULL`；只有页面明确出现总计标签但值无法解析时才记录金额解析错误。

## 代理与重试

- 实际抓取要求 `PROXY_ENABLED=true`；关闭时不会自动回退为直连。
- [proxyManager](../../src/utils/proxyManager.js)是代理兼容门面，由 `PROXY_PROVIDER` 选择 `kdl_tunnel` 或 `kdl_private` Provider。隧道模式使用固定主备 Host、端口和鉴权，不维护出口 IP 内存池。
- `PROXY_PROVIDER` 只定义 Worker 启动默认值。管理员可通过系统页面请求切换 Provider；请求写入 PostgreSQL，Worker 在当前批次完成后初始化候选 Provider，并使用全局限流时隙访问 Apple 中国首页做连通性检查。检查成功才原子切换新任务，失败保留旧 Provider；未知 Provider 必须失败关闭，不能隐式回退为私密代理。
- 切换状态只保存 `requested/active/status/error/timestamp` 等非敏感元数据。隧道鉴权、私密代理提取 API URL/签名和代理密码仍只来自环境变量；两个 Provider 都配置完成时才具备一键切换条件。
- 初次请求和所有重试统一经过 PostgreSQL 全局时隙限流器。`CRAWLER_REQUESTS_PER_SECOND` 默认 5、最高 10，附加小幅随机抖动；不再逐订单固定等待 5–10 秒。
- `CRAWLER_MAX_RETRY` 默认 3，规范上最多 3 次；请求超时由 `CRAWLER_TIMEOUT` 控制。
- HTTP 541/429 归类为 Apple 风控，441 归类为代理频率超限，407 归类为代理鉴权故障，517 归类为代理建链失败；407 会持久化暂停领取新任务。私密代理在 541 时废弃当前 IP；隧道模式下每次重试生成新的 `sid`，因此重试会切换出口。
- 单次尝试的 541 只切换出口并进入下一次受限重试，后续尝试成功会清零连续风控计数；只有连续订单都在三次尝试中全部收到 541，达到 `CRAWLER_WIND_CONTROL_PAUSE_THRESHOLD` 后才暂停新任务。这样不会因某一个低质量出口误停整个 Worker，同时保留持续风控时的断路保护。
- Apple 订单入口会从 `www.apple.com.cn/xc/...` 跳转到 `secure10.www.apple.com.cn/shop/order/guest/...`。快代理控制台“每次请求换 IP”可能让同一次订单抓取的首跳和重定向使用不同出口。隧道 Provider 因此通过用户名参数为每次尝试生成最长 6 位随机 `sid`，默认使用 `period-0.5` 将该尝试固定在同一出口 30 秒，与当前请求超时对齐；下一次重试使用新 `sid`，在保持会话一致性的同时切换出口。
- 隧道默认使用兼容性优先的企业池 `type-std` 和质量优先 `pool-q10`；可通过 `KDL_TUNNEL_STICKY_PERIOD`、`KDL_TUNNEL_POOL_TYPE`、`KDL_TUNNEL_POOL_PRIORITY` 覆盖。`KDL_TUNNEL_USERNAME` 必须填写不带转发参数的基础用户名。
- 快代理隧道模式发送 `Connection: close` 和 `Accept-Encoding: gzip`，继续使用已验证的 Axios 原生代理配置；对照实验中自定义 `HttpsProxyAgent` 没有提高真实订单成功率，因此不引入第二套传输实现。用户名和密码仅允许通过环境变量注入，不写入日志或仓库。
- 私密代理按需调用提取 API，保留仍在冷却期内的坏 IP 隔离记录，不因刷新代理列表立即清空；过期冷却自动清理。代理池耗尽时重新提取，Provider 初始化至少取得一个格式合法且可用的候选代理。

### 2026-09-07 同订单集 A/B

用户授权的 83 条真实订单链接按偏移 `0–82` 分为 9 个不重叠批次执行；每条订单同时进入隧道和私密 Provider，奇偶订单交替决定限流时隙的先后顺序。所有请求共用隔离 PostgreSQL 全局限流状态，统一 1 RPS，每订单每 Provider 最多 3 次，不写业务数据库，不保存 HTML、订单链接或代理凭据。

- 隧道 Pro 成功 `75/83`（90.36%），首次/第二次/第三次成功 `39/27/9`；144 次尝试中的失败分类为响应流中断 43、HTTP 541 9、`ECONNRESET` 12、超时 5。8 个最终失败为响应流中断 6、HTTP 541 1、超时 1。
- 私密代理成功 `55/83`（66.27%），首次/第二次/第三次成功 `28/9/18`；184 次尝试中的失败分类为响应流中断 110、HTTP 541 9、HTTP 515 4、`BAD_REQUEST` 2、`ECONNRESET` 2、超时 2。28 个最终失败为响应流中断 23、HTTP 541 2、HTTP 515 1、`ECONNRESET` 1、超时 1。
- 配对结果为双方成功 48、仅隧道成功 27、仅私密成功 7、双方失败 1；所有成功响应的订单身份匹配，零商品订单为 0。隧道样本解析 `completed/paid` 58 条、`cancelled/unpaid` 17 条；隧道 75 条和私密 55 条成功响应都未提供订单总金额，保持 `NULL`。

结论仅适用于本次试用规格和测试时段。私密代理能够提取、认证和轮换，但主要失败是 HTTP 200 后响应流中断而非 541，增加短效 IP 数量不能替代链路稳定性；当前不应将私密代理作为默认线路。隧道 Pro 也未达到 100%，生产启用前仍需继续评估出口质量、传输稳定性和业务可接受阈值。

用户名参数、频率、资源池和 gzip 规则以[快代理隧道代理 Pro 开发手册](https://www.kuaidaili.com/doc/dev/tps_pro/)为准；407、441、517 的含义以[隧道代理 Pro 错误码](https://www.kuaidaili.com/doc/dev/tps_prohttpresponse/)为准。供应商文档不定义 541，因此本系统按 Apple 目标站风控响应处理，而不是误报为快代理鉴权或频率错误。

## 自动调度和暂停

`AUTO_ORDER_REFRESH_ENABLED` 默认 false。启用后 Worker 每 5 秒扫描到期调度，未付款或支付状态未知且具有合法订单链接的订单按 60 秒周期入队；已付款、退款、终态、校验异常或关闭自动刷新的订单不再生成分钟级自动任务。页面打开和人工任务仍可按权限提交并与活动任务去重。

任务、批次、逐订单新鲜度、Worker 心跳、全局请求时隙和暂停原因都持久化在 PostgreSQL。Worker 使用事务、订单行锁和 `FOR UPDATE SKIP LOCKED` 租约领取；租约过期后可由其他 Worker 恢复。管理员在排障后可通过恢复接口清除持久化暂停状态。

## 目标与唯一口径

所有来源及全部历史订单的业务 TAG 唯一取自 `orders.recipient_ref` 关联的 `recipients.tag`。订单主数据的 TAG 变化随档案实时生效，不复制回历史订单，不回退 `orders.tag`、`source_recipient_tag` 或来源快照。未关联显示“未关联取机人”，已关联但 TAG 为 NULL、空串或全空白显示“未设置 TAG”；缺失状态不作为真实 TAG 写入数据库或参与授权。非空 TAG 保留原值，按完整字符串区分大小写精确匹配，不拆分、不自动重命名或归并。

`source_recipient_tag`、AOS 来源记录及历史 `orders.tag` 保留作为来源／历史记录，不重写、不删除；来源差异可在详情查阅，不再提示用户必须将档案改成来源值。取机人 `channel` 字段仍为独立渠道属性，不替代本方案的 TAG。

## 影响范围与边界

| 模块 | 目标规则 |
| --- | --- |
| 订单列表、详情、导出、筛选候选 | 相同实时 TAG 与缺失状态；SQL 过滤在分页之前完成 |
| 仪表板、统计、渠道列表／明细 | 相同 TAG 聚合和权限交集，无标签不创建虚构渠道 |
| 用户订单授权及所有订单衍生入口 | 每次查询／操作按当前取机人 TAG 重新校验，包括附件、照片、库存来源、批次结果、后台发信等 |
| 本人付款任务及付款调度 | 任务权限、所有权与当前 TAG 范围取交集，关闭历史本人任务绕过 TAG 范围的例外；不额外要求仅操作付款任务者具有 orders.read |
| 付款自动分配 | 所有来源按当前 TAG 命中规则；候选处理人也须具有该 TAG 的访问范围；缺失或未命中规则延续普通分配集合，缺失 TAG 仅全部范围账号可接单 |
| 已有任务 | 不自动转派、不改处理状态／备注／付款人；改 TAG 后越界任务不再开放给旧范围处理人，由有权调度员按现有流程处理 |
| TAG 规则和用户授权配置 | 保留现有字符串集合，不猜测 AOS TAG 到档案 TAG 的映射，不自动扩大授权；候选改取档案 TAG，允许保留未命中配置并展示影响 |
| 渠道改名 | 更新取机人 TAG，并按现有事务同步用户授权；处理同名冲突、权限版本及审计，禁止覆盖来源快照 |
| 取机人及关联写操作 | 编辑 TAG、导入覆盖 TAG、删除档案、订单补关联等会改变历史订单范围，须防止有限范围用户通过基础资料写入扩权；影响订单范围的操作只向全部范围且具备原操作权限者开放，普通不影响范围的资料编辑保持原权限 |
| 企微通知 | 新生成通知的业务 TAG 使用当前档案值；已投递内容保留为历史证据，不补发历史消息 |

关联继续沿用姓名＋身份证后四位唯一匹配。没有证据、歧义或缺少尾号时保留未关联，本轮不批量猜测或修复关联。取机人 TAG 变化不改变订单身份快照、库存、金额或已分配任务的归属。

## 实现路线

1. 先更新 API、数据库字段语义、快照匹配、付款规则及渠道等受影响正文，明确本轮实施状态。
2. 抽取统一 TAG 的 JavaScript 序列化与 SQL 表达式／权限条件，避免跨模块复制回退规则。查询使用关联预加载或有界子查询，杜绝逐单取档案的 N+1。
3. 逐一替换 ORM 和原生 SQL 的旧 TAG 读取、过滤、统计、候选和鉴权；检索直读 `orders.tag`、`sourceRecipientTag`、任务所有权例外及原生 SQL，来源记录读取除外。
4. 前端共用缺失状态展示，保留既有列键／个人列配置；修改付款规则、授权和渠道的解释文案，移动端保持现有列表布局。
5. 自动分配在事务提交前复核档案 TAG、账号权限及任务状态，防止使用扫描时过期数据；异步订单操作在执行阶段重新鉴权。任何缓存不得延迟撤权生效。
6. 优先通过实时读取实现，无需批量改写订单或授权配置；确有结构／索引需求时另用正式 Migration（up/down），先更新数据库文档再实现。

## 验收标准

- AOS、邮件及其他来源均显示档案 TAG，来源与档案不同仍保持原始来源记录。
- 已有关联订单从 A 改 B 后，列表／导出／统计／渠道／付款页面同步变化，筛选候选不混入旧值。
- 未关联、档案删除、NULL／空串／空白 TAG 均无来源回退；全部范围可见，指定 TAG 范围不可见。
- A 范围账号立即失去订单读取、付款操作、附件、库存来源和批次结果访问；B 范围在既有功能权限内获得访问；混合越权批量操作整体拒绝。
- 自动分配覆盖所有来源、匹配与未匹配规则、缺失 TAG、无权限／满容量处理人、TAG 专属账号隔离和改 TAG 并发；历史已分配任务不自动转派。
- 取机人编辑／导入／删除／补关联不能成为扩权入口；渠道改名原子更新与冲突、审计失败回滚通过。
- PostgreSQL 集成覆盖真实 SQL 别名、聚合、分页／总数和权限交集；前后端 lint、相关及全量可执行测试、前端构建、文档检查通过。浏览器覆盖桌面和手机的正常与缺失状态。

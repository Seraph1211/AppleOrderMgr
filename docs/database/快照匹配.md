# 订单快照与基础资料匹配

> 状态：当前有效
>
> 最近核对：2026-09-17
>
> 基线：main@ec2c1d8 与当前未提交工作树
>
> 验证范围：本地工作树静态核对；未验证真实数据库、邮箱、官网和生产环境

## 设计目的

基础 Apple ID 或取机人资料尚未导入时，仍能保存订单。订单保存必要快照，外键允许为空；关联用于追踪和补充，不应使订单展示依赖基础资料永远存在。

## 当前匹配规则

| 对象     | 条件                                                                                     | 无法唯一匹配                           |
| -------- | ---------------------------------------------------------------------------------------- | -------------------------------------- |
| Apple ID | 去首尾空白、忽略大小写匹配订单自身账号                                                   | 保留来源快照，外键为空                 |
| 取机人   | 全名＋完整身份证优先；否则全名＋来源证件尾号；AOS 可用全名＋手机号，并校验已有邮箱不冲突 | 多候选、信息冲突或只有姓名时保持空关联 |

实现见[公共订单接入](../../src/services/orderIngestionCore.js)和[身份匹配](../../src/services/profileOrderMatching.js)。全名由姓＋名比较，不按首字拆分，支持复姓。尾号新增保存于 orders.recipient_id_last4；旧订单若未保留完整证件／尾号／AOS 联系证据，不会猜测补回，需后续提供可靠来源。

当前取机人与账号双向唯一，历史可多对多；订单外键独立于当前绑定。张三从 A 换为 B 后，张三统计其 A+B 订单，A/B 各统计自己的订单；A 下其他取机人的订单不计入张三。基础档案换绑不迁移历史订单。

历史空关联提供预览／选中执行，见[API 契约](../design/API设计.md)。先只读拉取候选，由用户确认后执行；事务中重新验证订单与档案，不覆盖已有关联、快照、TAG 或付款任务。

## 数据一致性

订单保存和邮件日志处于同一事务；订单号存在时返回已有订单。官网同步首次合并前保存非敏感导入来源快照；身份一致后采用官网有效商品、数量（含 0）、付款方式、金额等值，并展示来源冲突，缺失不覆盖。订单号不一致时拒绝跨单更新，详见[爬虫说明](../design/订单爬虫.md)。

快照不是实时 JOIN 的别名；不能假定修改基础资料会自动重写历史订单。渠道改名是明确的跨表 tag 更新，见[渠道管理](../design/渠道管理说明.md)。

2026-09-17 用户授权清理生产测试基础资料时，仅删除 Apple ID／取机人档案并将订单对应外键置空；订单敏感快照、商品、TAG、付款任务和历史记录保留。一次性脚本 `scripts/clearTestProfiles.js` 默认只读预览，执行需匹配资料指纹，在事务内检查外键及订单／付款任务完整性；必须先备份、隔离恢复演练，不作为日常批量删除接口。

## 安全与字段

密码及身份证快照由模型 setter 加密，getter 解密仅供受控服务处理。API 另行脱敏，隐藏前端列不能替代服务端权限控制。字段、类型、索引以[数据库架构](数据库架构.md)为准，本页不复制 SQL 建表与明文插入示例。

上述订单快照权限不变；基础资料页面经用户批准，具有 `apple_ids.read` 的用户可直接读取 Apple ID 密码，具有 `recipients.read` 的用户可直接读取取机人身份证与手机号。订单快照权限仍独立；当前密保、详细地址及完整导出另按本轮批准的专用权限契约开放，详见 API 契约。

## 待验证

多匹配、事后关联、补齐范围和真实数据库并发行为需独立验收；历史“自动匹配不会丢单”不作为可靠性承诺。

## AOS 来源匹配（2026-09-10 已确认，实施中）

AOS 使用显式姓、名、手机号查询全部候选，唯一命中且邮箱等其他已提供联系资料无冲突才关联。缺失或歧义不阻止订单保存。联系邮箱与下单 Apple ID 分别保存，账号密码仅进入加密订单快照，不更新基础账号。完整来源 TAG 独立保留并可见；订单已存在时只关联来源，不补空或覆盖。

# 日志查询页面 UI 重构开发提示词

```text
请严格按照《日志查询页面UI与交互重构需求.md》V1.0及同目录“日志查询UI参考/”中的20张已确认截图，完成日志查询页面的正式UI与交互重构，不重新设计或自由发挥。

需求文件：docs/planning/日志查询页面UI与交互重构需求.md。
实施范围仅为 /server-monitor/logs 内容区及其专属下拉、日期时间面板、更多筛选、采集详情、详情与上下文、来源浮层、专注阅读和标签管理弹层。其他页面UI，以及共享侧栏、顶栏、Logo、登录页、全局主题和全局字体一律不要改；MonitorLogs如被服务器监控页复用，原嵌入界面保持原样。新增样式必须局部隔离，不能整包复制预览前端或覆盖全局组件。

重点按文档落实：紧凑工具栏，“全部账号”在日期左侧，搜索框合理加宽，查询后不收起筛选；一个日期时间范围入口，左侧开始日期＋秒级时间＋独立日历，右侧结束日期＋秒级时间＋独立日历，互不串改，不把日期和时间拆散；支持北京时间连续跨日区间，例如2026-10-23 16:23:55至2026-10-25 12:23:20，包含中间整天与结束秒，不能按每天重复套用时段。确定只更新草稿，主查询才生效，取消恢复，倒序禁止。

详情与上下文严格按已确认的线上通栏排版：到顶到底，正文占主要空间；不增加默认元数据卡和重复选中原文，来源信息点信息按钮查看。保留账号／实例切换、选中定位、复制、换行、真实双向追加、去重、向前追加保持阅读位置、重试和分层Esc／焦点恢复。标签管理保留既有权限、逐行正式保存和版本冲突，不改业务规则。

先核对最新目标分支、有效API与共享组件调用方，保留其他未提交工作。预览是mock，不能视为真实接口已完成：跨日列表、同范围账号候选、完整条件绑定游标和上下文方向追加需要真实只读适配时，按需求第10节先更新契约再实现，保持旧调用兼容；不复制固定日期、样例数量、模拟错误、内存标签保存或演示认证。不要顺带改采集器、Worker、日志存储结构、保留期、权限或通知，也不要改写真实日志。

完成后逐项提交LOG-01～24验收结果，附1440×900、1265×712、768×900、390×844及375px检查和关键交互截图、真实查询边界测试、其他页面UI无变化的对比证据，以及修改文件清单、lint／构建／相关测试／docs:check结果。遵循项目AGENTS及文档维护规范；未通过或未验证的项明确列出，不能只凭mock截图报告完成。本次不执行提交推送或生产发布。
```

## 环境与原则

本地开发统一使用 [docker-compose.dev.yml](../../docker-compose.dev.yml)。宿主机只要求 Docker Engine 或 Docker Desktop、Docker Compose，不要求安装 Node.js、PostgreSQL 或项目 npm 依赖。

默认启动 PostgreSQL、数据库迁移、Express API 和 Vite 前端。邮件和爬虫会访问外部服务，必须通过 profile 显式启动；API 内始终设置 `RUN_WORKERS_IN_API=false`。

## 首次准备

从仓库根目录执行：

```bash
cp .env.example .env
```

`.env` 已存在时不要覆盖。至少替换以下配置：

| 配置                                               | 本地 Compose 用途                                                                                   |
| -------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `DB_NAME`、`DB_USER`                               | 初始化本地 PostgreSQL，并供 API、迁移和 Worker 使用                                                 |
| `DB_PASSWORD`                                      | 本地 PostgreSQL 密码，不能保留公开示例值                                                            |
| `POSTGRES_HOST_PORT`                               | PostgreSQL 映射到宿主机的端口，默认 5433                                                            |
| `JWT_SECRET`                                       | 至少 32 字符，不能包含示例占位内容                                                                  |
| `FIELD_ENCRYPTION_KEY`                             | 32 字节 Base64 或 Hex 密钥                                                                          |
| `ADMIN_INITIAL_PASSWORD`                           | 首次创建管理员使用，至少 8 字符                                                                     |
| `LOCAL_MOCK_USER_PASSWORD`                         | 仅在显式生成本地 Mock 工作人员时注入，至少 8 字符；不写入仓库                                       |
| `IMAP_*`、代理配置                                 | 仅启动相应 Worker 时使用；地址／域名白名单必须对应真实 From，不联调外部链路时保持禁用或使用测试账号 |
| `KDL_TUNNEL_USERNAME`                              | 快代理基础用户名，不附加 `period`、`sid`、`type` 或 `pool` 参数                                     |
| `KDL_TUNNEL_STICKY_PERIOD`                         | 单次抓取固定出口的分钟数，默认 `0.5`；重试自动生成新 `sid`                                          |
| `KDL_TUNNEL_POOL_TYPE`、`KDL_TUNNEL_POOL_PRIORITY` | 默认 `std`、`q10`，分别表示企业池与质量优先                                                         |
| `PROXY_API_URL`                                    | 私密代理 JSON 提取 URL；包含签名时按秘密管理，不写入日志或仓库                                      |
| `FANPROXY_TUNNEL_ACCOUNT`                          | 网帆隧道基础账号，仅填写账号值，不附加 `acc/cty/reg/sid` 参数                                       |
| `FANPROXY_TUNNEL_HOST/PORT/PASSWORD`               | 网帆隧道网关与账密；只注入 Worker 环境，不写入日志或数据库                                          |
| `FANPROXY_TUNNEL_COUNTRY/REGION`                   | 默认国家 `CN`，地区可选；Provider 为每次尝试自动生成新 `sid`                                        |

可以用以下命令生成本地随机密钥：

```bash
openssl rand -base64 48 # JWT_SECRET
openssl rand -base64 32 # FIELD_ENCRYPTION_KEY
```

Compose 会在容器内强制使用 `DB_HOST=postgres`、`DB_PORT=5432` 和 `DB_SSL=false`，不读取 `.env` 中面向宿主机工具的数据库地址。

开发 Compose 同时显式设置 `ALLOW_LOCAL_SENSITIVE_DISPLAY=true`。只有 `NODE_ENV=development` 且登录角色为 admin 时，Apple ID 页面密码、取机人页面身份证号、手机号和详细地址、订单页面手机号才显示完整值；operator、readOnly、未开启配置及 production 环境仍保持脱敏。该开关不修改数据库中的加密或完整数据，也不应用于生产 Compose。

## 启动完整开发栈

```bash
docker compose -f docker-compose.dev.yml up --build -d
docker compose -f docker-compose.dev.yml ps
```

首次启动时 `migrate` 服务会等待 PostgreSQL 健康后执行全部 Migration；成功后 API 启动，API readiness 通过后前端启动。

首次创建管理员需要显式执行：

```bash
docker compose -f docker-compose.dev.yml --profile tools run --rm seed-admin
```

需要为本地浏览器验收准备合成数据时，显式执行：

```bash
docker compose -f docker-compose.dev.yml exec \
  -e ALLOW_LOCAL_MOCK_DATA=true \
  -e LOCAL_MOCK_USER_PASSWORD='<至少 8 位本地临时密码>' \
  api npm run db:seed:local-mock
```

该命令只允许连接 `postgres`、`localhost` 或回环地址上的 development 数据库，使用事务写入 8 个 Apple ID、20 个取机人、48 个订单、3 个 Mock 工作人员和 30 个付款任务，并在部分订单上填写合成的外部付款人姓名。付款任务包含四种处理状态、24 个已分配任务和 6 个待分配任务；两个完整权限账号与一个仅查看本人任务账号可用于权限隔离体验。付款人不会登录系统，Mock 工作人员均为内部员工账号。数据带有稳定标识并可重复执行，不读取生产数据；脚本只重置 `mock_pay_*` 合成账号的密码，不修改 `admin`，Mock 订单关闭自动刷新，避免 Worker 访问虚构订单。

访问地址：

- 前端：`http://localhost:5173`
- API：`http://localhost:3000`
- API 存活：`http://localhost:3000/api/health/live`
- API 就绪：`http://localhost:3000/api/health/ready`
- 宿主机数据库：`localhost:${POSTGRES_HOST_PORT:-5433}`

Vite 容器通过 `VITE_API_PROXY_TARGET=http://api:3000` 访问 API。源码目录使用 bind mount，前后端依赖封装在开发镜像中，数据库、日志、上传、覆盖率和前端构建产物使用 Docker volume，不写入宿主机项目目录。

## 日常开发

查看日志：

```bash
docker compose -f docker-compose.dev.yml logs -f api frontend
```

代码修改由 nodemon 和 Vite 自动加载。新增 Migration 后显式重新执行：

```bash
docker compose -f docker-compose.dev.yml run --rm migrate
```

`package-lock.json` 变化后重新构建对应镜像并重建容器：

SheetJS 官方固定制品保存在 `vendor/`，构建安装前执行 `npm run security:verify-vendor`；不可遗漏该目录，也不从 npm registry 回退到旧版本。依赖详情见[第三方制品说明](../../vendor/README.md)。验证新依赖时先使用独立容器和合成数据，既有 Worker 重建仍需确认外部访问边界。

```bash
docker compose -f docker-compose.dev.yml build api frontend
docker compose -f docker-compose.dev.yml up -d
```

## 按需启动 Worker

只启动邮件 Worker：

```bash
docker compose -f docker-compose.dev.yml --profile email up -d email-worker
```

只启动爬虫 Worker：

```bash
docker compose -f docker-compose.dev.yml --profile crawler up -d crawler-worker
```

同时启动两个 Worker：

```bash
docker compose -f docker-compose.dev.yml --profile workers up -d email-worker crawler-worker
```

邮件 Worker 可能改变邮箱已读状态，爬虫 Worker 会访问代理与 Apple 官网。启用前检查测试账号、可选 `IMAP_ALLOWED_SENDERS` 精确地址、`IMAP_ALLOWED_SENDER_DOMAINS` 精确域名、`IMAP_MARK_SEEN`、`PROXY_ENABLED` 和 `AUTO_ORDER_REFRESH_ENABLED`。地址与域名白名单任一命中即可通过；域名只匹配 `@` 后完整值，不接受子域名或相似后缀。两项白名单都为空时 development 与 production 接受任意标准化 From，但仍执行主题、订单结构、字段和 Apple URL 校验。主题命中但 From 未授权的邮件进入 `manual_review` 并保留加密原文，不再直接丢弃。使用快代理隧道时还需确认 `PROXY_PROVIDER=kdl_tunnel`、主备 Host、端口和基础用户名；使用网帆隧道时确认 `PROXY_PROVIDER=fanproxy_tunnel`、Host、端口、基础账号和密码。两种隧道 Provider 都会为每次尝试生成随机 `sid`，日志与状态接口不得暴露组合用户名或密码。使用亦优 HTTP 时确认 `YIYOU_HTTP_PROXY_API_URL` 为官方 HTTPS 提取地址，且返回 `IP:端口 用户名 密码` 换行文本；5 分钟节点建议保持 `YIYOU_HTTP_PROXY_TTL_MS=240000`。未设置 `PROXY_PROVIDER` 时默认使用首选 `yiyou_http`；本地示例也显式配置该值。需要从管理页四方一键切换时，必须预先配置两种隧道变量、快代理私密 `PROXY_API_URL` 和亦优提取 URL；Worker 在批次边界验证目标 Provider 后才确认切换。首选配置不开启自动跨供应商降级；修改环境变量仍需按授权重建 Worker，已经配置完成的 Provider 运行时切换不重启进程。

邮件 Worker 启动会回查最近 24 小时，之后每 10 分钟补查 30 分钟，并可能按 `IMAP_MARK_SEEN` 修改终态邮件的已读标记。启用 profile 前必须先执行最新 Migration；不要为验证邮件页面直接连接真实邮箱。Migration 可逆性和邮件并发/事务测试使用精确命名的可丢弃数据库，例如：

```bash
docker compose -f docker-compose.dev.yml exec -T -e DB_NAME=<隔离库名> api npx sequelize-cli db:migrate
docker compose -f docker-compose.dev.yml exec -T -e DB_NAME=<隔离库名> api npx sequelize-cli db:migrate:undo
docker compose -f docker-compose.dev.yml exec -T -e DB_NAME=<隔离库名> -e RUN_EMAIL_DB_INTEGRATION=true api npx jest test/emailProcessing.integration.test.js --runInBand --coverage=false
```

创建和删除隔离库时只能使用已经确认的具体名称，不能把当前开发库、共享库或生产库用于该测试。

## 容器内检查

```bash
docker compose -f docker-compose.dev.yml exec api npm run lint
docker compose -f docker-compose.dev.yml exec api npm test -- --runInBand
docker compose -f docker-compose.dev.yml exec api npm run docs:check
docker compose -f docker-compose.dev.yml exec frontend npm run lint
docker compose -f docker-compose.dev.yml exec frontend npx vite build
```

## 停止与重置

停止容器并保留本地数据库和运行数据：

```bash
docker compose -f docker-compose.dev.yml down
```

完全重置本地 Docker 数据：

```bash
docker compose -f docker-compose.dev.yml down --volumes
```

`down --volumes` 会永久删除本地 PostgreSQL、上传、日志、覆盖率和前端构建产物 volume，只能用于确认可丢弃的开发环境。生产部署继续使用[生产环境部署指南](../deployment/生产环境部署指南.md)，不能套用本地 Compose 的数据库重置命令。

另发现 605 不需要登录 Apple ID 即可读取完整访客详情，这是降低登录频次的后续验证方向。当前产品尚未统一改为访客优先，不把单个样本推广为全库都可以免登录。

## 代理提取与兼容根因

使用用户已有流量套餐，选择国内、单个 IP、JSON、600 秒、账号密码验证；未充值、购买或更改白名单。后台当前显示剩余流量 11.03G，有效至 2027-09-14，不属于本次余额耗尽。

同时检查了已购静态订单：两份静态直连套餐分别于 2026-09-10、2026-09-26 到期，当前没有可直接使用的有效静态订单。本轮动态套餐的结果不能外推为亦优所有产品均无固定出口能力，也未擅自续费或采购静态资源。

首个新节点的自有站点 curl 检查为 CONNECT 200／HTTPS 200，但原浏览器实现的 605 试验 `run-45` 在首次导航失败：`PROXY_CONNECTION_FAILED`，只消耗 1 个请求许可，没有提交 Apple 密码。

对该节点进行不含 Apple 账号的 CONNECT 对照：

| 向代理发送的认证方式 | 结果 |
| --- | --- |
| 等待上游挑战，首个 CONNECT 无认证 | HTTP 502，没有 `Proxy-Authenticate` |
| 首个 CONNECT 预先携带现有代理认证 | HTTP 200 Connection established |

现有浏览器依赖标准 407 挑战补交代理凭据，因此此类节点存在鉴权协议兼容问题。既有网帆成功路径仍使用原模式；不能将所有 502 或之前的 407 都归为同一个原因。

新增 `officialOrderProxyTunnel.js`，仅在代理私密配置显式设置 `preemptiveAuth: true` 时启用：

- 监听采集容器回环地址的随机端口，仅接受官方白名单域的 443 CONNECT；其他目标和普通 HTTP 转发被拒绝。
- 预先向已配置的上游提供代理认证，不转发客户端认证头；Apple TLS 字节透传，由浏览器校验证书。
- 15 秒建立连接超时、连接数量限制，采集退出时关闭全部通道；无持久服务或对外开放端口。
- 上游 407／429／541 与 Retry-After 仍进入原暂停机制；其他连接异常明确失败，不自动重试。
- 现有请求许可、账号互斥、登录冷却、单日订单次数及累计预算全部保留。没有清空首个失败节点的暂停；使用另外提取的新节点进行后续验证。

## 后续边界

优先扩大访客免登录样本，严格验证订单身份和完整商品；再决定访客优先／登录回退策略。确需登录的订单应按账号分组复用服务器会话、使用独立登录预算并保留官网验证暂停。代理需增加有效期准入、受限续取和出口变化观测；已取得端点或某次 HTTP 200 不构成稳定粘性验收。

当前不将静态十分钟节点长期写入默认配置，不恢复全量队列，也不因修复认证而清空失败账号的保护。待固定出口或减少登录的路径通过事前定义的小批量验收后，再恢复剩余范围。

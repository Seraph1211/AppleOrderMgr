# 表格列配置规范

> 状态：当前有效
>
> 最近核对：2026-09-21
>
> 基线：main@0fd7f80 与当前未提交工作树
>
> 验证范围：本地工作树静态核对；未验证真实数据库、邮箱、官网和生产环境

## 范围与代码来源

订单、Apple ID、取机人页面使用可配置列。列键、标签、默认显示、宽度和 sensitive 标识集中在[tableColumns.js](../../frontend/src/constants/tableColumns.js)，配置交互见[ColumnConfigModal.jsx](../../frontend/src/components/ColumnConfigModal.jsx)，持久化见[useColumnConfig.js](../../frontend/src/hooks/useColumnConfig.js)。本页不复制三份完整列数组。

## 当前存储

localStorage 键为 `columnConfig:${tableName}`；tableName 由调用页面传入。保存结构包含 version、columns、updatedAt，columns 元素为 key、visible、order。

- 未保存时采用默认列及 defaultVisible。
- 已保存时按 key 和 order 恢复可见性及顺序；新增列采用默认可见性并追加到普通列末尾，固定操作列仍位于末尾；失效旧列不继续使用。
- 恢复默认会移除对应 localStorage 项。

## 交互与安全规则

配置页面遵循[前端设计规范](../development/前端设计规范.md)。显示、隐藏只影响客户端布局，不授予读取敏感字段的权限。历史列定义仍存在密码、身份证等键，是否返回或展示必须服从当前 API 脱敏契约。

订单列表的来源冲突提示固定在每行最前面，不参与可配置业务列的排序和隐藏。无冲突时留空，有冲突时显示 Lucide 叹号；悬停、键盘聚焦或触摸可查看服务端已脱敏的差异。浮层不得被横向滚动容器裁切。

## 验收要点

订单管理的订单号单元格依次展示系统订单 ID、Apple 订单号和入库来源。系统订单 ID 使用列表接口已有的 `id`（`orders.id`），以“订单 ID：数字”加粗展示，与付款调度页面一致；不使用付款任务 ID 或当前页序号。沿用原 `orderNumber` 列键及已保存的列配置。

2026-09-17 起，订单管理、付款调度与付款任务列表按完整商品名称与型号聚合展示数量，保持首次出现顺序，示例 `iPhone 18 Pro Max 512GB 冰川蓝色 ×2`。只改变列表展示，不改写原始商品明细、官网数据、订单详情或复制契约；0 保留，未知或非法数量显示“待核实”，不得默认按 1 计算。

订单管理提供当前页勾选。具有 `orders.refresh` 或 `orders.export` 任一权限即可显示复选框，但两个动作保持独立：批量刷新只由 `orders.refresh` 控制，选中导出只由 `orders.export` 控制，任何一项都不得授予另一项。翻页或筛选变化清空选择；刷新提交失败的项保留选择以便重试，成功入队或合并不代表官网同步成功。沿用异步刷新及 PostgreSQL 全局限流，不直接在前端并发抓取官网。

选中导出只覆盖当前页勾选项。首次打开字段弹窗以当前可见且允许导出的业务列为默认，成功导出后把字段选择保存在浏览器 `orderExportFields:v1`；后续可全选、清空或逐项调整。显示列配置不改变服务端导出白名单和权限，密码、身份证号、订单链接及付款截图不提供导出。

验证订单、Apple ID、取机人三个页面分别保存可见性和顺序、跨页面返回、刷新、新增默认列、损坏配置和恢复默认。共享合并函数必须覆盖三套真实列定义，不能只验证取机人页面。权限用例需要验证网络响应与 DOM，不仅检查列是否隐藏。

### 2026-09-21 订单列表默认字段与邮件来源

未保存个人列配置或恢复默认后，业务列依次为：订单号、订单状态、最后更新时间、商品、取机人、TAG、下单时间、取货信息、付款方式、创建时间。其余业务列默认隐藏，操作列仍固定在右侧；已保存的个人可见性和排序保持不变。

“最后更新时间”读取 `email_lifecycle_updated_at`，表示最近一次邮件解析后归并应用到订单的时间；缺失显示“尚未更新”，不回退到官网爬取时间、邮件发信时间或通用更新时间。为保留个人配置，沿用历史列键 `lastOfficialUpdatedAt`。“TAG”沿用 `recipientTag`，取值与权限不变。“取货信息”沿用 `emailPickupInfo`，表头右侧 Lucide 叹号悬停提示“基于邮件数据更新”。订单状态表头右侧同样提供叹号，逐行说明“订单已确认：已下单，待付款”“处理中：订单已付款”“可取货：订单可取货”。两个表头图标保留普通箭头鼠标，使用立即显示的自定义浮层，不使用浏览器原生 `title` 延迟提示；支持键盘聚焦和点击显示、Escape 关闭，浮层挂载到页面根部以避免表格横向滚动裁切。

订单管理列继续沿用 `emailOrderStatus` 列键以保留个人配置，但展示 `display_order_status`：已确认且未确认付款的订单，在完整来源下单时间满 30 分钟后显示“已过期”；未知下单时间不推断。“已取货（邮件推定）”在徽章中简写为“已取货”，表头说明保留邮件推定来源。页面每 15 秒自动重新读取，打开中的详情弹窗同步当前列表状态。

导出字段弹窗中原官网时间明确标为“最后官网更新时间”，仍使用原导出字段及官网数据，但不再由邮件更新时间列自动勾选；本次不扩展后端导出契约。列表继续不提供 `recipientPhone` 和旧 `lastCrawledAt` 可配置列，取机人管理电话列不变。

### 2026-09-17 基础档案列与详情

Apple ID 只展示 notes 备注，新增当前绑定列；取机人新增真实联系电话、备注、当前绑定及可选关联密码列。列默认可见性使用 defaultVisible，兼容旧保存配置，旧 nickname 列退出。订单数量可进入独立外键筛选的订单明细；详情提供当前关联和最近绑定历史。密保通过有权限的详情请求读取，不随列表返回。新增与编辑共用表单，姓／名不重新拆分；状态与当前绑定独立展示。

取机人无本地保存配置时，默认顺序为姓名、身份证号、TAG、渠道、绑定 Apple ID、真实联系电话、状态、订单数、备注，之后为下单手机号等补充列和固定操作列。渠道是独立于 TAG 的单值档案标签；旧保存配置通过列键合并后将新增渠道列追加到普通列末尾，可由用户重新排序或恢复默认。原“联系电话”列名改为“下单手机号”，与真实联系电话明确区分。

Apple ID 无本地保存配置时，默认可见顺序为 Apple ID、密码、状态、当前绑定、国家地区、订单数、最后下单和固定操作列；备注、密保与时间字段默认隐藏。状态使用 badge 样式。当前绑定有取机人时直接显示姓名，未绑定显示“未绑定”。`isModified` 列已退出并由正式 Migration 删除数据库字段。

2026-09-21 订单列表的商品信息单元格补充映射订单金额及“按官方售价计算”，不新增列配置键；金额来源为 order_amount，未知显示“待确认”，0 显示 ¥0.00。付款两页同样在商品信息下展示金额。

# 库存页面空白与前端懒加载缓存修复

> 日期：2026-10-30  
> 环境：`PP_CloudServer`、`https://apple.godp.me/stock`  
> 生产版本：`20261030-stock-cache-hotfix-r2`（侧栏版本 `v20261030132230`）

## 现象与影响

“库存管理”进入后只显示空白页，其他已打进入口包的页面仍可打开。公网 HTML、库存懒加载 JS、其依赖 JS/CSS 和 API readiness 均返回 HTTP 200，因此仅检查状态码不能发现该故障。

浏览器控制台显示 React #321（Invalid Hook Call）。调用栈同时出现当前入口包和上一版入口包，库存模块在渲染阶段终止；后续 `removeChild` 错误是 React 清理失败的次生现象。

## 根因

2026-10-29 的前端增量发布复用了同一个库存懒加载 URL，但替换了该 URL 的文件内容：

- 旧发布中的库存包导入旧入口包；
- 新发布在相同库存 URL 下改为导入新入口包；
- Nginx 对 `/assets/` 返回一年 `immutable` 缓存，已有浏览器继续使用缓存中的旧库存包；
- 新 HTML／入口包与旧库存包组合后加载两份 React，触发 Invalid Hook Call。

原发布门禁只解析和校验 `index.html` 直接引用的 JS/CSS，没有递归校验懒加载依赖，也没有阻止相邻版本以同一 immutable URL 发布不同字节，因此门禁、入口摘要和 API 健康均可通过。

## 修复

1. 以原生产静态树制作仅前端修复版本，为入口包和库存懒加载包使用此前从未发布过的新 URL，并同步修改二者的循环模块引用；没有修改库存业务代码、API、数据库、配置或 Worker。
2. 使用正式 `productionFrontendGate.py` 依次执行 `prepare`、实际 Nginx 身份 `check`、`switch`、`verify`；完成缓存修复验证后，将 `current` 从 `20261029-orders-ui-followup` 原子切换并最终收敛到带新版本标识的 `20261030-stock-cache-hotfix-r2`。
3. 扩展发布门禁：从 HTML 入口递归解析 Vite 静态导入、动态导入和依赖预载表，缺失懒加载文件立即拒绝；切换前比较候选与当前版本的可达资源，同一 URL 字节变化返回 `IMMUTABLE_ASSET_REUSED`，不得切换。

## 验证

- 门禁专项 31 项通过，1 项仅在设置真实 root／Nginx 用户时执行；新增覆盖缺失懒加载文件、递归 HTTP 校验、同 URL 变更阻断和同字节共享放行。
- 前端 ESLint 0 error（保留 15 条既有 warning），Vite 正式构建通过；本地候选的 `prepare`／`check --permissions-only` 通过。
- 生产两个实际读取身份均可读取 29 个前端文件；正式切换和再次 `verify` 均通过，递归校验 12 个可达资源及首页、订单页、登录页、API readiness。
- 已登录 Chrome 普通刷新后，入口使用新 URL，库存标题、状态计数、筛选、表格、分页和行操作完整渲染；新 URL 范围内无 error／warning。此次只读浏览器验收未点击写操作。
- API 持续 healthy、数据库 `db=ok`；API、邮件、订单邮件、库存、监控通知和企微 Worker 保持运行，未重启服务，未执行 Migration 或生产业务写入。

## 回退

若新静态树出现问题，回退目标为 `20261029-orders-ui-followup`，仍须通过门禁 `switch`，不得直接改写 `current`。旧版本存在已确认的缓存碰撞，回退只能用于短时止损，不能视为库存页已恢复；业务 API、数据库和 Worker 无需随此前端修复回退。

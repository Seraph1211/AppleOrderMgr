## 方案概览

第一版收敛为**一张库存台账，一台手机一条记录，以 SN 唯一识别**。内部人员在同一页面完成入库、售出和货款状态更新，并有独立的“补录历史销售”按钮。主要解决每台手机在哪里、是否已售、谁卖的、卖了多少钱、货款到哪里了。

范围只覆盖重庆自己持有及销售的机器。电脑为主要操作端，手机可查库存、登记入库、登记售出和更新货款。日常操作不要求先建销售单、接单占用、挑货或做到账分配。

本轮已经明确：SN 唯一、设备关联原苹果订单号、在库与已售信息、成本毛利、可选费用及照片备注、历史销售直接补录。用户补充不需要记录收货人，需要记录实际交货或寄件的人；该角色命名为“出货人”（出库经办人），与销售人分开。用户已确认本文方向及默认规则，并要求标题去掉地域名称；仓库按实际配置，仍先覆盖当前自有仓库业务。

## 一个入口和两个业务状态

菜单保留一个“自有库存”入口，页面提供“在库／已售／全部”三个视图；默认进入“在库”。“销售出货”和“货款回款”不再作为简化版的独立日常入口。

| 视图 | 主要展示                                                   | 常用操作                           |
| ---- | ---------------------------------------------------------- | ---------------------------------- |
| 在库 | SN、订单号、型号／容量／颜色、仓库、入库日期               | 入库、登记售出、更改仓库、编辑资料 |
| 已售 | SN、订单号、规格、销售日期、销售人、出货人、售价、货款状况 | 更新货款、补资料、查看或更正记录   |
| 全部 | 每台机器及其在库／已售状态                                 | 按 SN 或订单号查找完整记录         |

页面顶部提供“入库登记”和“补录历史销售”按钮。查看单台详情时可见成本、毛利、额外费用、照片、备注和修改记录。支持按规格、仓库筛选；已售视图增加销售人、销售日期和货款状况筛选。仓库库存数量按实际在库机器计算，不再显示接单占用或可接单数量。

手机沿用相同台账，保留 SN、规格、状态及当前视图的重要信息，其他字段展开查看。表单可滚动完成提交，拍照和手工输入都能完成 SN 录入；识别候选须人工确认后才保存。

## 每台手机记录的字段

| 分组     | 字段                       | 填写规则                                                                                         |
| -------- | -------------------------- | ------------------------------------------------------------------------------------------------ |
| 设备身份 | SN                         | 必填、全局唯一；同一台手机在库、售出和历史补录共用一个档案                                       |
| 设备身份 | 订单号                     | 指当初购买这台手机的苹果订单号；允许留空、后补；多台手机可关联同一订单号                         |
| 设备身份 | 型号、容量、颜色           | 必填，优先选择已有规格；不要求操作员先到另一页面建立商品资料                                     |
| 在库     | 入库日期                   | 正常入库必填，表示实际收货日期；默认今天，可改为真实历史日期                                     |
| 在库     | 所在仓库                   | 正常入库必填，只精确到重庆哪个仓库；首期支持现有两个仓库                                         |
| 成本     | 官网成本                   | 按拿货时对应规格的官网售价保存；可带出参考值供核对，允许待补，不因以后官网改价重算历史           |
| 已售     | 销售人                     | 登记售出必填，可为内部或外部人员；可选历史姓名或填写新姓名，不要求建立登录账号                   |
| 已售     | 售价                       | 逐台必填，精确到分；批量可统一填写，再修改个别机器                                               |
| 已售     | 出货人                     | 登记售出必填；实际从仓库交货给买家或办理快递寄件的人；可选历史姓名或直接填写，可与销售人为同一人 |
| 已售     | 销售日期                   | 必填，表示真实售出日期；默认今天，允许补录历史日期                                               |
| 已售     | 出库仓库                   | 正常售出时自动保留原所在仓库；历史补录不知道时可留空                                             |
| 货款     | 货款状况                   | 正常售出必选，规则见下节；不能从“已售”自动推定“已收款”                                           |
| 货款     | 实际代收人                 | 选择“销售人已代收待转回”时显示，默认带出销售人，可改为实际收款人                                 |
| 货款     | 收款日期、公司到账日期     | 对应事件发生时填写；可与销售日期不同，历史日期不清楚可待补                                       |
| 可选补充 | 额外费用                   | 快递、跑腿等已知费用合计，按单台保存，允许后补；不要求创建费用单                                 |
| 可选补充 | 照片、备注                 | 按需填写，不作为入库或售出的前置条件                                                             |
| 自动记录 | 毛利、录入人、修改人及时间 | 毛利由售价减官网成本计算；操作记录由系统自动保留                                                 |

“订单号”是唯一的订单关联字段，表单不另设“来源订单”。订单暂时对不上仍可正常入库、售出；后补时保留该台手机已有的库存和销售记录。若系统已有相同 SN 的取货登记，应复用设备身份，而不是新增一台手机。

额外费用单独记录，不改变毛利，也不抵扣销售人应转回的货款。需要查看时，可在详情展示“扣已记费用后利润＝毛利－已记费用”，不称为净利润。成本未补时毛利显示“待补成本”；费用空白显示“未录入”，不强制做费用完整性确认。

## 日常操作

### 入库登记

填写或扫描 SN，选择规格和仓库，核对入库日期后保存。订单号、成本、照片、备注可在已知时填写，也可后补。支持一次录多台相同规格，仍按不同 SN 分别建档；重复 SN 明确提示已有记录。

收货页面中的规格选择、姓名输入等应就地完成，不要求使用者先逐项配置销售人、出货人和复杂基础资料。仓库名称由管理员做一次简短设置。

### 登记售出

从在库列表选一台或多台，填写销售人、出货人、销售日期、逐台售价和货款状况，一次保存后转入已售列表。正常销售只允许选择重庆在库机器；两个仓库可以同时选取，每台保留自己的出库仓库。

批量操作用于减少重复填写。相同销售人、出货人和日期可以统一带入，但每台的售价、费用和货款记录独立保存。保存前统一检查全部 SN；任一台已被别人售出或信息无效，整批拒绝并指出问题，避免重复售出或只保存一半。

### 更新货款

在已售列表直接更新单台货款状态，也可勾选多台一起更新。仅对已核实收到全款的机器标记公司已到账，不要求建立到账单、上传回单或执行金额分配。

| 货款状况           | 含义                                               | 需要填写的信息                                   |
| ------------------ | -------------------------------------------------- | ------------------------------------------------ |
| 未收款             | 买家尚未付款                                       | 暂无收款记录                                     |
| 销售人已代收待转回 | 买家已付全款给销售人或其他代收人，公司还未收到全款 | 实际代收人；收款日期已知时填写                   |
| 公司已到账         | 公司直接收到买家全款，或收到代收人转回的全款       | 到账日期；直接收款或代收转回的去向说明沿用原记录 |
| 待核实             | 仅用于历史销售补录时，尚未核实货款情况             | 后续核实后修改，不能默认算作未付款或已到账       |

例如：昨天卖出三台，销售人代收，三台都标记“销售人已代收待转回”；今天全款转回，勾选这三台更新为“公司已到账”，到账日期填今天。销量和毛利仍属于昨天，不能因为今天到账再计一次销售。

**首版按单台全额货款维护。** 同一笔转回覆盖多台时，只需勾选已核实全款的机器；不做跨单金额核销或某一台的部分到账分摊。若实际只收到某一台的部分货款，不能标记为“公司已到账”，先保留待转回状态并备注，本版不据此自动计算剩余金额。该限制已随本方案确认，页面不能把备注中的部分金额误计为已全额到账。

### 更改仓库和资料更正

在库机器可直接选择新的重庆仓库，按实际到位后更新，自动记录原仓库、新仓库、操作人和时间；不要求建立转运单。该简化规则不追踪途中物流状态。

录错 SN、订单号、规格、日期、售价、销售人、出货人或货款状态时，可从详情更正。普通资料直接编辑；影响已售金额、货款或状态的更正需要简短确认和原因，系统保存前后值，不要求使用者理解复杂纠错流程。误标已售且实物仍在仓时，允许有权限人员更正回在库，同时处理该次误录销售和货款事实；真正的退换货仍不属于本版。

## 补录历史销售

在台账顶部直接点击“补录历史销售”，无需先建库存，也无需准备 Excel。表单沿用正常售出字段，并增加设备 SN 和规格输入。订单号、原入库日期、出库仓库、照片或费用暂时不清楚时允许后补。

历史销售人或出货人暂时查不清时，允许明确标注“待补”，不自动填成本次录入人；正常新销售仍要求记录两者。

保存后直接进入已售列表，标明“历史补录”，并分别保留真实销售日期和本次录入时间。已知收款情况按实际填写；不清楚时选择“待核实”。本次补录不能改变当前仓库的现货数量，也不能把历史销售日期替换成今天。

如果 SN 已存在，先提示并打开原记录，不重复建档。现有在库机器应走“登记售出”；已有已售记录应走编辑，不能再次补录一笔。已有取货身份但未进入库存的机器可在核对后复用其身份形成历史已售记录。

## 本版暂缓的内容

暂缓长沙明威等外地代卖、全国直发、接单预占、分步挑货、转运收发、独立费用单、客户付款单、到账分配、复杂对账报表和真实退换货。历史补录以页面表单为主，Excel 批量导入不作为本版使用前提。

延续内部人员操作、管理员全量查看的权限边界；不新增外部销售登录流程。已有金额和订单访问权限继续生效，不能因界面简化而扩大权限。原取货记录继续负责取货及来源登记，不以邮件状态或取货扫码自动认定重庆实物已经入库。

旧版复杂功能由本方案替代，简化版是唯一日常库存入口。已有记录保留；本方案不授权删除旧表、清空资料或把已有代卖机器混入自有库存台账。生产变更按用户随后追加的发布授权执行，范围与结果见生产发布记录。

### 旧版的退出与复用

用户已明确担心两套版本冲突。本轮在原库存模块上改造，不另建一套设备档案或并行运行的库存产品：

- 旧“销售出货”“货款回款”页面退出日常使用，原链接转到简化台账对应视图；未再被使用的旧前端页面及专属流程组件清理。
- SN 身份、订单关联、取货扫码、权限、防重复和事务等共同基础继续复用，同一台手机仍只有一份档案和销售事实。
- 旧表及已有记录不因简化而删除。确有历史事实读取、原操作重试或数据一致性依赖的后台逻辑可以保留，开发记录须说明原因；不再将旧完整版本作为第二套产品持续扩展。
- 验收检查导航、旧链接、刷新读回与新旧记录的一致性，确认没有重复库存、重复售出或两个入口出现相反货款状态。

## 验收时应看到的结果

| 场景                   | 预期结果                                                     |
| ---------------------- | ------------------------------------------------------------ |
| 同一订单两台手机       | 两条不同 SN 记录，可显示相同订单号                           |
| 订单号未知             | 可以入库、售出及历史补录，后补订单号不丢原记录               |
| 两个重庆仓库           | 能按仓库查在库机器；更改仓库后只在新仓计数                   |
| 一台或跨仓多台售出     | 一次填表保存，各台保留售价及原仓库，不出现接单、挑货前置步骤 |
| 重复 SN 或多人同时售出 | 不新增第二台，也不重复扣库存；批量失败不留下部分写入         |
| 销售人次日转回         | 销售日期保持，货款从代收待转回变为公司已到账；费用不抵货款   |
| 成本和费用             | 毛利按官网成本计算；费用可后补；缺成本不显示零成本毛利       |
| 历史补录               | 直接显示已售，保留真实销售日期，当前现货数量不变             |
| 修改误录               | 有权限人员可更正，修改记录保留，相关库存与货款保持一致       |
| 电脑和手机             | 同一台账可完成四个入口操作；手机短视口也能看到并点击提交     |

以上标准已按本轮独立证据核对，不沿用旧完整版本的测试通过数量作为简化版已通过的证明。

## 已确认的开发安排

2026-10-04 用户已确认方案，授权补充必要细节后安排开发，并明确要求标题去掉“重庆”。文件名、标题和索引统一为“自有库存简化版方案”；地域仅作为当前业务范围背景，页面、仓库名称和代码不额外写死地名。

角色采用“销售人”和“出货人”：销售人负责成交，出货人负责实际交付或寄件，两者可以是同一个人；系统自动记录录入人。收货人、买家和客户名称不作为本版独立字段。首版按单台全额货款维护，支持多台一起更新；历史不明情况使用“待核实”。

开发延续现有独立工作树，复用设备身份、订单关联、扫码、金额和权限能力。旧数据及完整版本的必要兼容逻辑保留，不清空真实资料。实现与主 Agent 独立验收已完成，发现的问题均交回实现 Agent 修复并复测。用户随后追加授权先合入主分支，再发布生产；已于2026-10-04完成主分支推送和API／前端切换，模块已启用。生产不造仓库或业务测试记录，实际仓名需用户配置；备份、演练、技术检查及真实业务验收边界见[生产发布记录](../archive/2026-10/2026-10-04-自有库存简化版生产发布记录.md)。

## 开发细化与验收补充

以下规则只为落实已确认的简化流程，不新增面向用户的业务步骤：

1. 单台详情、在库列表、已售列表和筛选始终围绕同一个设备身份。页面默认展示逐台明细，不再默认展示规格汇总或要求先建销售单。旧代卖、在途、待登记身份不混入简化版现货；历史自销记录可按实际事实查看。
2. 订单号允许先保存为待关联的原订单号码；系统有匹配订单时按既有权限核对关联，不能因订单暂未导入而阻止正常记账。后补或更正不复制设备、不隐式改变原规格、成本或销售事实。
3. 新增规格、填写销售人和出货人都在当前表单完成；已有项可搜索复用。前端不出现内部编号、原始 JSON、价格版本或客户建档等技术前置输入。正常新销售的销售人、出货人必填，历史补录允许明确待补。
4. 直接售出由后台在一笔事务内检查全部设备、写入销售并更新库存及货款事实。批量任一项失败整笔回滚；重复点击或网络中断按同一请求重试，不再生成第二笔。
5. 每台金额保存到分，成本快照、售价、额外费用各自独立；费用字段指本台合计，不把同一批的一笔总费用重复算到每台。额外费用只按单台填写，批量默认留空；成本缺失继续标记待补。
6. 货款状态和详情必须来自同一份事实。代收转回可跨日，费用不抵扣货款；更正售价、代收人或货款状态时同步处理受影响记录，不能只修改页面标签。旧记录如有部分到账或跨单分配，保留已有事实并明确限制不适用的简化操作，不擅自认定全额到账。
7. 正常入库日期、销售日期及已知收款日期以用户输入的实际发生日期为准，采用北京时间；系统录入时间另存。只知道日期时不强制填写秒。历史日期或历史人员不明时不得自动编造为今天或当前操作员。
8. 历史销售补录直接生成已售事实，不能先生成一笔现货再扣减，也不受原完整版本切换时点的人工配置前置阻碍。重复 SN 展示已有记录；在库、在途或已售冲突不得静默覆盖。
9. 录错更正保留前后值和操作人。把误售更正为在库，仅限已核对实物仍在仓的错误记录；相关销售、费用、货款事实须一致更正，不作为真实退货功能。单台资料及仓库更改也做权限和版本检查。

## 运行前提

宿主 Linux、Python 3.6+、Docker、curl，以及既有独立 Gate PostgreSQL。浏览器镜像固定为 `mcr.microsoft.com/playwright@sha256:eff16c30e6f3f4af0a03fa4b706120d5e9b0891c344a27d64559aff5900a4a27`，使用其中的 Node.js 22+ 和 Chromium headless shell。`depsDir` 提供与项目锁文件一致的 Node 依赖；`runtimeDir/venv/bin/python` 预装 `scripts/officialOrder/requirements.txt` 中固定的 curl_cffi。采集时不联网安装或升级依赖。

生产应用须包含 `StockUnit`、`StockOperation`、`stockCommandService.runCommand/lockStock`、`stockUnitService.ensureUnit/bindSource`，并已通过现有正式库存 Migration。该 Worktree 基线早于生产库存模块，因此以运行时契约检查为准；旧应用不具备该接口时不能运行绑定。不要通过 `sync/alter` 或复制零散模型补齐生产结构。

Gate 沿用 `apple-account-research-db/apple_account_research` 的 `budget`、`runs`、`collector_attempts`、`collector_pauses` 和全局锁，不创建新空库规避既有历史。内网为 `apple-account-research-internal`，代理出口网络为 `apple-account-research-egress`。保护包括全局约 4.5 RPS、账号互斥、15 分钟登录冷却、滚动 24 小时 10 次历史运行、单次 200 请求／180 秒网络许可窗口、宿主采集进程 240 秒上限、单订单每批最多 3 次完整尝试。累计预算是共享上限，不能重置已用值。

配置文件及代理文件权限必须为 `0600`。代理文件包含 `host`、整数 `port`、`username`、`password`、`provider: "iproyal"`、`preemptiveAuth: true` 和连接上限；秘密只保留在受限服务器文件。IPRoyal 的实际创建时间写入 `createdAt`，恢复时不能改成当前时间假装续租。推荐配置 `iproyalTemplate` 指向已有代理私密配置：调度器按 [IPRoyal 官方会话参数](https://docs.iproyal.com/proxies/residential/proxy/rotation)为每次尝试生成新的 8 位随机会话，由代理网关在首次连接时分配出口，保留账号认证基础值、中国区域和 24 小时 TTL；不需要创建管理 API 密钥。也支持固定 `proxies` 列表。24 小时仅为时长上限，每次仍需前后探测实际出口；541 命中过的出口不在本单重用。

## 操作顺序

在服务器发布目录执行，示例 ID 仅展示参数格式：

```bash
python3 scripts/officialReceiptBatch.py plan --config /受限路径/config.json --orders 1355,1354
python3 scripts/officialReceiptBatch.py run --config /受限路径/config.json --batch 批次UUID --wait-seconds 3600
python3 scripts/officialReceiptBatch.py status --config /受限路径/config.json --batch 批次UUID
python3 scripts/officialReceiptBatch.py stop --config /受限路径/config.json --batch 批次UUID
python3 scripts/officialReceiptBatch.py resume --config /受限路径/config.json --batch 批次UUID --wait-seconds 3600
python3 scripts/officialReceiptBatch.py export --config /受限路径/config.json --batch 批次UUID
```

`plan` 只读冻结范围，返回批次 UUID 和不符合条件的人工条目。新版本不得覆盖旧批次配置；已建立批次继续使用其原发布目录、原配置。`run/resume` 自动采集、独立重验、绑定及回读，默认两个并发，同一 AppleID 串行，数据库锁处理跨批次互斥；等待时间限制新任务领取，已开始的尝试在自身预算内结束。达到运行窗口后 `retry_wait` 留在队列，下次使用同一批次继续。可以在运维服务管理器中运行该命令，退出不等于所有订单完成，应读取状态。

`stop` 持久化停止标记。运行中的调度器传播至采集器，未开始任务停止；已有提交须继续只读对账。`resume` 保留尝试次数和 Gate 冷却，成功单跳过；未知提交先取得相同事务锁只读核对，只有确定未提交才用原请求键重放。普通业务冲突不自动重放。

`export` 生成私密 `export.json`：成功条目包括订单号、明确 SN、料号、商品名称；失败及人工条目包括系统 ID 和错误码，不附凭据／Cookie／原始链接。`status` 只输出安全摘要。不要把完整运行目录或导出提交 Git。

## 异常与人工处理

| 情况 | 行为与处理 |
| --- | --- |
| 541、网络超时、连接／代理／会话失败 | 保存失败，换出口并遵守既有冷却；每单最多三次。旧 R4 中 `HTTP_TIMEOUT` 转人工的历史保持，不能直接换新配置继续旧批次 |
| 登录冷却／历史次数达到上限 | `retry_wait`，按数据库到期时间再领取 |
| 验证码、双重认证、协议确认、凭据冲突 | `review`，人工处理账号后重新评估，脚本不自动提交挑战 |
| 已有设备、库存来源文字、订单快照变化 | 整单拒绝绑定，保留人工修改；人工核对收据和现有设备 |
| 连接断开／未知提交 | `review` 加 `recoveryRequired`；恢复原批次做只读对账，禁止建新批次掩盖未决写入 |
| 代理过期／无有效代理 | 停止该条目并报告；提取新代理后创建新的配置与明确范围，先完成原批次未决提交核对；推荐使用自动分配新会话的 `iproyalTemplate` |
| 旧应用缺少库存契约 | 拒绝写入，先部署经过正式迁移的兼容应用 |

批次状态、原始输入、加密正文及密钥属于同一证据集，备份须包含 Gate 历史和业务幂等记录。调度器不自动删除证据；按现有备份与敏感数据管理制度受限保存。前后出口相同只证明两个观测点，不代表运营商绝不会在中途更换线路。

## 检查入口

- `npm run test:receipts:batch`：断点、停止、未知提交、单 leader 等隔离状态机测试，需要 Python；当前开发后端镜像未安装 Python，可在本机 Python 执行相同入口。
- `npm run test:receipts:binding`：仅允许 `receipt-binding-test-db/receipt_binding_test`，从生产同版源码和 schema-only 建空白测试库；使用合成订单和账号，不带生产行数据。`RECEIPT_TEST_RUNTIME` 指向测试运行时。
- `npm run test:receipts:browser`：无外网容器、本地 TLS／合成页面、真实 Chromium；容器只因本地 443 测试服务需要 `NET_BIND_SERVICE`，生产采集容器无该权限。
- JS 单元与项目规范仍执行常规 lint、Jest、文档检查。真实数据成功、自动绑定成功、长期成功率分别记录。

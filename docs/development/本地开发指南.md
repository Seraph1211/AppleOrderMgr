## 环境与安装

使用 Node.js 20+、PostgreSQL 14+；所有命令默认从仓库根目录执行。前端使用 React、Vite、Tailwind CSS 和 Lucide React。

```bash
npm ci
npm --prefix frontend ci
cp .env.example .env
```

`.env` 已存在时不要覆盖。配置字段以[环境变量示例](../../.env.example)及各读取入口为准。

| 配置                                                         | 说明                                                                      |
| ------------------------------------------------------------ | ------------------------------------------------------------------------- |
| `DB_NAME`、`DB_USER`、`DB_PASSWORD`、`DB_HOST`、`DB_PORT`    | API 数据库连接与 CLI 迁移均使用这些变量；仅填写 DATABASE_URL 不能替代它们 |
| `JWT_SECRET`                                                 | 至少 32 字符；替换占位值                                                  |
| `FIELD_ENCRYPTION_KEY`                                       | 32 字节密钥，以 Base64 或 Hex 注入；不要提交真实值                        |
| `FIELD_ENCRYPTION_KEY_VERSION`、`FIELD_ENCRYPTION_KEYS_JSON` | 当前加密版本及仍需读取的旧版本密钥                                        |
| `FIELD_BLIND_INDEX_KEY`                                      | 可选独立盲索引密钥；轮换需配套数据处理                                    |
| `ADMIN_INITIAL_PASSWORD`                                     | 首次创建管理员使用，至少 12 字符                                          |
| `RUN_WORKERS_IN_API`                                         | 保持 false，使用独立 Worker                                               |

数据库准备见[数据库初始化与迁移指南](../database/数据库初始化与迁移指南.md)。

## 启动 API 与前端

先完成迁移和管理员初始化，在两个终端分别执行：

```bash
npm run dev
```

```bash
npm --prefix frontend run dev
```

前端默认访问 `http://localhost:5173`；如端口被占用，以 Vite 实际输出为准。Vite 将 `/api` 代理到 `http://localhost:3000`，配置见 [vite.config.js](../../frontend/vite.config.js)。更改 API 端口时需同时调整代理目标。

`/api/health/live` 只反映 API 进程存活；`/api/health/ready` 检查数据库，失败返回 503；旧 `/api/health` 返回 307 重定向。首次登录管理员必须改密。

## 启动邮件与爬虫

仅在需要联调对应链路、外部账号与使用范围已确认后启动：

```bash
npm run start:email-worker
```

```bash
npm run start:crawler-worker
```

- 邮件需要 `IMAP_*`；生产环境要求发件人白名单。`IMAP_MARK_SEEN` 会影响邮箱已读状态，见[邮件处理流程](../design/邮件处理流程.md)。
- 爬虫请求需要可用代理；自动调度需显式启用 `AUTO_ORDER_REFRESH_ENABLED`，见[订单爬虫](../design/订单爬虫.md)。
- Worker 独立启动并不代表已经成功处理业务；需要日志及订单数据验证。

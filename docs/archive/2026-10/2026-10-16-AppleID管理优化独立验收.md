- 备注留空明确提示“清空备注”；实际保存清空且状态不变。合成数据库触发器返回失败时对话框保持确认信息和草稿，移除触发器后原对话框重试成功，故障触发器均已移除。

- 实际 CSS 视口宽度375、高度811时，批量编辑和确认对话框可读可保存，表格保持内部横滚，页面未新增横向溢出；桌面页面、全部操作和四种状态均目视检查。工具viewport参数受浏览器缩放影响，因此记录的是DOM读取的真实CSS宽度。

## 复现命令

先创建允许命名的空库并执行全部正式 Migration。以下使用已建立的独立网络，`APPLEID_TEST_DB_PASSWORD` 必须来自该合成库，禁止载入生产环境文件。命令会清理专库合成用户及账号，勿与浏览器专库同时使用。

```bash
docker run --rm --network appleid-management-test \
  -v /Users/seraph/.codex/worktrees/appleid-management/AppleOrderMgr:/workspace \
  -w /workspace -e NODE_PATH=/app/node_modules -e NODE_ENV=test \
  -e RUN_APPLEID_ACCEPTANCE=true -e DB_HOST=appleid-management-test-db \
  -e DB_NAME=apple_order_mgr_appleid_test_acceptance_final_20261016 \
  -e DB_NAME_TEST=apple_order_mgr_appleid_test_acceptance_final_20261016 \
  -e DB_USER=postgres -e DB_PASSWORD="$APPLEID_TEST_DB_PASSWORD" \
  -e JWT_SECRET=synthetic-appleid-acceptance-secret-123456789 \
  -e FIELD_ENCRYPTION_KEY="$(openssl rand -hex 32)" \
  apple-order-mgr-dev-backend:local /app/node_modules/.bin/jest \
  --runInBand --no-coverage --roots test src scripts \
  --runTestsByPath test/appleIdManagementAcceptance.integration.test.js

docker run --rm \
  -v /Users/seraph/.codex/worktrees/appleid-management/AppleOrderMgr/frontend:/workspace \
  -w /workspace apple-order-mgr-dev-frontend:latest \
  node --test test/appleIdManagement.test.mjs
```

独立测试文件 ESLint 0错误、0警告；已按指定文件运行 Prettier。集成输出临时保存于 `/tmp/appleid-acceptance-final.log`。

>
> 最近核对：2026-09-29
>
> 适用范围：南京万辉账号可见的苹果手机价格采集；接入现有公开报价属于可选后续阶段
>
> 基线：AppleOrderMgr `ae7f8bd`；来源站点使用用户授权账号进行只读浏览

> 验证范围：已完成一次带图形验证码的登录及桌面／移动报价页浏览；未验证独立 HTTP 采集、全量分页、会话寿命、无人值守运行或生产部署

## 一、目标与推荐范围

从 [南京万辉移动报价页](http://njwhtx.com/m/quoteList.action) 获取账号实际可见的 iPhone 报价，保存原始名称、商品标识、价格、货况、来源分类及观测时间，支持当前报价查询与历史变化追溯。

建议第一阶段采集“苹果手机”分类内全部 iPhone 型号，保留不同货况，查询默认展示未注明特殊货况的商品；“未注明”不等于已经证实全新未激活。“苹果手机安徽同城系列”作为独立区域来源，默认暂不纳入。排除 AirPods、平板、电脑、手表和配件。

用户已明确要求每半小时自动采集一次，常规会话失效后不得依赖用户协助登录。计划每天整点及半点运行，共 48 个计划批次；失败恢复重试单独计数，禁止重叠任务。首版只采集和存储，不自动替换现有公开报价来源。无人值守登录须通过真实验证后才可判定可交付。

## 二、现场确认的事实

| 项目 | 本轮观察 | 对实现的影响 |
| --- | --- | --- |
| 登录 | 未登录访问移动页跳回登录页；账号、密码和四位图形验证码登录成功 | 需要维护会话；验证码不能假定可长期无人值守处理 |
| 内置自动登录 | 重新读取登录页源码，存在自动登录 Cookie 及有效期逻辑，但本次响应中的 `autoLoginTime` 与服务器时间参数为空，前端会隐藏自动登录选项 | 仅证明网站软件包含此功能，不能认定本账号已启用或可依赖；不伪造自动登录标志 |
| 页面 | 桌面 `/quoteList.action` 和移动 `/m/quoteList.action` 均能看到文本价格 | 无需用图片 OCR 识别报价；接口直采是否可用仍待验证 |
| 分类 | 同时有“苹果手机”和“苹果手机安徽同城系列” | 保存区域分类，不能直接合并为同一种价格 |
| 商品 | 普通名称、拆封激活、官网预激活、盒损商品同时存在 | 型号／容量／颜色不能单独作为来源商品唯一键 |
| 混杂数据 | 桌面“苹果手机”分类中包含 AirPods | 分类筛选后仍需识别商品类型 |
| 商品标识 | 移动页商品链接携带商品 ID 与公司标识 | 候选键使用来源＋公司标识＋商品 ID，跨分类重复关系另验证 |
| 加载范围 | 移动页初始和选择“苹果手机”后均观察到 80 个商品链接；滚动到底未见追加 | 80 仅是当前页面加载量，不能证明全量；必须核对分页／加载机制 |
| 时间 | 桌面页标题显示当日报价单，未确认可信的逐批更新时间 | 日期标题不能直接充当增量游标 |

例如，本轮同一“苹果18pro 256G 冰川蓝色”页面报价分别为：未注明特殊货况 9850 元、盒损 9800 元、官网预激活 9800 元。它们是独立商品，不能按最低价覆盖。数值仅为本轮页面样本，不构成持续有效报价。

## 三、采集技术路径

推荐链路：定时任务 → 会话检查 → 获取完整分类报价 → 解析与校验 → 内容比对 → 事务保存批次 → 查询／导出。

1. **先验证会话和请求。** 使用正常登录流程，确认报价请求的 URL、方法、分页参数、响应类型及鉴权；先取小样本与浏览器同一商品逐项比较。确认 HTTPS 支持情况；本轮实际页面为 HTTP，不关闭证书校验。
2. **优先使用已验证的 HTTP 数据请求。** 若页面提供 JSON 或 HTML 列表，复用登录会话直接获取；若必须依赖浏览器，则用 Playwright 读取文本及 DOM。此处是候选方案，本轮没有确认报价接口端点。
3. **无人值守登录与失效恢复。** 正常轮次复用会话，不每半小时重新登录；会话与登录凭据由独立密钥保护，在授权的部署环境中持久化。优先验证站点原生自动登录机制是否可用。若不可用，候选方案为在同一 HTTP 会话内获取图形验证码，使用本地 OCR 识别后提交正常登录表单；不将账号、密码或验证码发送到第三方打码服务。四位验证码目前只完成一次人工识别登录，自动识别成功率及服务端限制未验证，不能提前承诺可靠无人值守。验证码错误时换新验证码，每轮最多 3 次有间隔尝试；账号密码错误、账号锁定或新增风控直接停止，避免锁号。登录成功须再次读取受保护报价数据验证，不能仅以 HTTP 200 判定。通过真实样本、会话失效与进程重启测试后再选定路线；若普通登录无法自动恢复，则应判定未满足要求并评估站点提供的正式接口或长期授权方式，不能默认改回要求用户定期协助登录。
4. **列表优先。** 完整获取分类列表，不默认逐个访问详情。只有列表缺失关键货况或规格时才按需补详情，并缓存不常变的属性。
5. **低并发执行。** 单站点串行分页、短抖动、任务互斥；超时有限重试并退避，限流或风控时停止。分页未完成、身份失效或结构异常均不得发布为成功批次。

建议采集器放在专用采集项目中；既有 PPSpider 可作为候选，但其当前结构、运行环境和调度需在实施时核对。本轮只核对 AppleOrderMgr 当前代码，没有重新核验 PPSpider 或生产调度。

## 四、字段与数据规则

| 字段组 | 建议保留内容 |
| --- | --- |
| 来源身份 | 来源代码 `njwhtx`、公司标识、商品 ID、分类／区域、账号配置引用（不保存明文账号） |
| 原始证据 | 原始商品名称、原始价格文本、备注、来源页面、解析版本 |
| 标准规格 | 商品类型、型号、容量 GB、颜色、机型代码、规格码 |
| 商品状态 | 激活状态、包装状态分开保存，可同时存在；另保留原始货况文字和待人工确认标记 |
| 报价 | 当前账号可见价格、币种 CNY、报价状态；使用 Decimal 或整数分，保留小数精度 |
| 时间与批次 | 采集时间、最近成功检查时间、来源更新时间（无可靠值时为空）、批次 ID、内容摘要 |

标准化不能丢掉原始值。1TB／2TB 转换为 1024／2048GB；颜色同义词采用显式映射，未知型号、颜色或货况进入待确认队列。页面的商品描述不用于推断手机官方规格。缺货、询价、空价格单独编码，不写成 0 元；页面无库存字段时不推断库存。

建议独立来源明细与批次记录，具体表名在采集项目的数据规范中确定。不同账号可能看到不同价格，应保留账号配置范围；会话、密码不得进入 Git、日志、截图样本或方案正文。

## 五、增量、完整性与失败行为

- 每轮完整采集后，按稳定商品标识排序，对价格、货况、名称和备注等业务字段计算摘要；无变化只更新检查记录，有变化保存新批次及变更记录。
- 不仅比较页面日期：同一天改价也必须识别；也不把每次抓取时间变化当成报价变化。
- 完整性以真实分页终点、来源数量（若提供）、商品键唯一、价格有效及解析成功情况判断，不预设 80 条，也不要求每个容量都拥有同样颜色集合。
- 页数未完成、商品大幅减少、未知结构或异常价格进入异常批次，不覆盖已验证的当前批次。完整成功后才能记录新增、改价和本轮未出现的商品；“未出现”不直接等同停售。
- 数据过期与采集失败明确展示。历史价可以保留供内部追溯，但不得伪装为刚更新的有效报价。
- 建议任务结果区分 `success`、`skipped`、`auth_required`、`partial`、`failed`，记录条数、耗时、变更数量及脱敏错误原因。
- 常规过期自动恢复成功不打扰用户；自动恢复耗尽、账号异常、验证码机制改变或持续采集失败时才告警。`auth_required` 表示自动恢复已失败，不是每次过期都要求人工输入。

## 六、与 AppleOrderMgr 的关系

当前 [Apple 公开报价](../design/Apple公开报价.md) 读取明威来源；现有 `quoteSourceRepository.js` 明确查询 `quote_hnmwdx_apple`，当前型号过滤与数据校验也具有来源语义。南京万辉数据不能直接写入该表冒充明威价格。

第一阶段建议仅形成独立报价库及核对结果。若后续需要接入管理台，增加“南京万辉报价”来源查询，按型号、容量、颜色、激活状态、包装状态和区域筛选，显示更新和过期状态。

若进一步用于公开报价，需要另行确认选源规则：指定来源、人工选择或条件相同商品的比价。不得默认跨货况取最低价，或在来源失败时静默切换。公开接口继续采用字段白名单，隐藏来源原价、账号配置与内部调价信息；来源缺少官网价时保持缺失或由明确的独立来源补充，不能凭空填值。

涉及本项目的表结构、API 或公开报价规则变更时，再按数据库架构、API 契约、专题说明、实现及测试的顺序执行级联维护。

## 七、分阶段交付与验收

| 阶段 | 交付 | 验收条件 |
| --- | --- | --- |
| 1. 技术验证 | 登录与会话方案、真实分页说明、字段样本、HTTP／浏览器路线选择 | 浏览器与采集结果一致；证明抓取范围完整；在有限真实登录样本中记录验证码识别率、重试成功率与锁定反馈；确认会话失效可自动恢复 |
| 2. 采集实现 | 独立采集器、字段解析、增量批次、运行日志与测试 | 普通／预激活／拆封／盒损不混价；配件不误收；同日改价可识别；重复运行无重复批次 |
| 3. 调度运行 | 每半小时调度、互斥、重试退避、自动登录恢复及异常提示 | 授权环境连续观察建议 48 小时、96 个计划轮次；验证采集进程重启及自有会话过期／移除后无人工恢复；记录成功、无变化、失败和恢复次数；合成故障与真实现场证据分别记录 |
| 4. 可选接入 | 内部查询、历史变化、导出或公开报价选源 | 根据确认的展示范围验证权限、货况筛选、过期标记和敏感字段白名单 |

关键测试还包括：多个货况具有相同型号容量颜色、规格码变化、同一商品重复分页、新增／消失、空价／询价、小数价格、接口返回登录 HTML、会话过期、字段结构变化。只读采集不得触发购买、购物车或订单操作。

## 八、待确认的业务选择

1. 范围是否采用推荐值：全部 iPhone 型号和货况均采集，默认查询未注明特殊货况；暂不含安徽同城系列。
2. 周期与常规登录免人工已确认：每半小时采集，登录失效自动恢复；具体自动登录路线待技术验证。
3. 首版是否只做独立采集入库；管理台查询或公开报价接入另列阶段。

本轮只完成调研和方案，没有实现采集器、修改数据库、启动定时任务或部署生产。

# 库存监控

> 状态：已生产发布；2026-10-03 PC/H5 界面更新，当前采集和通知沿用已开启配置；真实全量 48 小时稳定性另验。当前发布证据见[界面发布记录](../archive/2026-10/2026-10-03-库存监控界面优化发布记录.md)。

## 范围与入口

库存模块分为两个菜单页：“库存监控”含全国库存、历史记录、统计分析三个页签，要求显式库存查看权限；“监控管理”含监控管理、通知与健康两个页签，仅管理员可访问。当前商品范围支持 Apple 中国大陆的 iPhone 18 Pro、iPhone 18 Pro Max 与 iPhone Duo 全部已确认颜色／容量 SKU 和直营店，不接入订单爬虫、客户或付款数据。业务口径和已批准参数见[需求方案](../planning/库存监控需求草案.md)。

## 数据和状态

目录使用精确 SKU 和门店代码；官网发现的新项默认待启用，一次发现失败不下架。版本化种子只包含已抓取的公开目录和来源时间，不表示全量库存已验证。监控总开关及通知默认关闭。Duo 通过正式增量迁移加入 8 项且默认待启用；已有全部目录记录、各项启停、总开关、通知配置与历史保持。官网预购时间及 `comingSoon/getReady=false` 不能证明已能购买；目录接入不触发真实请求或通知。

最新快照保留最后有效库存和本次错误；单次全局风控不作全库强制中断，已成功组合保留原有效期。只有该组合真实查询失败、轮次覆盖缺失或启停范围改变才记录连续性缺口；`displayStatus` 区分 `in_stock`、`out_of_stock`、`unknown`、`error`、`stale`、`disabled`、`paused`、`unsupported`。有效期在成功时固化为正常周期的两倍，后来降速不延长。手动检查与自动轮次共用最新基线和持久化队列。

同轮同 SKU/门店只应用一次；后到的重叠地域失败不得覆盖本轮已成功组合。并发请求分别预占字节和请求预算、按请求归还剩余字节额度，未知请求保守保留预占；普通在途请求的迟到成功不能计作保护触发后的恢复探测。代理候选验证在同一 Worker 内合并，避免多个并发请求重复消耗端点。新鲜、连续的无货转有货才是 `arrival`；从未成功为 `first`；中断后观察为 `recovery`。持续有货只增加检测，短暂错误后恢复原有货不重复通知。检测、事件、小时聚合与快照在一个事务中更新。

商品目录、型号筛选、全国库存缺失组合与自动／手动轮次均应用服务端精确机型白名单。当前白名单共 40 SKU（原 Pro／Pro Max 32 项加 Duo 8 项）；停用与移出范围是不同操作，范围外商品即使存在于旧数据库且标记启用，也不返回当前目录或参与新采集。首次种子和每日官网目录更新均过滤范围外机型，防止重新加入 iPhone 17 等商品；保留既有历史证据，不删除历史表。

## 调度与保护

库存 Worker 仅由 `inventory` profile 显式启动。一个轮次由单一 Worker 持有数据库租约，轮内最多 3 个请求并发；每个任务有独立令牌和到期时间，异步返回按事务归并，任务租约到期记为结果未知，不无条件重放。轮次过期后停止领取新任务，等待已有请求结算或到期再完成覆盖审计。轮次固定启用清单与正常周期，保存计划、完成、失败、未采和待采数量及任务进度。普通并发容量等待不计停采或查询异常；限速、换出口、恢复探测等未发送等待保留 pending/notBefore 至轮次截止；不提前将剩余任务记为失败，不延长原轮次。终态 not_sent 表示未发出的查询任务，failed 表示实际发出但失败或结果未知；组合失败数保留历史“未取得有效结果”的覆盖口径，另附 notSent/attemptedFailed 区分。停机或冷却错过的计划轮次保留，不追赶突发。手动请求合并且限制排队，自动到期优先但不无限饿死手动任务。

所有目录、自动、手动、重试、恢复、代理提取都经过同一个 PostgreSQL 请求闸门。初始全局 5 RPS（最大 10）、库存任务 1 RPS，正常采集最多 3 并发，恢复探测保持单并发；单查询最多 3 次且全轮重试不超过基础请求数的 20%。小时、日、字节和代理提取预算重启不清零；代理失效无直连兜底。403/挑战、无效结构与供应商鉴权错误需人工处理；429/541 尊重至少 60 秒冷却，达到连续/比例/双出口阈值暂停 10 分钟；有限恢复最多三次，失败延长到 20/40 分钟，再失败人工处理。普通 5xx/超时连续五次同样进入十分钟冷却，但不计为 Apple 风控响应。IPRoyal CONNECT 500/502/503/504 归为临时隧道故障，410 表示粘性会话失效；首次和第二次候选故障分别冷却 60/120 秒，再验证新候选，连续三次候选故障停用该来源。同候选并发故障只计一次。供应商故障不清空或累计 Apple 风控与库存恢复次数；实际有效库存才清供应商失败计数。CONNECT 407 或其他拒绝仍暂停出口，未知 402 不推断余额不足；Apple 541 和认证保护不变。轮次覆盖缺失保留对应任务的具体失败原因，只有缺少原因时才回退为通用缺失。库存目标侧 307 只有在 CONNECT 200 已确认时，缺失 Location 或无危险特征的同源 HTTPS 跳转才归入既有 TARGET_REJECTED 有限恢复，始终只重试原固定 URL，不跟随任何 Location；明确外域、降级、认证或挑战等危险特征继续 REDIRECT_BLOCKED 人工处理。其他 3xx、用途和未确认 CONNECT 200 的响应不放宽。诊断只保存定长摘要与固定分类，不保存原始 Location 或响应正文；具体边界见[IPRoyal 库存代理接入](IPRoyal库存代理接入.md#库存目标-307-的有限恢复)。

## 通知与统计

独立配置、加密 Webhook、队列和每分钟 18 条预算。10 秒窗口按城市/门店合并，首次摘要单独标记；恢复观察事件继续留在历史与统计，但不逐门店发送库存恢复通知，发布前 pending recovery 队列以 RECOVERY_NOTIFICATION_RETIRED 跳过；首轮摘要等待轮次结束再计发送有效期，仍须复核样本新鲜度；发送前复核最新快照、开关、目标机器人和 120 秒事件有效期。未知投递不重发；明确失败有限重试。启用只处理之后事件，替换机器人废弃旧目标队列，静默不暂停采集。

运行健康提醒独立降噪：普通查询异常持续 2 分钟才排队，查询通道恢复并连续观察 2 分钟且此前故障已送达或回执未知时，仅提醒一次恢复。同类普通传输故障合并为一个事件，同类故障 30 分钟内不重复发起提醒；需要人工处理、保护冷却、代理不可用及预算耗尽立即排队，仍遵守静默时段和群限速。发送前重新读取数据库健康状态，撤销已失效的健康提醒（含旧版本待发提醒）；关闭采集／通知或替换机器人重置观察，不补发历史恢复。状态及时间使用数据库事务持久化，重启不清零。恢复只发送一条健康摘要，附当前有效组合／启用组合、有货组合数及登录页面链接；该摘要不承诺全国完整覆盖或长期稳定。到货与首次库存通知保持既有规则，三次有效库存请求恢复、5 分钟风险窗口、2 分钟健康观察、30 分钟去重及发送成功／未知关联保持。

分析默认到货事件，可切换有货检测、首次和恢复。所有图表共用筛选及北京时间范围，缺口与 0 分开；检测明细 7 天、事件及投递 90 天、小时统计 365 天。超过明细保留期不提供假下钻，只有小时聚合时不能伪造细粒度热图；较旧查询明确显示对齐后的完整小时范围，超保留期的明细导出拒绝并提示调整起始时间。

## PC 与 H5 操作布局

PC 使用蓝白工作台：库存监控三个页签、监控管理两个页签、采集与通知状态入口、库存概览及统一表格工具栏。H5 在对应菜单页内展示页签，商品筛选与时间条件可折叠；已应用条件保留摘要，修改后需应用，重置会同时清空已应用筛选。库存行“查看记录”携带精确 SKU 与门店，并在摘要展示对应商品；摘要需兼容精确 SKU 和未知字段，不能使页面崩溃。商品选择支持搜索，多选在手机使用可滚动底部弹层，支持完成、关闭、遮罩和 Escape，关闭后焦点回到入口。

手机库存、目录、历史、轮次及通知采用连续紧凑列表，首屏展示商品／门店与状态，展开详情查看精确 SKU、官网提示、错误、时间和历史入口；不使用业务数据卡片网格。PC 保留完整表格，统计榜单并排展示。状态未知、错误、过期与无货仍明确区分，查看缓存不等于实时请求官网。

输入框在手机至少 16px，主要触控目标至少 44px；窄屏与短屏弹层内部滚动，底部操作考虑安全区。设置表单按用途分组，采集、通知开关及保存按钮清晰可达。布局适配不改变自动采集、通知、请求预算或手动排队规则。

开发验收包括纯函数、事务/多 Worker、API 权限、通知失败与 PC/375px H5 交互。上线后再做至少 48 小时全国固定范围观察及新群真实送达。已有目录及代理证据见[数据源验证](../testing/库存数据源验证.md)。完整代码不等于真实源稳定性通过。

## 运行配置与发布顺序

正式 Worker 入口 `npm run start:inventory-worker`；开发、生产 Compose 均为显式 `inventory` profile。API 不自行启动库存采集。生产按现有发布流程构建新镜像、备份并执行库存表与时间索引 Migration，再更新 API/前端，最后显式启动库存 Worker；全局监控和通知默认关闭，逐项启用目录后再打开采集。未迁移前不得开放库存页面。

库存代理仅允许 IPRoyal 中国住宅来源 `iproyal-main`，通过 `INVENTORY_PROXY_FILE` 读取 0600 私密文件，格式与固定参数见[IPRoyal 库存代理接入](IPRoyal库存代理接入.md)。入口为 `geo.iproyal.com:12321`，HTTP CONNECT，十分钟粘性、高端池和 killswitch；基础密码由程序附加固定路由参数。每个候选先验证真实出口哈希再发库存请求，认证 URL 加密进入持久化闸门。旧备用文件和亦优 API 配置不参与选路；配置缺失或不可用时关闭请求，不回退其他供应商或直连。生产目录由 `INVENTORY_SECRETS_DIR` 只读挂到 `/run/inventory-secrets`，环境中的文件路径应指向此挂载；不得提交真实配置或把旧订单代理服务重新启用。

`INVENTORY_PUBLIC_URL` 可选，须为本系统 HTTPS 公共源，用于需要登录的库存详情链接。Webhook 通过管理员设置页保存并使用既有字段加密密钥；生产必须已有有效 `FIELD_ENCRYPTION_KEY`。切换 Webhook 后重新测试。发送测试是明确操作，自动提醒开关与采集开关分开。

2026-10-16 已批准接入 IPRoyal，当前实现及验证范围见接入设计与开发进度；未真实验收前不宣称中国出口或 Apple 长期稳定性通过。`tunnel` 配置固定 `provider=iproyal`、`stickySeconds=600`，`expiresAt` 可省略；仅已知实际期限才填写，配置期限到达会停止请求。住宅流量未配置期限不能伪造为套餐过期。十分钟是出口粘性窗口，采集继续每 300 秒执行，541、冷却、有限恢复及预算保护保留。历史网帆操作证据继续保留：[2026-10-05 网帆切换记录](../archive/2026-10/2026-10-05-库存监控网帆代理切换.md)、[2026-10-07 套餐更新与恢复记录](../archive/2026-10/2026-10-07-库存监控网帆套餐更新与恢复.md)；历史通过不表示当前来源验收通过。

默认请求预算为小时 1200、日 25000；每日响应字节上限 512 MiB、每日代理提取上限 400。字节值为解压响应及在途最大响应预占，不是供应商账单；实际费用在上线观察中按供应商后台核对。默认预算是保护上限，不能据此保证 300 秒全量覆盖。达到上限要在页面与统计保留缺口，按实测调整周期与预算，不自动采购。

目录通过购买总页发现当前系列，再用精确 `partNumber` 的 `productSelectionData` 和 `displayValues` 核对机型、容量、中文颜色；不能单独采用 metrics 里的型号名称（已发现 Pro Max 被写为 Pro）。预售未开放项不加入在售清单，新发现项默认关闭。目录核对失败保留既有清单及最近核对时间。

回滚代码前先关闭全局采集和通知、停止库存 Worker。数据库 down 会删除本模块历史，常规版本回滚保留表，不把 down 当作自动发布回滚步骤。订单/邮箱/付款/AOS 及其 Worker 不受本模块配置控制。

### 独立页面与只读范围（2026-10-03）

用户菜单“库存监控”位于 `/inventory-monitor`，内含全国库存、历史记录、统计分析，使用 `?tab=latest|history|analysis`，要求显式 `inventory.read` 权限。管理员菜单“监控管理”位于 `/inventory-monitor/manage`，内含监控管理、通知与健康，使用 `?tab=manage|settings`，只允许管理员。侧栏仅提供这两个菜单，旧 tab 及路径链接兼容归组后重新鉴权。普通用户可查看和导出已有数据，不可触发外部采集或配置。

全国库存与管理页展示已启用商品、门店及其组合数，可展开查看完整名单。配置已启用不代表采集正常：关闭、自动等待（含预计恢复时间）、需人工处理、Worker 离线、数据失效、查询异常和正常采集分别提示，附停采起点、原因、下一步及最近成功时间。预算耗尽自动等待对应小时／日桶重置，显示下次核验时间，不要求人工解除；来源阻断只依据当前 IPRoyal 来源，旧来源 pausedEgress 不阻断新来源。停采起点为持久化采集受阻时间；历史缺失时仅显示最近成功时间，不伪造停采时刻。权限通过现有用户管理分配，不根据普通用户角色隐式赋权。

## AOS 放货信号提醒（2026-10-19）

2026-10-19已完成正式迁移、生产发布及开关启用；2026-10-25用户提供的19:34首次与汇总手机截图证明上轮纯文本自然消息在普通微信入口可见，仅限该样本。本轮手机分层排版上线后的实机展示与长期稳定性仍待观察。

完整日志同步检测 `取货信息: 取货日期待付款完成后确定`。以设备＋实例＋源文件＋完整任务标识关联上下文，最近 `消息20110501`、开始登录或重新加购成功开始新的尝试；仅从该尝试在锚点之前的“尝试预约”“商品”提取门店和规格。跨上传批次持久化上下文，不复用上一轮配置；无法核对的字段显示未知。

管理员在库存“通知与健康”设置独立 `config.aosSignalsEnabled`，默认关闭，复用已经测试的库存群机器人与投递链路。官网采集、官网库存通知、代理保护和库存目录开关不控制 AOS 提醒；群静默及每分钟18条限制仍生效。日志接收事务仅写入实际新增事件的脱敏队列，库存 Worker 每秒有界消费；Worker 停机不影响原日志同步，恢复不补发超时事件。

10台服务器、11实例及后续新接入实例共用全局窗口：首个新鲜命中立即提醒，后续3分钟到点合并；首次提醒的命中同时计入第一个3分钟汇总，即使只有首条也生成1次命中的汇总。后续窗口只统计各自窗口内的新命中，不累计前窗。一个完整3分钟窗口没有新增命中时结束本轮，下次重新立即。启用前、收到时超过3分钟、未来时间或无法可靠解析身份的日志不触发。重复上传、跨存储模式回执和重启不重复计数。

每条概览使用普通文本，按手机阅读层次展示，不依赖Markdown渲染：首行为“首次信号／3分钟汇总｜总命中数｜已知门店数”，未知门店命中另列说明；后续按城市与门店分段，同店按机型分组，每个机型只列一次，颜色、容量、命中数单独成行。非连续出现的同店与同机型同样归并，门店数按已知门店代码去重，不按商品规格组数计。

时间放在详情之后，以北京时间精确到秒，同秒开始／结束只显示一次；同日仅开始显示月日，跨日两端显示月日，跨年两端显示完整年份。原始毫秒字段和实际计数不变。最后显示来源，服务器使用 `US_21` 等明确编号、实例保留档案标签，单来源内联、多来源分行，不显示S1映射；仅AOS消息移除网页详情链接，其他库存与健康通知的链接保持。

### 同城同规格账号比例（2026-10-26，已批准实施）

所有账号监控所选城市全部门店。首次信号样式及立即排队保持，不查询分母；升级前已有命中但无账号tracker的活跃窗口保留raw汇总，整窗比例—/—，不拿升级后新增hit冒充完整N；首次命中也计入三分钟汇总。汇总按完整商品与城市分段，例如 `iPhone Duo · 星光白色 · 512G`、`广州 · Apple 天环广场｜10次`、`US_12 / 实例标签｜10/23`；同城多店列各店日志命中数，来源比例不跨城市合并。末尾无CR／LF、无链接，内部空行保留。

N为窗口内同设备／实例／城市／机型／颜色／容量的原始日志编号去重数，同编号跨门店仍计一次，编号保留前导零，不关联AppleID。D为该scope首hit日志之前各编号最近一次启动的完整设置集合：停止本身不改变设置，无近10分钟限制。无A任务号的“开始监控库存状态”“开始下单”按同账号、同文件原字节边界处理，不能用空task相等配对；新不完整启动也截断旧设置。城市只能由同轮可靠门店映射证明，请求店不限定监控门店列表；未知代码、冲突及无法证明跨文件的证据降级。

首hit集合冻结，后续hit时点的eligible集合变化、缺设置或不在其时点eligible中的真实hit均保留N而令D显示`—`；N无法完整证明时显示`—/—`，不把hit强加入D、不显示N>D。已知任一维度不匹配的编号可排除，例如明确夜空1T但城市未知不妨碍白512分母。独立比例跟踪不借用1000条关联refs上限，超限/无法重归属只降级比例，原日志命中数仍保留。

## 业务口径

取货记录是订单的一对一业务扩展。取机人将一笔订单的全部设备交给工作人员后，才可登记为“已取货”；不支持部分取货。人工取货状态与官网、邮件状态相互独立，不能互相覆盖或推断。

取货业务和权限统一以 `orders.tag` 完整匹配。取机人档案 TAG 与 AOS 来源 TAG 应在入库和资料治理中保持一致，但不能替代订单 TAG 扩大访问范围。管理员查看全部；内部工作人员由管理员配置订单 TAG 范围，多人共享处理，不设置负责人、主负责人或认领关系。

外部渠道不登录系统。管理员导出 Excel 清单后发送给外部渠道，再由管理员或另行获得该外部 TAG 范围的内部工作人员代录。

## 状态与字段

状态为 `pending`（待取货）、`picked_up`（已取货）、`exception`（异常）。首次登记已取货且未填写实际时间时，系统自动写入当前时间；工作人员可以修改。结款金额、结款人、备注、取货凭证和结款凭证均可空，不计算应结、剩余或结清状态。

每次字段变化和凭证新增均追加事件，保存操作人快照、发生时间、前后版本与具体变化。最后更新人仅用于列表提示，不代表负责人。并发修改采用版本校验，冲突时要求刷新后重试。

## 页面与导出

独立“取货记录”页面同时支持桌面表格和手机紧凑列表。列表包含系统编号、订单号、商品、取机人、订单 TAG、门店、日期、时段、人工取货状态、结款信息、凭证和最后更新信息。筛选、详情、导出、更新历史和凭证读取都执行同一订单 TAG 范围。

Excel 默认导出安排取货所需字段和人工状态，不含结款信息及凭证地址，避免对外清单扩大信息范围。订单详情保留进入取货记录的入口。

凭证文件在取得短期读取地址后使用站内预览层展示，图片按视口等比缩放，PDF 使用内嵌查看，并保留用户主动点击的“在新窗口打开”入口。不能依赖异步请求完成后调用 `window.open`，否则会被手机或桌面浏览器的弹窗策略拦截。

手机端登记使用动态视口高度的全屏表单，标题、可滚动内容和底部操作区分层；打开时锁定背景页面滚动。筛选、登记输入框、选择器和文本域在 767px 以下使用至少 16px 字号，避免 iOS 聚焦输入框时自动放大；主要按钮和输入控件最小触控高度为 44px，并保留安全区底部间距。

## OSS 凭证

凭证存放在私有阿里云 OSS Bucket。服务端校验订单权限后签发 5 分钟的限定对象路径上传地址；浏览器直传后，服务端核验对象大小并保存元数据。查看时重新执行订单权限校验并签发 5 分钟读取地址。数据库不保存图片 Base64 或长期公开 URL。

当前已创建杭州地域私有 Bucket `apple-order-mgr-pickup-evidence`，开启阻止公共访问与 OSS 托管 AES256 加密；生产站点 CORS 只允许 `https://apple.godp.me` 的 GET、PUT、HEAD，允许 `Content-Type`，暴露 `ETag`，缓存 600 秒并返回 `Vary: Origin`。RAM 用户 `apple-order-pickup-oss` 无控制台登录权限，仅通过自定义策略 `AppleOrderPickupEvidenceOSSAccess` 读写 `pickup-evidence/*`，不具备列举或删除权限。凭据已写入本地 Git 忽略的 `.env` 和生产权限为 `600` 的 `shared/app.env`，不进入 Git、浏览器或数据库。

支持 JPG、PNG、WebP 和 PDF，单文件不超过 10MB。对象路径按 `pickup-evidence/{orderId}/{pickup|settlement}/` 隔离。长期 AccessKey 只保存在服务端受限环境变量中，不进入浏览器、Git、日志或数据库。

## 权限

- `pickups.read`：查看授权订单 TAG 范围的记录、历史和凭证。
- `pickups.edit`：登记取货、结款及上传凭证，依赖 read。
- `pickups.export`：导出授权范围清单，依赖 read。
- `pickupStaff` 显示为“内部工作人员”，新建该角色时默认授予上述三个权限；订单范围仍须由管理员配置。

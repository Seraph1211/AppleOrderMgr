# 生产发布分级执行规范

> 状态：当前有效
>
> 最近核对：2026-10-30（北京时间）
>
> 适用范围：AppleOrderMgr 前端、API、Worker、运行配置、数据库 Migration 与数据转换的生产发布
>
> 基线：现行统一发布执行器、前端门禁、完整备份恢复工具及2026-10-30生产实测
>
> 验证范围：规则、现有命令入口和历史生产证据；本次只更新发布规范和文档，不执行新的生产发布

## 1. 目的与强制原则

本规范用风险分级替代“任何发布都重新做完整数据库备份恢复”。优化目标是缩短纯前端和严格无写入发布，同时保留业务写入、Migration及数据转换的完整保护。

所有生产发布继续遵守以下规则，不因等级降低而跳过：

1. 生成唯一`releaseId`、`attemptId`、制品manifest和SHA-256，记录当前生产组件基线及回退目标。
2. 使用`productionRelease.py`冻结计划、验证并持有全局发布锁；结果未知时先对账，不盲目重跑。
3. 公开树执行`productionFrontendGate.py prepare`；正式服务变化前用全部实际Nginx身份执行`check`；版本指针只通过`switch`切换，最后执行`verify`。
4. 发布目录不可原地覆盖；不重启共享PostgreSQL、Nginx或未在本次范围内的Worker。
5. AOS监控日志明细及原始日志文件继续排除，生产日志不删除；需要新鲜业务备份的等级仍须覆盖其余业务数据、配置和运行游标。
6. 技术发布、生产只读回读和真实业务验收分别记录。HTTP 200、容器运行或队列接受任务均不能单独代表业务完成。

## 2. 发布前必须提交的分级证据

每次发布在构建前生成`release-classification.json`，放入受限发布证据目录，并把路径和SHA-256写入冻结计划的`releaseClassification`证据引用，由`planDigest`一并绑定。`sourceDigest`仍只表示发布源码/制品来源，不得复用为分级摘要。不得只看改动文件数量或代码行数判断等级。

```json
{
  "schemaVersion": 1,
  "releaseId": "<唯一发布ID>",
  "releaseClass": "A",
  "components": {
    "frontend": true,
    "api": false,
    "workers": [],
    "runtimeConfig": false,
    "nginx": false,
    "databaseMigration": false
  },
  "impact": {
    "apiContractChanged": false,
    "businessWritePathChanged": false,
    "backgroundJobChanged": false,
    "schemaOrModelChanged": false,
    "dataTransform": false,
    "sharedMutableFilesChanged": false
  },
  "databaseProtection": {
    "mode": "reuse-recovery-proof",
    "proofPath": "<受限路径或null>",
    "proofSha256": "<64位摘要或null>",
    "maximumAgeHours": 24
  },
  "reason": "<说明为何满足本等级全部条件>",
  "reviewedAtUtc": "<UTC时间>"
}
```

任一字段未知、无法证明或与实际制品不一致时，必须升级到能覆盖风险的更高等级。发布开始后只允许升级，不允许降低；如需降低必须废弃当前attempt、重新审查并生成新计划。

## 3. 四级发布分类

### 3.1 A级：纯静态前端

必须同时满足：

- 生产制品只改变版本化前端静态文件；API、Worker、Compose、运行环境、Nginx和数据库均不变。
- 不改变API路径、HTTP方法、请求体、权限、表单提交、批量操作或业务动作语义。
- 不改变前端持久化格式、导入导出协议或会导致既有页面发出不同写请求的校验逻辑。
- 当前公开树和候选树均可由门禁完整解析，旧版本目录仍可直接回退。

允许：

- 不生成本次数据库dump，不做本次数据库完整恢复。
- 不扫描全部业务文件；只保存当前指针、当前/候选公开树manifest、SHA-256、权限和版本目录回退证据。
- 复用24小时内满足第4节的数据库完整恢复证明。

示例：颜色、间距、只读表格列、文案、图标、响应式布局；不影响提交数据的纯展示修复。

以下看似前端改动但不得归为A级：改变表单字段、请求参数、批量操作、权限判断、支付/订单/库存动作、导入导出内容或业务状态解释。

### 3.2 B级：严格无写入应用或基础设施变更

必须同时满足：

- 无Migration、模型、约束、索引和数据转换变化。
- API仅新增或修改只读`GET`/`HEAD`路径，或基础设施变化已证明不会触发业务写入。
- 不改变Worker、调度器、队列消费者、重试、外部通知、邮件、官网请求或任何后台写入。
- 候选环境使用只读数据库账号或只读事务，关闭调度和外部副作用。

允许：

- 复用24小时内有效的完整恢复证明，不生成本次数据库dump。
- 复用已验证不可变文件基档，只备份本次配置/制品差量；共享可变业务文件发生变化时升级到C级。

示例：只读统计查询、只读筛选、无副作用的格式计算、TLS/Nginx只读路由调整。依赖升级、安全补丁或公共服务代码即使表面只读，无法证明不会影响写路径时归C级。

### 3.3 C级：业务写入代码，无Schema变化

命中任一即为C级：

- 改变`POST`/`PUT`/`PATCH`/`DELETE`、事务、幂等、状态流转、订单、付款、库存、取货、通知或审计写入。
- 改变Worker、队列、定时任务、重试、游标、外部请求或影响业务写入的环境配置。
- 前端改变写请求内容或业务动作，即使后端代码未变。
- 共享可变业务文件、密钥版本、运行游标或证据写入方式变化，但数据库Schema不变。

必须：

- 生成本次数据库完整业务备份，记录最终落盘SHA-256。
- 把本次dump恢复到全新、无网络、无公开端口的隔离PostgreSQL 15容器，并完成源/恢复业务摘要比较。
- 对受影响共享文件生成当前完整逻辑清单；可复用已认证不可变基档，但本次差量必须恢复验证。
- 候选验证关闭真实调度、邮件、企微、官网请求和其他外部副作用。

不得用24小时恢复证明代替本次dump的完整恢复。

### 3.4 D级：Migration、Schema或数据转换

命中任一即为D级：

- 新增、删除或改变字段、类型、约束、索引、表、Migration记录或模型持久化语义。
- 数据回填、批量转换、加密、历史纠正或不可逆业务迁移。
- 新旧应用不能同时安全读取当前Schema，或回退需要停写/数据窗口决策。

在C级全部要求上追加：

- 在恢复库使用正式migrator执行全部待处理Migration和数据转换。
- 严格核对`SequelizeMeta`、核心业务摘要、约束、索引、序列安全及原生schema证明。
- 写明兼容顺序、停写要求、应用回退下限、是否允许`down`、RPO/RTO和发布后增量业务处理方案。
- 不兼容Migration不得把“恢复旧dump”作为自动回退；必须停止并由授权人依据数据窗口决定。

## 4. A/B级恢复证明复用条件

A/B级只有同时满足以下条件才能复用；否则自动升级到C级备份路径：

1. `backup-set.json`、数据库恢复证据、比较证据和认证恢复组合证据完整，全部摘要匹配且结论通过。
2. 完整恢复结束至本次锁前基线不超过24小时；时间以认证证据UTC时间为准。
3. PostgreSQL主版本、备份/恢复工具摘要、日志排除范围、密钥版本、数据库身份、Schema摘要和`SequelizeMeta`摘要均未变化。
4. 备份集合、对象库、认证密钥及其全部依赖仍存在、可读且受保护；没有清理计划将其列为候选。
5. 自证明生成后没有数据库故障、非正常恢复、完整性告警、手工DDL、未知Migration或恢复失败。
6. 本次分级证据明确证明没有业务写路径、Schema、模型、Worker、队列和共享可变文件变化。

复用证明只表示备份机制和该历史快照可恢复，不表示本次发布时刻的最新业务数据已备份。A/B级接受最长24小时RPO；如发布授权要求本次时点数据保护、当天没有有效证明或任何条件不满足，立即执行C级新鲜备份恢复。

## 5. 各等级执行矩阵

| 项目 | A 纯静态前端 | B 严格无写入 | C 业务写入 | D Migration/转换 |
| --- | --- | --- | --- | --- |
| 本次数据库dump | 复用证明 | 复用证明 | 必须 | 必须 |
| 本次数据库完整恢复 | 复用证明 | 复用证明 | 必须 | 必须 |
| Migration演练 | 不适用 | 不适用 | 不适用 | 必须 |
| 当前Schema/Migration指纹 | 必须 | 必须 | 纳入备份证据 | 纳入备份及演练 |
| 业务文件 | 公开树当前/候选manifest | 配置/制品差量 | 受影响范围完整逻辑清单+差量恢复 | 同C并覆盖迁移相关文件 |
| 候选副作用 | 无API | 数据库只读、外发关闭 | 外发/调度关闭 | 外发/调度关闭、正式迁移仅恢复库 |
| 前端四步门禁 | 必须 | 必须 | 必须 | 必须 |
| 全局发布锁与基线重读 | 必须 | 必须 | 必须 | 必须 |
| 生产独立回读 | 必须 | 必须 | 必须 | 必须 |
| 预期生产执行墙钟 | 3～6分钟 | 5～10分钟 | 15～25分钟 | 20～40分钟以上 |

耗时是当前规模下的规划区间，不是SLA。失败、回退、网络等待和真实业务验收单独记录。

## 6. 可照抄执行的统一流程

### 6.1 冻结范围与验证计划

```bash
sha256sum <受限证据目录>/release-classification.json
python3 scripts/productionRelease.py validate --plan <本次冻结计划.json>
```

冻结计划须包含以下引用，当前执行器不会自动推断发布等级，发布负责人必须在运行前核对：

```json
{
  "releaseClassification": {
    "path": "<受限证据目录>/release-classification.json",
    "sha256": "<分级证据的64位SHA-256>"
  }
}
```

检查计划绑定：分级证据摘要、源码/制品摘要、当前生产基线、目标组件、旧版本、回退动作、实际Nginx身份和证据目录。验证只检查计划结构，不代表发布通过。

### 6.2 A/B级备份前置

1. 读取24小时内最新`backup-set.json`及恢复组合证据。
2. 核对第4节全部条件，并在分级证据中保存路径和SHA-256。
3. 锁前重新读取PostgreSQL主版本、Schema和`SequelizeMeta`指纹；与证明不一致即升级C级。
4. A级保存当前`current`指针及新旧公开树manifest；B级追加目标API/基础设施配置快照和只读候选证明。

不得只有“昨天备份过”文字说明；没有可验证文件和摘要等同于没有恢复证明。

### 6.3 C/D级数据库备份恢复

```bash
python3 scripts/productionReleaseBackup.py database-backup \
  --database apple_order_mgr \
  --output <本次备份目录>/business.dump \
  --validation-sql scripts/productionReleaseDatabaseValidation.sql \
  --evidence <本次备份目录>/database-backup-evidence.json

python3 scripts/productionReleaseBackup.py isolation-proof \
  --container <本次唯一隔离PG15容器> \
  --target-database <本次唯一恢复库> \
  --source-database apple_order_mgr \
  --output <本次备份目录>/isolation-proof.json \
  --proof-key-file <0600认证密钥>

python3 scripts/productionReleaseBackup.py database-restore \
  --dump <本次备份目录>/business.dump \
  --sha256 <备份证据中的dump摘要> \
  --target-database <本次唯一恢复库> \
  --isolation-proof <本次备份目录>/isolation-proof.json \
  --container-dump-path /restore-input/business.dump \
  --validation-sql scripts/productionReleaseDatabaseValidation.sql \
  --evidence <本次备份目录>/database-restore-evidence.json \
  --proof-key-file <0600认证密钥>

python3 scripts/productionReleaseBackup.py compare-validations \
  --source-evidence <本次备份目录>/database-backup-evidence.json \
  --restore-evidence <本次备份目录>/database-restore-evidence.json \
  --output <本次备份目录>/database-comparison.json
```

D级把正式Migration命令通过`database-restore --migration-command-json`绑定到恢复步骤，并继续执行部署指南规定的原生schema证明。任一证据不通过即停止。

C/D级受影响共享业务文件使用同一认证对象库生成逻辑清单，并恢复到全新空目录：

```bash
python3 scripts/productionReleaseFiles.py snapshot \
  --source / \
  --store <受限对象库> \
  --manifest <本次备份目录>/business-files-manifest.json \
  --key-file <0600认证密钥> \
  --release-id <发布ID> \
  --include-path <受影响业务目录> \
  --consistency-proof <已认证一致性证明.json>

python3 scripts/productionReleaseFiles.py restore \
  --manifest <本次备份目录>/business-files-manifest.json \
  --destination <新建空恢复目录> \
  --store <受限对象库> \
  --key-file <0600认证密钥>
```

有多个业务根时重复`--include-path`。不得把原始AOS日志加入清单，不得用`/`无白名单扫描；活动
writer必须先停止领取并取得一致性证明。Linux正式恢复保留owner和mode，Mac隔离演练才使用受
同一manifest摘要认证的`--ownership-map`。

### 6.4 候选公开树门禁

生产安装路径以服务器实际工具为准：

```bash
python3 /var/www/apple-order-mgr/shared/tools/productionFrontendGate.py \
  prepare /var/www/apple-order-mgr/releases/<发布ID>

python3 /var/www/apple-order-mgr/shared/tools/productionFrontendGate.py \
  check /var/www/apple-order-mgr/releases/<发布ID> \
  --nginx-user <实际UID:GID>
```

多个实际Nginx身份必须逐一`check`。该步骤位于API/Worker/Migration正式变化之前；`--permissions-only`不能代替生产检查。

### 6.5 锁内发布

```bash
python3 scripts/productionRelease.py run --plan <本次冻结计划.json>
```

执行器必须在同一全局锁中完成：重读分级与生产基线、`prepare/check`结果确认、目标组件变化、`switch`、`verify`、失败反向回退和最终组件核对。A/B级计划中不得出现数据库或业务写入步骤；C/D级不得缺少本次恢复证据。

unknown状态使用：

```bash
python3 scripts/productionRelease.py resolve-unknown \
  --plan <本次冻结计划.json> \
  --outcome rolled-back \
  --evidence <独立对账证据.json>
```

只有独立对账证明原attempt已经完成时才可把`--outcome`改为`completed`。成功回退的attempt必须
新建计划，不得resume成成功；只有执行器明确标记为可安全续跑且基线未变化时才使用：

```bash
python3 scripts/productionRelease.py resume --plan <本次冻结计划.json>
```

### 6.6 生产回读与留档

所有等级至少核对：

- `current`精确指向目标版本，网页、动态资源、缓存头和API readiness通过。
- 实际变化组件的镜像/PID/环境与目标一致；未变化组件ID和运行状态与基线一致。
- A级确认零API/Worker/Migration/数据库写入；B级确认只读候选和零后台副作用。
- C级核对受影响业务写入路径和回退不变量；D级核对Migration、Schema、核心数据摘要和兼容下限。
- 生成阶段计时、失败/重试/回退记录、生产只读验收和未验证的真实业务边界。

## 7. 强制升级示例

| 初看改动 | 实际影响 | 最低等级 |
| --- | --- | --- |
| 调整按钮颜色、间距 | 纯展示 | A |
| 修改表单校验并改变提交字段 | 业务写请求改变 | C |
| 新增只读报表GET接口 | 无写入、无后台任务且可证明 | B |
| 修改通用服务或依赖包 | 不能证明不影响写路径 | C |
| Worker重试时间调整 | 队列与写入行为改变 | C |
| 修改环境变量但代码不变 | 影响调度、通知或写入 | C |
| 新增字段或索引 | Schema变化 | D |
| 历史订单批量纠正 | 数据转换 | D |

“只改一行”“只是小逻辑”“没有新增表”都不是降级理由。

## 8. 例外与审计

- 紧急发布也必须分级和生成计划；可以缩短人工等待，不能跳过对应等级的硬门禁。
- A/B级复用证明的发布必须在报告中披露证明时间、最大24小时RPO及未生成本次dump这一事实。
- 若发布后发现分级错误，立即停止后续动作，按实际影响升级处理；已发生业务写入时不得用前端回退掩盖数据风险。
- 每月抽查A/B级分级证据、恢复证明有效期和生产零写入证据；发现一次误分级，相关变更类型在复盘完成前默认按C级。
- 本规范不创建自动备份、定时任务或自动删除；没有有效恢复证明时始终回退到新鲜完整备份恢复。

# 日志筛选与人工标签发布适配说明

> 状态：当前有效；记录增量制品的复现方式，不代表生产发布已验收。
>
> 日期：2026-10-24（北京时间）

本次工作区与生产已有功能存在差异。生产日志查询页已有跨日范围、原文导出和元数据展示，接口使用 `monitor.logs.read` 独立读取权限，模型注册包含通知及 AOS 信号队列模型。本次发布从实际生产镜像增量修改，保留这些功能。工作区的功能提交和这里的生产适配补丁分别可追溯，不能用工作区旧文件整体覆盖生产文件。

## 制品与源码边界

- [制品白名单](制品白名单.json)记录基线镜像、9个业务文件的修改前后 SHA-256，以及新增 Migration。跨 Docker 镜像存储格式时，基线身份比较 `RootFS` 的 DiffIDs 逐层值及源码摘要，避免同一镜像的 OCI 与传统格式 ID 不同造成误拒绝。
- [生产增量补丁](production-overlay.patch)以实际生产源码为修改前版本，包含2个已有 API 文件、2个新增 API 文件、1个已有前端文件、2个新增前端组件、1个生产布局 CSS 和1个新增 Migration。
- `Dockerfile.api`、`Dockerfile.frontend`、`Dockerfile.migrator`只覆盖白名单文件，分别继承实际生产 API、对应前端构建镜像和正式迁移镜像。前端构建执行现有 lint 与 Vite 构建。
- 源码中不包含生产环境文件、访问令牌、数据库备份、业务内容或镜像归档。运行配置从上一发布目录继承，API和迁移镜像指向新制品；无关 Worker 保持既有镜像及配置。
- 手工标签保存在独立 `monitor_resource_tags` 表，初始为空；正式发布不配置示例标签。标签写入仍要求 `monitor.manage`，既有日志读取权限继续生效。

## 复现方法

1. 在独立本地 `main` 构建目录准备白名单基线镜像，核对 API 镜像身份。分别从基线 API 和前端构建镜像读取 `/app/src`，放入构建目录的 `src` 和 `frontend/src`；正式 Migration 放在 `migrations` 下。不得提取或复制环境密钥。
2. 执行 `python3 scripts/releases/20261024-log-labels/verifySource.py before <构建目录>`，确认已有白名单文件与生产基线一致、新增文件尚不存在。
3. 在构建目录执行 `git apply --unidiff-zero --check <本补丁的绝对路径>`，通过后执行 `git apply --unidiff-zero <本补丁的绝对路径>`。补丁采用零行上下文，修改前 SHA-256 校验不可省略；执行相同校验脚本的 `after` 模式，确认所有目标文件 SHA-256。
4. 在构建目录以此处三个 Dockerfile 构建 `linux/amd64` 镜像，提取前端 `/app/dist` 并记录源码、静态文件和镜像归档摘要。前端 Dockerfile 配套使用同目录的 `.dockerignore` 文件。
5. 在实际生产组合上完成后端权限、标签持久化与并发、跨日查询及导出回归，并以桌面和手机宽度浏览器验收点击后在正常文档流直接展开的下拉列表。生产页面容器宽度达到1080px时改为三等宽列：首行服务器、实例、账号，第二行时间范围占两列、关键词占一列；640px至1079px保留两列，更窄保留一列，避免服务器控件被旧五列布局压窄。

生产发布必须继续遵守[部署指南](../../../docs/deployment/生产环境部署指南.md)：业务备份排除约定的 AOS 日志明细和原始日志文件；隔离 PostgreSQL 15 恢复及正式迁移演练通过后才迁移生产；候选 API 关闭全部调度器并设置数据库只读；正式 API 精确继承原有效环境。库存现行配置与开关、官网付款刷新及既有预算保持原值；发布预检读取当前库存配置摘要和开关，在后续阶段核对一致，不根据历史暂停记录改变当前业务状态。库存基线只存配置摘要与开关布尔值，不保存配置原文。统一执行 `productionFrontendGate.py` 的 `prepare`、实际 Nginx 用户 `check`、`switch` 和 `verify`。

本次 Migration 仅增加标签表。应用回退恢复旧 API 和前端指针，保留新增表、Migration 记录及用户标签，不执行生产 `down`，不把备份回灌到继续写入的业务库。

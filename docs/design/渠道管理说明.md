## 数据模型

渠道来自 orders.tag 与 recipients.tag，不存在独立渠道表。列表以有非空 tag 的订单聚合，因此仅给取机人设置标签不保证渠道立即出现在列表。

## 当前能力

| 接口                          | 说明                                          |
| ----------------------------- | --------------------------------------------- |
| GET /api/channels             | 按订单 tag 聚合渠道统计                       |
| GET /api/channels/:tag/stats  | 指定标签的状态与取机人统计                    |
| GET /api/channels/:tag/orders | 分页订单，支持 page、pageSize、status、search |
| PUT /api/channels/:tag        | 请求体 newTag，更新订单和取机人标签           |

标签作为 URL 路径片段需要编码。读取需要登录及完成强制改密，改名需要 write 权限。

## 金额与状态

金额来自 official_order_amount，缺失使用聚合空值处理并返回缺失计数，不按固定每单金额估算。paidOrders 使用 payment_status=paid；列表中的 deliveredOrders 统计 picked_up 与历史 completed，不能误解为仅 delivered 状态。状态统计兼容新 payment_due、payment_received、payment_expired；商品数量使用官网优先的有效值，原导入值保留在来源快照。跨币种汇总和展示口径仍需业务验收。

## 改名规则

控制器拒绝空标签、相同名称、没有订单的原渠道，以及已经有订单的新标签。通过后在同一事务中更新所有命中原标签的订单和取机人，并返回 ordersUpdated、recipientsUpdated。

当前新名称是否已存在主要检查订单表；仅存在于取机人表的同名标签，以及空白规范化、并发改名、特殊字符行为需边界验证，不宣称已完成全部消歧。

## 脱敏与入口

渠道订单返回脱敏手机号，隐藏 Apple 订单链接。实现见[控制器](../../src/controllers/channelController.js)、[页面](../../frontend/src/pages/Channels.jsx)及[订单明细页](../../frontend/src/pages/ChannelOrders.jsx)。验收方法见[渠道管理验收清单](../testing/渠道管理验收清单.md)。

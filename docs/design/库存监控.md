# 库存监控

> 状态：已生产发布；2026-10-03 PC/H5 界面更新，当前采集和通知沿用已开启配置；真实全量 48 小时稳定性另验。当前发布证据见[界面发布记录](../archive/2026-10/2026-10-03-库存监控界面优化发布记录.md)。

## 范围与入口

库存模块分为两个菜单页：“库存监控”含全国库存、历史记录、统计分析三个页签，要求显式库存查看权限；“监控管理”含监控管理、通知与健康两个页签，仅管理员可访问。当前商品范围只保留 Apple 中国大陆的 iPhone 18 Pro 与 iPhone 18 Pro Max 全部颜色／容量 SKU 和直营店，不接入订单爬虫、客户或付款数据。业务口径和已批准参数见[需求方案](../planning/库存监控需求草案.md)。

## 数据和状态

目录使用精确 SKU 和门店代码；官网发现的新项默认待启用，一次发现失败不下架。版本化种子只包含已抓取的公开目录和来源时间，不表示全量库存已验证。监控总开关及通知默认关闭。

最新快照保留最后有效库存和本次错误；`displayStatus` 区分 `in_stock`、`out_of_stock`、`unknown`、`error`、`stale`、`disabled`、`paused`、`unsupported`。有效期在成功时固化为正常周期的两倍，后来降速不延长。手动检查与自动轮次共用最新基线和持久化队列。

同轮同 SKU/门店只应用一次；后到的重叠地域失败不得覆盖本轮已成功组合。并发请求分别预占字节和请求预算、按请求归还剩余字节额度，未知请求保守保留预占；普通在途请求的迟到成功不能计作保护触发后的恢复探测。动态代理提取在同一 Worker 内合并，避免多个并发请求重复消耗端点。新鲜、连续的无货转有货才是 `arrival`；从未成功为 `first`；中断后观察为 `recovery`。持续有货只增加检测，短暂错误后恢复原有货不重复通知。检测、事件、小时聚合与快照在一个事务中更新。

商品目录、型号筛选、全国库存缺失组合与自动／手动轮次均应用服务端精确机型白名单。当前为 32 SKU；停用与移出范围是不同操作，范围外商品即使存在于旧数据库且标记启用，也不返回当前目录或参与新采集。首次种子和每日官网目录更新均过滤范围外机型，防止重新加入 iPhone 17 等商品；保留既有历史证据，不删除历史表。

## 调度与保护

库存 Worker 仅由 `inventory` profile 显式启动。一个轮次由单一 Worker 持有数据库租约，轮内最多 3 个请求并发；每个任务有独立令牌和到期时间，异步返回按事务归并，任务租约到期记为结果未知，不无条件重放。轮次过期后停止领取新任务，等待已有请求结算或到期再完成覆盖审计。轮次固定启用清单与正常周期，保存计划、完成、失败、待采数量和任务进度。停机或冷却错过的计划轮次保留，不追赶突发。手动请求合并且限制排队，自动到期优先但不无限饿死手动任务。

所有目录、自动、手动、重试、恢复、代理提取都经过同一个 PostgreSQL 请求闸门。初始全局 5 RPS（最大 10）、库存任务 1 RPS，正常采集最多 3 并发，恢复探测保持单并发；单查询最多 3 次且全轮重试不超过基础请求数的 20%。小时、日、字节和代理提取预算重启不清零；代理失效无直连兜底。403/挑战、无效结构与供应商鉴权错误需人工处理；429/541 尊重至少 60 秒冷却，达到连续/比例/双出口阈值暂停 10 分钟；有限恢复最多三次，失败延长到 20/40 分钟，再失败人工处理。普通 5xx/超时连续五次同样进入十分钟冷却，但不计为 Apple 风控响应。代理 CONNECT 502/503/504 归为临时隧道故障，遵守同一有限重试和连续失败冷却；不因单次临时故障永久停用供应商。CONNECT 407 或其他拒绝仍暂停出口，Apple 541 和认证保护不变。轮次覆盖缺失保留对应任务的具体失败原因，只有缺少原因时才回退为通用缺失。

## 通知与统计

独立配置、加密 Webhook、队列和每分钟 18 条预算。10 秒窗口按城市/门店合并，首次摘要与恢复观察单独标记；首轮摘要等待轮次结束再计发送有效期，仍须复核样本新鲜度；发送前复核最新快照、开关、目标机器人和 120 秒事件有效期。未知投递不重发；明确失败有限重试。启用只处理之后事件，替换机器人废弃旧目标队列，静默不暂停采集。

运行健康提醒独立降噪：普通查询异常持续 2 分钟才排队，恢复正常连续 2 分钟且此前故障已送达或回执未知时，仅提醒一次恢复。同类普通传输故障合并为一个事件，同类故障 30 分钟内不重复发起提醒；需要人工处理、保护冷却、代理不可用及预算耗尽立即排队，仍遵守静默时段和群限速。发送前重新读取数据库健康状态，撤销已失效的健康提醒（含旧版本待发提醒）；关闭采集／通知或替换机器人重置观察，不补发历史恢复。状态及时间使用数据库事务持久化，重启不清零。到货、首次和恢复库存通知规则保持原样。

分析默认到货事件，可切换有货检测、首次和恢复。所有图表共用筛选及北京时间范围，缺口与 0 分开；检测明细 7 天、事件及投递 90 天、小时统计 365 天。超过明细保留期不提供假下钻，只有小时聚合时不能伪造细粒度热图；较旧查询明确显示对齐后的完整小时范围，超保留期的明细导出拒绝并提示调整起始时间。

## PC 与 H5 操作布局

PC 使用蓝白工作台：库存监控三个页签、监控管理两个页签、采集与通知状态入口、库存概览及统一表格工具栏。H5 在对应菜单页内展示页签，商品筛选与时间条件可折叠；已应用条件保留摘要，修改后需应用，重置会同时清空已应用筛选。库存行“查看记录”携带精确 SKU 与门店，并在摘要展示对应商品；摘要需兼容精确 SKU 和未知字段，不能使页面崩溃。商品选择支持搜索，多选在手机使用可滚动底部弹层，支持完成、关闭、遮罩和 Escape，关闭后焦点回到入口。

手机库存、目录、历史、轮次及通知采用连续紧凑列表，首屏展示商品／门店与状态，展开详情查看精确 SKU、官网提示、错误、时间和历史入口；不使用业务数据卡片网格。PC 保留完整表格，统计榜单并排展示。状态未知、错误、过期与无货仍明确区分，查看缓存不等于实时请求官网。

输入框在手机至少 16px，主要触控目标至少 44px；窄屏与短屏弹层内部滚动，底部操作考虑安全区。设置表单按用途分组，采集、通知开关及保存按钮清晰可达。布局适配不改变自动采集、通知、请求预算或手动排队规则。

## 验收边界

开发验收包括纯函数、事务/多 Worker、API 权限、通知失败与 PC/375px H5 交互。上线后再做至少 48 小时全国固定范围观察及新群真实送达。已有目录及代理证据见[数据源验证](../testing/库存数据源验证.md)。完整代码不等于真实源稳定性通过。

## 运行配置与发布顺序

正式 Worker 入口 `npm run start:inventory-worker`；开发、生产 Compose 均为显式 `inventory` profile。API 不自行启动库存采集。生产按现有发布流程构建新镜像、备份并执行库存表与时间索引 Migration，再更新 API/前端，最后显式启动库存 Worker；全局监控和通知默认关闭，逐项启用目录后再打开采集。未迁移前不得开放库存页面。

库存代理只读取专用私密文件：`INVENTORY_PROXY_FILE`（主出口）、`INVENTORY_BACKUP_PROXY_FILE`（备用出口），格式 `{label,url}`，URL 内鉴权值仅保存在 0600 文件；或 `INVENTORY_PROXY_API_FILE` 指向 `{apiUrl}` 的既有亦优提取配置。供应商主机固定白名单，一次只提取一个端点，端点缓存加密进入持久化闸门。未配置健康出口时停止该轮，不回退直连。生产目录由 `INVENTORY_SECRETS_DIR` 只读挂到 `/run/inventory-secrets`，环境中的文件路径应指向此挂载；不得提交真实配置或把旧订单代理服务重新启用。

`INVENTORY_PUBLIC_URL` 可选，须为本系统 HTTPS 公共源，用于需要登录的库存详情链接。Webhook 通过管理员设置页保存并使用既有字段加密密钥；生产必须已有有效 `FIELD_ENCRYPTION_KEY`。切换 Webhook 后重新测试。发送测试是明确操作，自动提醒开关与采集开关分开。

默认请求预算为小时 1200、日 25000；每日响应字节上限 512 MiB、每日代理提取上限 400。字节值为解压响应及在途最大响应预占，不是供应商账单；实际费用在上线观察中按供应商后台核对。默认预算是保护上限，不能据此保证 300 秒全量覆盖。达到上限要在页面与统计保留缺口，按实测调整周期与预算，不自动采购。

目录通过购买总页发现当前系列，再用精确 `partNumber` 的 `productSelectionData` 和 `displayValues` 核对机型、容量、中文颜色；不能单独采用 metrics 里的型号名称（已发现 Pro Max 被写为 Pro）。预售未开放项不加入在售清单，新发现项默认关闭。目录核对失败保留既有清单及最近核对时间。

回滚代码前先关闭全局采集和通知、停止库存 Worker。数据库 down 会删除本模块历史，常规版本回滚保留表，不把 down 当作自动发布回滚步骤。订单/邮箱/付款/AOS 及其 Worker 不受本模块配置控制。

### 独立页面与只读范围（2026-10-03）

用户菜单“库存监控”位于 `/inventory-monitor`，内含全国库存、历史记录、统计分析，使用 `?tab=latest|history|analysis`，要求显式 `inventory.read` 权限。管理员菜单“监控管理”位于 `/inventory-monitor/manage`，内含监控管理、通知与健康，使用 `?tab=manage|settings`，只允许管理员。侧栏仅提供这两个菜单，旧 tab 及路径链接兼容归组后重新鉴权。普通用户可查看和导出已有数据，不可触发外部采集或配置。

全国库存与管理页展示已启用商品、门店及其组合数，可展开查看完整名单。配置已启用不代表采集正常：关闭、保护暂停、异常、恢复、等待 Worker 和正常采集分别提示，并展示最近成功时间。权限通过现有用户管理分配，不根据普通用户角色隐式赋权。

### 2026-10-16 Apple ID 管理优化（已生产发布）

用户确认新增独立编号，现有账号按内部 ID 从 1 编排、之后递增不重用；旧 ID 和业务关联保留。默认列为编号、AppleID、密码、国家地区、状态、关联订单、最后下单时间、备注，操作末列保留编辑／删除，移除重复的名下订单按钮。状态使用蓝（未使用）、绿（使用中）、灰（已下架）、红（异常）标签。详情密保按授权读取并显示编码／内容，问题映射采用用户 2026-10-16 提供的 130–147 完整截图（其中 136 为“你的理想工作是什么？”，142 为“你的父母是在哪里认识的？”）；答案没有编码，直接展示原始答案。未知问题编码保留原文，不猜测。

多选后支持批量状态／备注修改与复制，每行精确 `AppleID,密码,`；状态和备注打开弹窗即可编辑，无需勾选字段；状态默认“保持原状态”，备注未编辑时保持原值，编辑后留空或点击“清空备注”后由“确认”一次保存；不增加二次核对流程。问题行标题只写“问题 1／2／3”，值保留编码／完整问句。编号与批量 API 契约分别见[数据库](../database/数据库架构.md#2026-10-16-独立编号已生产发布)和[API](../design/API设计.md#apple-id-管理扩展2026-10-16已生产发布)。在新 Worktree 中由 GPT 6.1 Sol／medium 子 Agent 开发及独立测试，Main 完成功能验收与代码 Review 后合入 main、提交推送并生产发布。已于 2026-10-16 发布 20261016-appleid-management，功能提交 adaad2d；编号与原字段保全、真实登录只读回查通过。弹窗简化追加修订1d9f975已发布20261016-appleid-dialog-simplify，生产只读验收通过。

完善基础档案、一次性表格导入、独立档案和历史追溯、名下订单、信息模板导出。首次导入后由系统维护，不持续同步腾讯文档。真实资料差异必须先预览，由用户逐项确认；编码阶段使用合成数据；2026-09-17 的首次发布及导入历史见[发布记录](../archive/2026-09/2026-09-17-取机人与AppleID发布及真实资料导入记录.md)。本轮仅按授权结束真实旧绑定并清空冗余字段，不导入或改写其他真实档案资料。

### 2026-10-16 选择工具栏与统计汇总（已发布）

参照订单列表，把选择计数和批量入口移至白色列表区域顶部并常驻：左侧显示选中数量，右侧提供全选本页、全选筛选结果、取消选择、批量修改及批量复制。全选本页替换为当前页；普通行勾选和表头勾选保留跨页选择。筛选变更清空旧选择，迟到的选择请求不得恢复旧筛选的ID。全选筛选结果取得当前筛选匹配的ID快照，后续新增账号不会自动加入，沿用最多5000条上限；超限提示缩小筛选范围，不静默截断。

选择列保持窄列、表头半选和选中行浅蓝反馈；批量按钮无选择时禁用，手机换行显示。保留已上线的一次确认修改和精确复制格式。

“统计分析”置于“列设置”左侧，参考库存统计弹窗样式，以表格展示全部账号总数与四种状态数量，零数量仍显示，未知存量状态单独列出。统计不受当前搜索、状态筛选或分页影响，支持刷新、加载／失败重试和关闭；只返回计数，不返回账号密码或密保。权限沿用Apple ID查看权限，接口和批量上限见API契约。

## 已确认业务规则

1. 取机人按标准化完整身份证去重，姓名不一致视为冲突。姓、名保留原始分列，兼容复姓；只有姓名时不能自行猜测复姓。
2. 每人只有一个原始 TAG，不拆分城市／负责人，不重新拼接，不允许同时归属多个渠道。
3. 真实联系电话可空，独立于下单手机。下单手机号随机生成合法大陆手机号格式，下单邮箱为该号码加 @vvv8.net；不要求收信、短信或随机地址实际可达。生成只影响档案，不改订单快照。
4. 取机人包含姓名、身份证、TAG、真实电话、下单手机号／邮箱／省市区街道、状态、备注和订单数。Apple ID 包含账号、密码、三组密保问答、国家（默认中国）、状态、备注；不保留独立昵称概念。
5. 状态为未使用／使用中／已下架／异常。新建默认未使用；取机人来源“已挂服务器”和“已挂 需下架”映射使用中，“已进表 未挂”映射未使用，不另存来源状态。大陆账号表只读 K 列状态，忽略 J、M；香港账号也只读 K 列状态，地区统一中国。
6. 2026-10-12 已批准解除档案绑定：取机人与 Apple ID 完全独立，不引入多对多绑定。正式迁移结束活动绑定历史，清空取机人冗余账号、密码与关联字段，保留原账号档案和历史证据。订单仅按各自外键归属。
7. 订单归属按每张订单实际取机人和账号分别保存。张三用 A、B 下的订单均计入张三；A 下李四的订单不计入张三。档案编辑／解除旧绑定不迁移旧订单；只补关联外键，不覆盖历史快照、TAG、付款任务。
8. 表格重复不等于无条件覆盖。空值可补齐，相同值合并；非空差异逐项展示，用户选择保留已有、采用来源或跳过。密码／密保差异不回显明文；数据库在预览后变化则拒绝旧预览，要求重新核对。

## 来源与模板

- 取机人及当前关联：[汇总表](https://docs.qq.com/sheet/DTEtMUEtGSmNGd2JQ?tab=eweuyz)，兼容各城市／渠道工作表。
- 账号：[2026-AppleID](https://docs.qq.com/sheet/DTFFvcVNoR2FkbFFj?tab=l1iul1)，仅两个以“26年AppleID”开头的工作表；不导入 25 年表。
- 取机人 A—N：Apple ID、密码、下单手机号码、Email、省、市、区、街道地址、使用状态、姓、名、身份证号码、TAG、信息导入模板。额外支持真实联系电话、备注。
- 账号列：A 账号、B 密码、C 国家、D/E 第一组问答、F/G 第二组、H/I 第三组、K 状态；大陆 L 备注；香港 L 是公式，不能当备注。
- 取机人表的旧账号、密码列仅兼容解析并明确提示忽略，不创建或修改 Apple ID；账号必须通过独立账号导入维护。
- 支持标准模板及腾讯文档导出的 xlsx、多文件多工作表，保留文件／工作表／行号用于冲突定位。身份证必须是文本，拒绝已丢精度的数值单元格；不执行源表公式。
- “导出录入信息”只导出 N 列计算结果的 UTF-8 TXT，每条档案一行、无表头；旧 A/B 账号密码固定为空，其他格式仍取 C 下单手机、J/K 姓名、D 邮箱、E/F/G 省市区、H 街道、L 身份证、M 原始 TAG，连续逗号、WECHAT、固定配置后缀及结尾占位保持一致。该 TXT 不附加状态、真实电话或备注，也不作为系统回导文件。敏感导出显式授权，普通导出仍为脱敏 Excel。

## 实施设计

- 数据层：新增 recipients.real_phone、apple_ids.notes、orders.recipient_id_last4，保留 phone 为下单手机号。迁移复制既有昵称到备注，旧 phone 不猜测为真实电话。新增绑定历史，2026-10-12 迁移保留空兼容列并以 CHECK 阻止旧写入，移除当前关系唯一索引和同步触发器；不改 orders、TAG、库存或付款。
- 档案写入仍使用事务和锁；旧绑定写接口返回 410。普通编辑非空旧绑定字段返回 400。down 仅恢复旧结构，不恢复关系或重新打开历史；完整资料恢复需备份。
- 订单关联：保存来源身份证尾号，按 2026-10-12 用户批准调整为姓名＋身份证后四位唯一匹配，完整证件只用于提取尾号；手机号和邮箱不参与匹配或拦截。提供历史未关联订单预览和选中执行；无充分证据保持待关联。
- 页面：表格展示独立资料、备注、订单数；订单入口沿用 orders 列表筛选，要求 orders.read 并按 TAG 范围；完整编辑地址／真实电话／下单资料／备注；账号密保在已有 secrets 权限下查看编辑。
- 导入：预览与执行分离，服务端持有原始数据，客户端只提交会话令牌与冲突选择。事务内重新检查资料版本；文件内、跨文件及已有档案统一判重。出错不泄露秘密或半批写入。

## 验收条件

1. 重复身份证合并；同名不同身份证不合并；同身份证不同姓名必须确认；复姓正常。
2. 旧写接口与非空旧字段拒绝，导入不回绑，迁移结束历史但保留证据，down 不恢复关系。
3. 同一人跨 A/B 账号、A 下有多个取机人订单时，订单统计分别正确；导入后补关联只修改空外键。
4. 真实电话不被生成覆盖，邮箱生成规则唯一为 @vvv8.net，空字段可以清空。
5. 腾讯两个账号工作表按位置正确映射，香港国家转中国，重复表头不误读。
6. 导入差异先确认；令牌不可跨用户／重复使用；预览后资料变化拒绝执行；取机人导入不写账号；无订单读取权限不泄露统计，密保仍按权限。
7. 录入 TXT 每条档案仅一行且与已核对公式逐字一致；脱敏 Excel 的身份证保护、公式注入处理和敏感权限有效。
8. 前后端 lint、相关单元测试、隔离 PostgreSQL 迁移 up/down 和并发测试、前端构建、文档检查；浏览器合成验证与真实业务验收分别记录。

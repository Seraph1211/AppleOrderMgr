# 取货历史数据与共用能力

> 状态：当前有效；独立“取货记录”页面已于 2026-10-11 从生产移除
>
> 最近核对：2026-10-11
>
> 适用范围：订单照片、设备绑定、库存来源与历史数据兼容

## 页面下线范围

“库存管理”承接设备入库、出库及来源管理。移除取货菜单、`/pickups` 页面、订单详情跳转入口、专属设备扫码窗口、人工取货／结款登记、清单导出和凭证上传入口；对应专用 API 不再注册。旧 `/pickups` 书签转到 `/stock`，仍由库存页面权限守卫检查；无库存权限时返回当前用户可访问首页，不额外授予权限。

历史取货记录、结款信息、设备、事件、凭证、数据库表及 Migration 全部保留，不删除 OSS 文件。库存生命周期仍使用原有人工、邮件和官网已取货依据，不能把上传照片、绑定序列号或预约日期当作已取货。缺少依据时继续由既有订单同步与核实流程处理，不再提示跳转旧页面。

## 保留的共用能力

- 订单详情继续通过 `GET /api/pickups` 及凭证读取接口查看历史取货照片，保持原分页、订单号与 ID 双重匹配和私有签名读取。
- 设备列表、绑定、解绑及订单 OCR 接口保持原契约。订单序列号展示／搜索、官网收据绑定、库存来源关联与修复仍使用共用模型和服务。
- 库存扫码／OCR 组件及独立库存接口保留，不能因删除专属窗口移除共用识别组件。
- `pickups.read/edit` 及 `stock.source.link` 的依赖保持，继续校验完整 `orders.tag` 范围。既有 `pickups.export` 权限码仅保留历史授权兼容，不再提供导出接口。
- 管理员可访问全部订单，普通用户仍需功能权限及订单 TAG 范围同时满足，不因页面合并扩大权限。

## 历史记录与凭证

人工记录是订单一对一扩展，状态 `pending/picked_up/exception` 与官网、邮件状态独立。既有实际时间、结款金额、结款人、备注、版本及追加事件保持原样。设备绑定、解绑继续保留审计和幂等，旧 UUID 重试不得影响新的绑定。

历史照片和 PDF 保存在私有 OSS，读取时重新校验订单范围并签发 5 分钟地址，响应 `no-store`；数据库不保存 Base64 或永久公开 URL。站内图片预览、加载失败重试与用户主动的新窗口入口继续由订单详情提供。服务端凭据、Bucket、CORS、加密与对象前缀配置不变。

接口详见 [API 契约](API设计.md#取货记录兼容接口2026-10-11-页面下线)，库存业务见[库存管理与销售](自有库存与销售管理.md)。历史发布证据见[取货记录与 OSS 凭证](../archive/2026-09/2026-09-23-取货记录与OSS凭证生产发布记录.md)、[页面优化](../archive/2026-09/2026-09-23-取货页面优化与门店筛选修复发布记录.md)及[设备扫码](../archive/2026-09/2026-09-23-取货设备扫码绑定生产发布记录.md)，不代表当前页面仍可用。

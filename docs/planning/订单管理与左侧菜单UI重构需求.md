## 1. 目标与交付原则

将已确认的订单工作台交给开发落地，统一订单列表、筛选、二级弹层及左侧菜单的视觉与操作反馈。保持高信息密度，在浏览器 **100% 缩放**下完成日常订单核对；不依赖用户缩小浏览器获得可用界面。

本次只改变 UI 布局、样式和交互呈现，保留既有业务字段、状态含义、权限、接口、选择范围及用户偏好。设计已确定，不再从旧五套方案或三套配色中重新选型。

开发优先阅读第 2 节范围、第 5～7 节交互、第 9 节隔离要求和第 10 节验收清单。截图说明视觉效果，字段和数据以实际服务端响应及现有契约为准。

## 5. 订单管理主页面

### 5.1 标题、搜索与筛选布局

桌面上方左侧为“订单管理”及“订单、邮件证据与取货安排”；右侧合并搜索、列设置、重新加载。宽度不足时自然换行，不遮挡标题。搜索仍覆盖当前已有的订单 ID、订单号、Serial No.、Apple ID、取机人等范围，保留原有触发/节流与请求行为。

筛选区顺序固定为：**六项多选 → 三组日期 → 已选条件摘要**。六项依次为官网订单状态、邮件订单状态、商品信息、订单 TAG、取货门店、付款人。1600px 起九项筛选同排一行，三组日期位于最右侧；日期摘要超长时省略显示，完整范围仍可通过控件无障碍名称及面板查看。较窄桌面多选占一行、日期在下一行右对齐；中屏多选减为三列/两列，手机自适应换行；不挤成不可读的细框。

小于 1100px 默认收起筛选，显示“筛选条件”及已启用组数；展开/收起不丢条件。筛选变更回到第一页，继续沿用既有选择清理与查询规则，不自行增加跨条件选中订单。

| FILTER-02 | 桌面弹层宽度与当前触发框一致，左右边界对齐；不得固定成更宽的 300px 菜单。允许 1px 渲染误差；在视口内合理向上/下避让                    |

| FILTER-09 | “全选全部候选”是提交明确值集合，**不等于不限**；只有清空该维度才回到不限。维度内 OR、维度间 AND 的后端语义不变                         |

不照搬视觉参考中的列拖动手柄：筛选候选不需要排序；列排序只属于列设置界面。

### 5.3 日期筛选

三组独立控件：**下单日期、取货日期、实际取货日期**。下单日按北京时间；取货日期来自邮件预约；实际取货日期来自官网实际已取货记录。三者不互相代替，可组合使用。

- 桌面面板宽 **292px**、内边距 12px；常规范围模式高度约 **442px**，输入/工具及日期单元约 28px。按内容适高，出现校验信息时允许增高，不固定裁切。
- 保留日期范围、指定日期、早于、晚于、当天及之前、当天及之后六类条件；范围支持双边和单边，沿用原有边界转换及校验。
- 选择先写草稿，**应用**才更新列表；取消、关闭和 Esc 不提交草稿。清空按现有行为解除该日期条件。
- 范围结束日包含当天；范围起止算一个筛选组。开始日晚于结束日时明确提示并阻止无效提交。
- 月份切换、键盘日期移动、输入日期、禁用/错误状态及触发器摘要均保留。
- 根据面板实际尺寸避让视口边缘，不溢出屏幕底部；手机保持 16px 输入与至少 44px 触控，不能为追求桌面小尺寸而同步缩小手机。

参考：[最终日期面板](订单管理UI参考/04-日期面板-最终.png)。

### 5.4 条件摘要与批量操作

已启用条件按字段分组显示可移除摘要。移除某组只清空该组；“清空筛选”同时清空关键词和各组条件。折叠筛选后仍能识别存在有效条件。

批量栏保留进度入口、已选数、全选本页、全选筛选结果、更新选中官网状态、导出选中订单、批量刷新邮件状态，按权限及当前选择启用。

| 操作             | 必须保持的范围与反馈                                                                             |
| ---------------- | ------------------------------------------------------------------------------------------------ |
| 全选本页         | 只选当前页真实可操作订单，计数与勾选一致；支持取消单行/本页                                      |
| 全选筛选结果     | 表示当前筛选及权限范围内全部结果，可跨页；不能只提交页面上已加载的行来冒充全选                   |
| 官网更新         | 单行入口仅当前订单；批量入口使用明确 ID 或筛选快照，不能扩展到同一 Apple ID 的其他订单           |
| 邮件状态批量刷新 | 保留仅支持当前页显式勾选 ID 的边界；筛选结果全选模式禁用并解释原因，不能把官网批次逻辑移植到这里 |
| 导出选中订单     | 保留明确 ID/筛选结果两种范围、字段选择、白名单与文件下载，不新增无范围的全量导出                 |
| 提交/运行状态    | 禁用重复提交，显示加载和结果；成功、失败、跳过、排队分别表达。受理或排队不能显示为业务更新已完成 |

### 5.5 表格、行按钮和分页

- 未保存列偏好或恢复默认时，顺序为：选择列、订单号、商品、官网订单状态、邮件订单状态、取机人、TAG、取货信息、实际取货日期、固定操作列。选择列是否显示仍由权限决定。
- 已有用户保存的列顺序/可见性优先；Serial No.、邮件状态更新时间、下单时间、付款方式、创建时间等补充列仍可启用，不因精简默认列而删除字段。
- 订单号单元格保留系统订单 ID、Apple 订单号及来源。商品保留规格、数量与金额，移除列表“按官方售价计算”的文字；未知金额显示“待确认”，不能把未知变成 0。
- 桌面表格各类时间为11px、等宽数字、完整单行，宽度不足由原生表格滚动承接；不截断日期或时分秒。
- 移除共享顶栏邮件监听状态与相应轮询，邮件处理页自身监控保留。
- 官网状态与邮件状态分列展示；“尚未更新”和“尚未获取”等缺失状态如实显示，预约取货不等同于已取货，邮件推定不冒充官网事实。
- 操作列统一为 **Eye＋查看、Mail＋邮件、RefreshCw＋官网更新、RefreshCw＋邮件刷新**；文字可见，均为同一套白底细边框按钮。不同刷新操作必须可辨识，不能保留两个无文字的相同图标。
- 1600px 起尽量四按钮一行；中等桌面采用 2×2；按权限自然减少按钮，不留下空位。手机保持 44px 点击区，空间不足允许两行。
- 列表表头、选择/默认身份列及右侧操作列按现有规则固定；用户调整列顺序后不得擅自重排个人配置。
- 保留总数、当前显示范围、每页条数、上一页/下一页、页码与跳转；底部不被遮挡。分页、选择、筛选及刷新后的状态恢复遵守既有规则。

### 5.6 滚动、缩放和焦点

宽度≥1100px 且高度≥680px 时，标题、筛选、批量区及分页保留在视口，仅列表纵向滚动。矮窗口与平板恢复页面滚动，避免为固定高度裁掉功能。

默认列在 1440×900 和 1904×948、100% 缩放下完整展示；开启更多列或 1280px 等较窄窗口允许表格内部横向滚动。移除“右侧还有字段”和左右翻阅按钮；保留原生横向滚动、触控板及可聚焦区域的键盘操作。使用约 6px 的低对比细滚动条，不能为了美观隐藏唯一可达入口或造成页面整体横滚。

输入聚焦仅改变单层 1px 边框，不叠加蓝色粗外框、ring 和阴影；嵌套输入避免内外两层焦点框。鼠标点击按钮后不持续显示粗蓝框，键盘访问的按钮、复选框、链接、日历和滚动区域仍保留清晰的轻量焦点，**不得全局移除 outline**。

## 6. 订单页二级界面

本节只适用于从 `/orders` 打开的实例，不是全站弹窗改版任务。

### 6.1 统一弹层外壳

桌面采用白色圆角面板、轻遮罩与克制阴影，标题/分区导航/底部操作固定，正文独立滚动。详情和进度最大约 980px，邮件约 1120px，一般表单约 680px，简短备注或确认约 480px；以视口安全边距和内容为约束，不强行固定宽高。

小于 640px 的复杂详情、邮件和配置使用全屏；备注和简短确认适高展示。保留关闭按钮、Esc、Tab/Shift+Tab 焦点循环、焦点返回及背景滚动锁。嵌套弹层的 Esc 只关闭顶层；提交中阻止重复提交和关闭。未提交的编辑按原流程保留或确认放弃，不因切换分区丢失。

### 6.2 功能逐项要求

## 7. 必须保持的业务与权限契约

1. 仅重构 UI，不改官网观测、邮件生命周期、付款、取货和人工核定的业务判定；不同来源和时间分别展示。
2. 保留 `orders.read`、`orders.edit`、`orders.export`、邮件读取/管理、取货照片及来源读取等权限和 TAG 数据范围；官网更新仍需管理员及原订单编辑权限，付款人等独立授权不合并。
3. 无权限字段/操作由现有契约控制；隐藏列、折叠菜单或客户端隐藏按钮不构成敏感数据保护。
4. 保留列表、筛选候选、导出、官网更新使用的原参数映射；多选搜索与全选不得改变空值、精确状态匹配和当前授权范围。
5. 保留请求幂等、版本冲突、取消、草稿、失败重试和既有自动读取机制；页面打开、换主题、切分区不得额外触发官网抓取、邮件发送或业务写入。
6. 不覆盖个人列偏好，不清除导航偏好，不伪造成功、计数或进度。未知及错误不能显示为正常空数据。

权威契约入口：`docs/design/API设计.md`、`docs/design/列配置规范.md`、`docs/development/前端设计规范.md`、`docs/testing/测试与验收指南.md`。本文规定本次交付范围与视觉目标，不替代这些业务契约；遇到真实分支与文档冲突先记录并澄清，不自行改规则。
